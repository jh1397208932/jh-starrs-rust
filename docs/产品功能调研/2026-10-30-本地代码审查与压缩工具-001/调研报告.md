## 1. 结论速览（TL;DR）

1. **先修既有门禁，再加新工具。** `cargo fmt --check` 是绿的，但 `cargo clippy --all-targets -- -D warnings` **当前为红**：3 处告警（`domain/document.rs:145`、`services/board_service.rs:61`、`db/global.rs:111`），且这 3 个文件都在工作区未提交改动里。文档把这个命令写成门禁（`docs/开发/测试与质量检查.md:20-21`），现状与文档不一致。
2. **最值得加的本地审查工具是 jscpd、ast-grep、knip（配置后）和 Rust 依赖审计。**
   - `jscpd`：MIT，实测重复率 **0.54%**（10 处、194 行），14 秒级，适合做“重复率不超过 1%/3%”的预算门禁。
   - `ast-grep`：MIT，0.51.0，本地毫秒级；可把 AGENTS 里的项目规则落成可执行规则（如禁止组件直接 import `@tauri-apps/api`、禁止 `console.*`）。实测 `console.*` 0 命中，正对照 `useEffect(...)` 命中 989 处。
   - `knip`：ISC，6.44.0；开箱运行会误报 15 个入口文件（scripts/test），**必须先配 entry**。配置后它的线索很有价值：3 个 UI 组件（`separator.tsx`、`tabs.tsx`、`progress.tsx`）确实无人引用，对应两个 Radix 依赖可清理；`@tiptap/extensions` 在 `editorExtensions.ts:23` 被直接 import，但 **package.json 未声明**（实际由 starter-kit 传递安装）。
3. **Sonar 规则本地化的最直接方案是 `eslint-plugin-sonarjs`，但它不是“零成本”。** 实测 226 文件 4.5 秒、77 条：认知复杂度 >15 的有 10 处（最高 43），`no-nested-conditional` 60 条。许可证 **LGPL-3.0-only**——按现有 `scripts/check-licenses.mjs` 会被记为“弱 copyleft 警告”，不会失败；但会引入 ESLint 整套依赖，与 Biome 规则重叠。建议只做 advisory（不阻断），或只修 10 个复杂度热点后不常驻。
4. **压缩层面没有“换工具”的空间，只有“加预算和量具”。** JS 已由 Oxc 压缩、CSS 已由 Lightning CSS 压缩；Cargo release profile 已是 `lto + strip + panic=abort + codegen-units=1`。**不要加 gzip/brotli 插件**：Tauri 资源内嵌进二进制，没有 HTTP 传输环节，压缩产物不会减小安装包。可加 `rollup-plugin-visualizer`（活跃，7.1.1）与 `size-limit` 做体积预算；Rust 用 `cargo bloat` 量 release，项目目前没有 release 包体基线。
5. **明确不推荐**：SonarQube Community（需要本地服务端，违背前提）、CodeQL（许可证/体量成本高，未验证）、`madge`（实测无循环依赖，26 秒白跑）、`cargo-geiger`（Rust 侧仅 2 处 `unsafe` 字样，收益极低）、用完整 ESLint 替换 Biome（双 linter 重叠）。

### 4.1 Rust 门禁：fmt 绿、clippy 红

### 4.4 死代码 / 依赖：knip

开箱结果（未配置 entry）：

```text

Unused dependencies (6)：@radix-ui/react-separator、@radix-ui/react-tabs、
  @tiptap/extension-table-cell/table-header/table-row、@tiptap/extension-unique-id

```

人工复核结论：

- `scripts/*` 与 `test/**` 是入口，不是死代码；knip 必须配置 `entry` 后再用。
- `src/components/ui/separator.tsx`、`tabs.tsx`、`progress.tsx` 全仓无 import（本次 grep 确认），对应 `@radix-ui/react-separator`、`@radix-ui/react-tabs` 可以清理；`src/mocks/shortcuts.ts` 也需要确认是否仍被引用。
- `@tiptap/extensions` 在 `src/features/editor/extensions/editorExtensions.ts:23` 被直接 import，但不在 `package.json`；`npm ls` 显示它由 `@tiptap/starter-kit@3.32.0` 传递安装。建议显式声明，避免升级 starter-kit 后解析漂移。
- 48 个未用导出里有不少是 API 层封装，不能仅凭工具输出删除；按项目规范逐名核对调用点。

### 4.5 项目规则执行：ast-grep

```text
npx --package @ast-grep/cli ast-grep run -p 'useEffect($$$A)' -l tsx src → 989 处（正对照，证明扫描生效）
npx --package @ast-grep/cli ast-grep run -p 'console.$M($$$A)' -l ts src → 0 处
```

`console.*` 0 命中与项目“禁止 console，统一走 logger”的约定一致。适合把 AGENTS 中可机械判定的规则落成 3–5 条：

- 组件/功能代码禁止直接 `import ... from "@tauri-apps/api"`（只允许 `src/api/**`）。
- 禁止 `console.(log|debug|info|warn|error)`（排除 `src/lib/logger.ts`）。
- 禁止 `style={{ color: "#..." }}` 之类硬编码色值（按项目令牌规范）。
- 禁止跨 feature 的直接相对导入（如 `../其他feature/`）。

### 4.6 依赖漏洞：npm audit

```text
11 条：2 high / 7 moderate / 2 low
high:
  lodash-es   fixAvailable=true（可随依赖升级修复）
```

`lodash-es` 属于可修复项；`nanoid` 只能靠 Excalidraw 降级，建议记录为“上游待修”。`npm audit` 每次需要访问 registry；若要求离线，可换 `osv-scanner`（未实测）。

### 4.7 格式限制

| 范围 | 现状 | 可补的门禁 |
|---|---|---|
| TS/TSX/CSS（`src/**`） | Biome 已覆盖；`tokens.css` 被排除 | 保持 |
| `scripts/`、`test/` | 未纳入 Biome | 可选扩围，但会先产生一批格式 diff |
| `src-tauri/tauri.conf.json` | Biome 当前 `files.includes` 不含它 | Biome 本身能格式化 JSON（实测仅 7 行差异）；扩围即可，无需新工具 |
| `Cargo.toml` | rustfmt 不处理 TOML；taplo 实测“未正确格式化” | 可选：一次性 `taplo fmt` + `taplo fmt --check` 门禁；npm 包 0.7.0（2024）较旧 |

### 4.8 压缩 / 包体

| 项 | 读数 |
|---|---|
| `dist/` 总体积 | 10 MB |
| 最大 JS | 2.20 MB / 1.78 MB / 1.03 MB（Oxc 压缩后） |
| 最大 CSS | 293 KB（Lightning CSS 压缩后，Tailwind v4） |
| 生产 sourcemap | 已关闭 |
| Cargo release profile | `lto=true`、`strip=true`、`panic="abort"`、`codegen-units=1`（已是激进配置） |
| release 二进制 | 未构建，无基线；debug 二进制 152 MB（不代表发布体积） |
| Rust `unsafe` | 全仓 2 处字样，`cargo-geiger` 收益低 |

结论：

- **JS/CSS 压缩已经是当前工具链的最优路径**，再换 minifier 没有明显空间；后续收益来自拆分与懒加载，而不是压缩器。
- **不要加 gzip/brotli 构建插件**：桌面端资源内嵌，没有 HTTP 响应链，压缩文件不会减小安装包（机制推断，未做产物体积实验）。
- 需要可执行的包体治理时：`rollup-plugin-visualizer` 出图 + `size-limit` 设预算；Rust 侧 `cargo bloat --release --crates` 找大头。
- 图片/字体：`public/` 仅 8 KB；`docs/设计` 不随包分发，无需图片压缩工具。

## 5. 建议与优先级

### P0 · 先恢复既有门禁（不改工具）

1. 修 3 处 clippy 告警；把 `lint:rust`、`fmt:rust` 写进 `package.json`，与文档 `docs/开发/测试与质量检查.md` 对齐。
2. 修 `useBoardLibraryInsertion.ts` 的格式漂移（Biome/oxfmt 判据一致）。

### P1 · 低成本、高收益的本地检查

| 动作 | 成本 | 收益 |
|---|---|---|
| 加 `jscpd`，阈值 1% | 一个 devDependency，MIT | 防重复代码回潮；当前 0.54% |
| 加 `ast-grep` + 3–5 条项目规则 | 一个 devDependency，MIT | 把 AGENTS 的机械规则变成可执行门禁 |
| 配 `knip` 的 entry 后清理 | 需要 `knip.json` | 3 个 UI 组件、2 个 Radix 依赖、未声明依赖 `@tiptap/extensions` |
| 加 `cargo-audit`（或 `cargo-deny`） | `cargo install`，无项目依赖 | RustSec 漏洞；与现有许可证脚本互补 |
| 把 `npm audit` 纳入定期检查 | 需 registry 网络 | 当前 11 条，2 high |

### P2 · 可选，按需要开启

- `eslint-plugin-sonarjs`：只做 advisory；先修 10 个认知复杂度热点。若不愿引入 ESLint，可继续用 `oxlint --type-aware`（见 `2026-10-30-Oxc选型评估-001`）覆盖 React/类型感知规则。
- `taplo`：只针对 `Cargo.toml`，一次性格式化后再加检查；npm 包维护较旧，可用 cargo 版。
- `cargo-machete`：Rust 未用依赖；与 knip 的 JS 侧互补。
- `secretlint`：凭据扫描；未实测，项目目前没有相关事故记录。

### P3 · 包体压缩（有明确目标再做）

1. `rollup-plugin-visualizer` 出包体图，确认大块来自 Excalidraw/Tiptap 的按需加载边界。
2. `size-limit` 设预算（如总 JS ≤ 8 MB、首屏 ≤ 3 MB），防回归。
3. Rust 构建 release 后用 `cargo bloat` 做归因；当前 profile 不需要再调。
4. 明确不做：gzip/brotli 构建插件、图片压缩、UPX 之类二进制加壳。

### 不推荐清单

| 方案 | 原因 |
|---|---|
| SonarQube Community | 需要服务端，违背“不要服务端” |
| CodeQL | 本地但需建库/许可限制（未验证），体量重 |
| madge | 已实测无循环依赖，26 秒白跑；需要架构规则时选 dependency-cruiser |
| cargo-geiger | 仅 2 处 unsafe 字样，收益极低 |
| 完整 ESLint 替换 Biome | 规则重叠、双配置、双升级节奏；收益不足以抵消 |
| vite-bundle-visualizer | 1.2.1 停留在 2024-05，改用 rollup-plugin-visualizer |
| gzip/brotli 构建插件 | 对 Tauri 内嵌资源无收益 |

## 6. 风险与未决问题

1. **clippy 红灯未修**：在它恢复绿之前，新增检查的“通过”没有意义。
2. **knip 误报**：入口配置不当会把 scripts/test 全判为死代码；48 个未用导出必须逐名核对调用点，不能直接删。
3. **sonarjs 的 LGPL 警告**：现有门禁允许弱 copyleft，但会在许可证报告中新增一条警告；同时引入 ESLint 依赖树。
4. **npm audit 依赖网络**：无网环境不可用；离线方案（OSV-Scanner）未实测。
5. **Rust 依赖审计未实测**：`cargo-audit`/`cargo-deny` 需要安装；RustSec 数据库同样需要首次联网。
6. **release 包体无基线**：本轮没有构建 release，无法给出“可压缩多少”的数字。
7. **semgrep 许可证未验证**：PyPI 元数据没有 license classifier；在未核对官方许可证前不进入推荐。
