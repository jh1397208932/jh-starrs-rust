## 1. 结论速览（TL;DR）

1. **构建链路已经在用 Oxc，无需任何动作。** Vite 8.3.4 依赖 Rolldown 1.2.12，产物内存在 `transformWithOxc` / `oxcTransform`，`vite.config.ts` 生产构建显式 `minify: "oxc"`；`node_modules` 中已无 esbuild。
2. **不建议现在用 Oxc 全面替换 Biome。** 格式化质量已经足够（对拍逐字节一致），但 `oxfmt` 版本为 0.75.0（未到 1.0），`sortImports` 与项目现用的 Biome `organizeImports` 不是开箱等价——即使关掉分组空行，仍有 11 个文件排序结果不同，需要逐组调优。收益仅为百毫秒级（Biome 检查 229 文件约 120ms），不值当引入双工具维护。
3. **唯一明确的增量能力是 `oxlint --type-aware`。** 它基于 `oxlint-tsgolint`（tsgo），实测能命中 `no-floating-promises` 这类 Biome 没有的类型感知规则。建议以 warn-only 方式试点，不纳入阻断门禁。
4. **Oxc 不能替代 `tsc --noEmit`。** 它不提供类型检查器；`npm run build` / `typecheck` 的类型门禁仍必须由 TypeScript 完成。若痛点是 typecheck 耗时，正确方向是评估 TypeScript 7 / tsgo，而不是 Oxc。
5. **`oxc-parser` 替换 4 个 i18n 脚本里的 `typescript` AST 解析，收益极低**（脚本低频运行、仍需要 TypeScript 做类型检查），本轮不推荐。

一句话：**Oxc 适合继续待在构建层（已经在用）；lint 层可试点 type-aware；格式化层暂缓到 oxfmt 1.0 且排序语义对齐之后。**

## 4. 实测记录

### 4.1 构建链路：Oxc 已生效

```text
vite 8.3.4 dependencies: lightningcss, picomatch, postcss, rolldown ~1.2.12, tinyglobby
node_modules 中无 esbuild / @swc
vite dist 中 transformWithOxc / oxcTransform 各出现 6 次
```

结论：`npm run dev` 与 `npm run build` 的 TS/JSX 转换、生产压缩已经走 Oxc，不存在“是否该用”的问题。

### 4.2 Lint

| 场景 | 命令要点 | 读数 |
|---|---|---|
| 现状 | `biome check src` | 229 文件 / 120–129ms / 0 lint 错误 / 1 格式漂移 |
| oxlint 默认 | `oxlint src` | 226 文件 / 25ms / 96 条规则 / 0 error |
| oxlint 接近 Biome 口径 | `-W correctness -W suspicious -W perf --react-plugin --jsx-a11y-plugin --import-plugin` | 226 文件 / 173–194ms / 222 条规则 / **2137 warnings** |
| 关闭 JSX scope 噪声后 | 追加 `-A react-in-jsx-scope` | 226 文件 / 91–194ms / 221 条规则 / **228 warnings** |

2137 条里 1909 条是 `react(react-in-jsx-scope)`——项目使用 React 19 自动 JSX 运行时，这条规则本就不该开，属于插件默认配置噪声，不是代码问题。剩余 228 条的主要分布：

| 规则 | 数量 |
|---|---|
| `react(set-state-in-effect)` | 35 |
| `react(refs)` | 27 |
| `react-hooks(exhaustive-deps)` | 23 |
| `react(memo-dependencies)` | 22 |
| `eslint(no-await-in-loop)` | 20 |
| `jsx-a11y(prefer-tag-over-role)` | 16 |
| `import(no-named-as-default)` | 14 |
| `eslint(no-shadow)` | 13 |
| `react(exhaustive-effect-dependencies)` | 13 |

这些是“多一层审查”的候选，不代表代码有缺陷；Biome 的 recommended 集合不含其中大部分。**结论：两者当前都判定代码库无 lint 错误，差异在规则集，不在质量结论。**

### 4.3 类型感知 lint（已验证可用）

在临时目录安装 `oxlint@1.90.0` + `oxlint-tsgolint@7.0.2005`，对含“未 await 的 Promise”样例运行：

```text
oxlint --type-aware -W correctness a.ts
→ typescript(no-floating-promises) 命中，79ms，1 文件 / 111 条规则
```

这是 Biome 侧没有的能力，也是 Oxc 在本项目里最值得试的部分。未验证项：在项目完整 tsconfig 下对 226 个文件跑一遍的耗时与告警量。

### 4.4 格式化

配置用 `oxfmt --migrate=biome` 从 `biome.json` 迁移，得到 `printWidth 110 / tabWidth 2 / 双引号 / 分号`。

| 场景 | 读数 |
|---|---|
| `oxfmt --check src`（纯格式化） | 230 文件 / 21ms；仅 2 个文件不一致：`useBoardLibraryInsertion.ts`（既有漂移）与 `tokens.css`（Biome 已排除） |
| 漂移文件对拍 | oxfmt 输出与 Biome（stdin + 项目配置）输出 **逐字节一致** |
| `tokens.css` 若纳入格式化 | oxfmt 会把十六进制色值转小写、给 `cubic-bezier(.22,…)` 补 0，产生 868 行差异；保持排除即可 |
| 开启 `sortImports`（默认关闭） | **142/230 文件**不一致，差异是导入分组之间插入空行 |
| `sortImports.newlinesBetween: false` | 降到 **11 个文件**（含 `tokens.css`） |
| 再设 `sortImports.ignoreCase: false` | 数量不变；抽样差异是分组/大小写排序语义（如 `../ShortcutProvider` 与 `../actions` 的先后、`./MindmapNodeMeta` 与 `./markerIcons` 的先后） |

结论：**纯格式化已接近完全对齐；导入排序不是开箱可替换项**，需要按 Biome 的实际分组结果调 `groups` / `customGroups`，属一次性成本而非零成本。

另：`ignorePatterns` 相对配置文件所在目录解析。迁移时配置文件必须放在项目根，否则排除项（如 `tokens.css`）不会生效。

## 5. 对比矩阵

| 能力 | 现状 | Oxc 方案 | 判断 |
|---|---|---|---|
| TS/JSX 转换 | Vite 8（Rolldown/Oxc） | 相同 | **已在用，无需迁移** |
| 生产压缩 | `minify: "oxc"` | 相同 | **已在用** |
| Lint | Biome recommended | oxlint 1.90（870+ 规则、插件化） | 可试点；规则集不同，需显式配置 |
| 类型感知 lint | 无 | oxlint + oxlint-tsgolint | **唯一明确增量**，建议 warn-only 试用 |
| 格式化 | Biome 2.5.15 | oxfmt 0.75.0 | 输出对齐良好，但版本 0.x，暂不作为唯一格式化工具 |
| 导入排序 | Biome organizeImports | oxfmt `sortImports`（默认关） | 需调分组；当前仍有 11 文件差异 |
| CSS | Biome（Tailwind 指令解析） | oxfmt 支持 CSS，但会规范化色值大小写 | `tokens.css` 保持排除即可 |
| 类型检查 | `tsc --noEmit` | Oxc 无类型检查器 | **不可替代** |
| AST 脚本 | `typescript` API | `oxc-parser` 0.156 | 低频脚本，收益低，暂缓 |
| 许可证 | MIT OR Apache-2.0 | MIT | 均合规，可过现有许可证门禁 |
| 成熟度 | Biome 2.x 稳定 | oxlint 1.x 稳定；oxfmt 0.75（预 1.0） | 格式化层按预 1.0 风险对待 |

官方文档旁证（`oxc.rs`，2026-10-30 抓取摘要）：formatter 支持 JS/TS/JSX/CSS/JSON/HTML 等语言；linter 类型感知基于 tsgo；页面未见显式 alpha/beta 标识。但 `oxfmt` 包版本仍为 0.75.0，本报告按“预 1.0”保守处理，不把文档表述当作稳定性证明。

## 6. 建议与优先级

| 优先级 | 动作 | 理由 |
|---|---|---|
| P0 | 构建链路保持现状 | Oxc 已在 transform/minify 生效，没有迁移对象 |
| P1（可选） | 试点 `oxlint --type-aware`，warn-only | 补上 Biome 缺失的类型感知规则（`no-floating-promises` 等）与 React 19 规则；先关闭 `react-in-jsx-scope`，再按需收敛 228 条告警 |
| P2（观察） | 等 `oxfmt` 1.0 与 `sortImports` 分组对齐后再评估替换 Biome | 目前替换只省约百毫秒，却增加双工具、双配置、双升级节奏 |
| P3（暂缓） | `oxc-parser` 替换 i18n 脚本的 TS AST | 脚本低频运行，且 TypeScript 仍要保留给类型检查 |

项目规范（AGENTS.md §1）本身要求“没有明确需求时不引入新框架”，当前读数也不支持“为了性能必须换”的结论。

若执行 P1，建议的验证脚本（尚未在任何配置中落地）：

```bash
# 只作为本地/CI 的非阻断检查，先不写进 package.json
npx oxlint --type-aware \
  -W correctness -W suspicious \
  --react-plugin --jsx-a11y-plugin --import-plugin \
  -A react-in-jsx-scope \
  src
```

验收方式：先记录基线告警数，再逐批治理；不把 warn 直接升级为 error，避免与既有 `biome check` 门禁争夺“谁说了算”。

## 7. 风险与未决问题

1. **oxfmt 仍是 0.x**：格式化工具一旦替换，输出稳定性直接影响全仓 diff；升级节奏需自行承担。
2. **导入排序语义差异**：默认开 `sortImports` 会产生 142 个文件的大 diff（仅空行）；调参后仍有约 10 个 TS/TSX 文件排序不同。若要切换，必须先锁定分组配置并做一次独立“格式化提交”。
3. **双工具漂移**：Biome 与 oxlint 规则重叠但不完全一致；同时启用会带来“修复冲突”和两套 ignore 配置。
4. **type-aware 全量成本未知**：仅单文件验证；226 文件 + 项目 tsconfig 的耗时、与 TS 6.0.3 的兼容性未测。
5. **编辑器集成未验证**：JetBrains（项目使用 `.idea/`）对 oxlint/oxfmt LSP 的支持体验未实测。
6. **CSS 规范化差异**：`tokens.css` 若被纳入 oxfmt，会改写色值大小写（868 行 diff）；当前靠排除项规避。

## 8. 后续可执行动作（若决定推进 P1）

1. 在独立分支安装 `oxlint` + `oxlint-tsgolint`（devDependencies），新增 `.oxlintrc.json`：启用 react / jsx-a11y / import 插件，关闭 `react-in-jsx-scope`，先只开 correctness + suspicious。
2. 跑一次全量基线，记录告警数（预期 200 上下），按规则分批治理；不与 `biome check` 争夺阻断权。
3. 观察 1–2 个迭代：若 type-aware 规则确有收获，再讨论是否扩大；否则移除依赖，保持单工具。
4. `oxfmt` 侧每季度复核一次版本与 `sortImports` 对齐情况，等 1.0 或分组配置能零差异后再提替换方案。
