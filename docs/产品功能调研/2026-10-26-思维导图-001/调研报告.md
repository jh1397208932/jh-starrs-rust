# 思维导图功能 · 技术选型调研（2026-10-26）

- 调研范围：类 XMind 思维导图编辑器、React Flow 开源核心、行业格式导入导出、Starris 集成边界
- 结论性质：只读调研，未修改业务代码、配置或依赖
- 访问日期：2026-10-26（npm / GitHub / 官方文档均在该日核对）

## 1. 背景与目标

Starris 已有文档、表格、画板（Excalidraw）三类内容节点。本次要在文件树中增加“思维导图”节点，形成：

1. 新建/重命名/删除/回收站/恢复；
2. 中心主题与多层主题编辑、自动布局、折叠、拖拽改父级、撤销重做、自动保存；
3. 导入导出 `.xmind`、FreeMind `.mm`、OPML、Markdown，并导出 PNG/SVG；
4. 搜索、整库导出、备份恢复、真机黑盒回归的完整闭环。

硬约束：

- 只使用完全开源、可商用、无需付费授权的代码；
- 不使用任何 Pro/付费示例或闭源客户端代码；
- 不复制 XMind 的代码、主题、图标或素材，仅做文件格式兼容；
- 新依赖需满足“稳定、开源可商用、较高采用度”，并记录体积与替代方案。

## 2. 信息来源

### 2.1 React Flow / xyflow

| 来源 | 地址 | 核对结果 |
|---|---|---|
| npm | https://www.npmjs.com/package/@xyflow/react | `12.12.0`，`license: MIT`，peer `react >=17` |
| GitHub | https://github.com/xyflow/xyflow | 38,778 stars，MIT，2026-10-22 仍在推送 |
| 官方 Pro 页 | https://reactflow.dev/pro | “React Flow is MIT-licensed open-source software. Pro offers examples, support, and prioritized issues for a fee.” |
| API 参考 | https://reactflow.dev/api-reference/react-flow | 默认角落有归属链接；`proOptions.hideAttribution` 可移除 |
| 移除归属说明 | https://reactflow.dev/learn/troubleshooting/remove-attribution | MIT 允许移除；官方请求商用组织保留归属或订阅支持 |

结论：

- 核心库 MIT，可商用；Pro 出售的是**示例、支持和优先 issue**，不是运行时许可。
- Pro 示例代码受 Pro License 约束，不能无授权复制；我们只使用核心 API，自行实现交互。
- 归属链接不是许可证强制项（当前官方 API 文档明确“Anyone is free to remove this attribution”），但官方希望商用组织支持项目。Starris 可保留一个低调的 About/第三方许可归属，不购买 Pro。

| 来源 | 地址 | 核对结果 |

结论：

- 功能与格式覆盖最完整，几乎就是“Web 版 XMind 内核”；
- 但库处于低维护状态，版本号带 `fix` 后缀，解压体积大、依赖多；
- 自带主题体系需要重做才能贴合 Starris 的 Amber Isle 视觉；其闭源客户端不在使用范围，只使用 MIT 库。

### 2.4 文件格式

| 格式 | 性质 | 兼容策略 |
|---|---|---|
| `.xmind`（XMind 2020+） | 事实标准，ZIP + `content.json` + `metadata.json` + `manifest.json` | 导入/导出；保留主题文本、层级、备注、标签、链接、折叠状态；样式不保证还原 |
| `.xmind`（XMind 8） | ZIP + `content.xml` | 仅导入；导出统一写现代 `content.json` |
| FreeMind `.mm` | 开放 XML（`<map><node TEXT=...>`） | 导入/导出文本、层级、备注、链接、折叠 |
| OPML 2.0 | 开放 XML（`<outline text=...>`） | 导入/导出文本、层级、备注、链接 |
| Markdown | 事实标准（标题/列表） | 导入/导出标题与嵌套列表；段落进备注，代码块跳过 |
| PNG / SVG | 图片 | 导出；SVG 由统一的布局数据生成，PNG 由 SVG 转位图 |

**待验证**：`.xmind` 不是官方开放规范，必须用公开样例与真实 XMind（至少 2020+）做一次打开/回读验证；本机当前未安装 XMind，需在需求验收中列为真机项。我们只实现格式兼容，不复制 XMind 的任何代码或资源。

## 4. 建议

### 4.1 首选：React Flow 核心 + 自研思维导图领域层

理由：

1. 活跃、轻量、MIT，符合项目“高采用度、可商用、无付费授权”的选型门槛；
2. 节点/边/视口/选择/拖拽等画布能力成熟，Starris 可以完全控制节点视觉与交互；
3. 把“思维导图”留在我们自己的领域模型里，后续做 XMind 兼容、搜索、备份、整库导出时不会被第三方数据模型绑死；
4. 避免引入低维护、26 MB 的专用引擎及其主题体系。

必须接受的代价：

- 树布局、Tab/Enter 编辑、折叠、拖拽改父级、撤销重做、节点测宽、SVG 导出都要自研；
- 不能复制 React Flow Pro 示例；只使用公开核心 API；
- 首版必须明确功能边界，不能一次做成完整 XMind。

### 4.2 备选：simple-mind-map

只有在“XMind/FreeMind 格式保真和类 XMind 交互优先于依赖健康度”时才选它。选它需要接受：

- 库已低维护，出问题需自行修；
- 26 MB 解压体积与 15 个依赖，需要懒加载；
- 主题/工具栏/页面壳仍要按 Starris 重做；
- 文件解析若继续走 JS，会与“复杂转换放 Rust”的项目规范冲突，需要额外拆分。

### 4.3 不建议

- mind-elixir：低于 1 万 star 门槛，且 XMind/FreeMind 仍需自研，投入产出不如 React Flow 方案；
- jsMind/X6：采用度或定位不匹配；
- markmap：只读；
- 任何 Pro/闭源/带水印授权的组件。

## 5. 推荐的首版功能边界

### 5.1 必做（v1 闭环）

- 新节点类型 `mindmap`（SQLite type=7），新建、重命名、删除、回收站、恢复；
- 单画布思维导图：中心主题、子主题/同级主题、内联编辑、自动布局（左右平衡 + 向右逻辑图）、折叠/展开；
- 键盘：Tab 子主题、Enter 同级、F2 编辑、Delete 删除、方向键导航、空格折叠、⌘Z/⇧⌘Z；
- 拖拽改父级（拖到目标主题成为子主题；禁止拖进自己的后代）；
- 撤销/重做、自动保存、版本冲突提示、关闭前 flush；
- 备注、标签、超链接；节点搜索与定位；
- 导出：`.xmind`（2020+）、`.mm`、`.opml`、`.md`、`.svg`、`.png`；
- 导入：`.xmind`（现代/旧版）、`.mm`、`.opml`、`.md`，多画布 XMind 按画布拆成多个节点；
- 搜索索引收录所有主题文本；整库导出/备份/恢复包含思维导图；
- Rust 侧统一校验、格式转换、路径令牌写入；
- 真机黑盒用例：新建→编辑→保存→重开→导入→导出→回收站→恢复。

### 5.2 暂不做（v2 候选）

- 概要/边界/关系线/自由主题/多画布内切换；
- 图标库、优先级/进度标记、自定义主题编辑器；
- PDF 直接导出（先用系统打印另存 PDF）；
- 多人协作、云同步合并；
- XMind 样式/字体/主题的像素级还原；
- XMind 8 旧版导出（只导入）。

## 6. 风险与未决问题

| 风险 | 影响 | 应对 |
|---|---|---|
| .xmind 非开放规范 | 导出文件可能无法被某些 XMind 版本打开 | 用 2020+ 真实文件 + 公开解析器双回归；验收列真机项 |
| React Flow 自研量大 | 首版周期长、交互细节多 | 严格按 v1 边界；先做数据/格式，再做编辑器 |
| 布局/文本测量性能 | 大图卡顿 | 布局 O(n)、测宽缓存、只渲染视口、1000 节点基准 |
| React Flow 归属 | 界面出现第三方链接 | 保留 About 归属或按 MIT 移除；不购买 Pro |
| 多画布语义 | XMind 多 sheet 导入丢失 | v1 每个 sheet 建一个节点，绝不静默丢弃 |
| 主题/样式兼容 | XMind 样式无法还原 | 明确只保结构/文本/备注/标签/链接 |
