# 调研报告 · react-bits 动画组件 与 星屿 Starris 动画过渡优化

| 项 | 内容 |
|---|---|
| 调研日期 | 2026-10-20 |
| 调研对象 | https://github.com/DavidHDev/react-bits （官网 https://reactbits.dev ） |
| 调研目标 | 评估 react-bits 的动画组件是否有适合本项目的效果；在不改变现有视觉风格（暖屿橙 tokens、克制生产力工具气质）的前提下，选定可落地的动画过渡优化点，提升整体视觉质感 |
| 任务性质 | **只调研，不改业务代码**（本报告即为本次任务全部产出） |
| 结论状态 | 依赖数据为 registry 源码实测；个别标注"待复核"的项接入前需再验证 |

---

## 1. 结论速览（TL;DR）

1. **有适合的组件，但只占少数**。react-bits 共 215+ 组件，其中大部分（WebGL 背景、炫技文本、光标特效）与"内容优先的笔记工具"气质冲突。真正适配本项目的约 **5 类触点、6 个组件**，集中在"入场过渡、卡片焦点反馈、数字滚动、扫光高亮"四种克制动效。
2. **依赖红线清晰**：实测 13 个组件源码后，候选组件分为三档——零依赖（ShinyText / SpotlightCard / TiltedCard / Dock）、motion 依赖（BlurText / CountUp，**项目已安装 motion**，零新增成本）、GSAP 依赖（SplitText / ScrollReveal / FadeContent / AnimatedContent，**不建议引入**，避免双动画体系 + 约 60-80KB 额外体积）。
3. **推荐路线**：P0 先做 4 个零/低成本触点（卡片聚光灯、空状态扫光、数字滚动、统一入场过渡）；P1 观察态再评估；WebGL 背景与炫技文本不采用。
4. **接入方式**：react-bits 是"复制源码"式组件库（shadcn registry，非 npm 包），落地时应复制 TS-Tailwind 变体进 `src/components/common/`，并把组件内写死的时长/缓动替换为项目令牌（`--dur-1/2/3`、`--ease`）。
5. **许可可用**：MIT + Commons Clause，允许免费集成进商业产品（限制的是"单独售卖组件本身"）；复制时保留版权头。

## 3. 仓库概览

- **定位**：开源动效 React 组件集（"Animated React components for websites people remember"），215+ 免费组件 + 付费 Pro 版；官方另有 Vue Bits / Svelte Bits 移植。
- **分类**：Text Animations 33 · Animations 38 · Components 48 · Micro 34 · Backgrounds 63。
- **消费方式**：**非 npm 包**。三种引入方式：`npx shadcn@latest add @react-bits/<Name>-TS-TW`、`npx jsrepo add https://reactbits.dev/r/<Name>-TS-TW.json`、直接从官网复制源码。每组件提供 JS/TS × CSS/Tailwind 四种变体。
- **许可**：**MIT + Commons Clause**——可免费用于个人与商业产品；不得将组件本身作为付费内容出售（集成进我们的应用不受影响）。
- **维护状态**：非常活跃，1686 commits，2026-10 刚完成 2.0 大版本重构 → 组件 API 迭代快，复制落地时必须**锁定当日快照并记录来源**。
- **与本项目的兼容性**：实测样本（如 ShinyText）源码为 React 函数组件 + hooks + Tailwind v4 任意值语法（`[background-clip:text]` 等），React 19 / Tailwind v4 环境可直接使用。

## 4. 依赖实测（13 个候选组件）

| 组件 | 分类 | 实测依赖 | 实现技术 | 对本项目的依赖成本 |
|---|---|---|---|---|
| ShinyText | 文本扫光 | **无**（实测 deps: `[]`） | rAF 驱动 `background-clip:text` 线性渐变，内置 `prefers-reduced-motion` 与 loop/hover/view 三种触发 | 零 |
| SpotlightCard | 卡片聚光灯 | **无**（实测 deps: `[]`） | rAF + `radial-gradient` + `color-mix`，pointer 追踪；支持 `theme="light"`、CSS 变量覆盖、键盘 focusin 点亮、reduced-motion | 零 |
| TiltedCard | 3D 倾斜卡 | **无**（实测 deps: `[]`） | pointer 追踪 rotateX/rotateY | 零 |
| Dock | macOS 放大坞 | 无动画库（仅 `react-dom` portal） | 手写弹簧物理（rAF）+ Web Animations API | 零（实现较重） |
| BlurText | 文字模糊入场 | `motion@^12.23.12`（实测） | motion 逐词动画 | **零（项目已有 motion）** |
| CountUp | 数字滚动 | `motion@^12.23.12`（实测） | motion 数值插值 | **零（项目已有 motion）** |
| SplitText | 文字拆分动画 | `gsap@^3.13.0` + `@gsap/react`（实测） | GSAP SplitText 插件（注：GSAP SplitText 曾为付费插件，开源策略 2025 年后才变化） | **高：新增 GSAP** |
| ScrollReveal | 滚动显现 | `gsap@^3.13.0`（实测） | GSAP ScrollTrigger | 高 |
| FadeContent | 内容淡入 | `gsap@^3.13.0`（实测） | GSAP ScrollTrigger | 高 |
| AnimatedContent | 内容入场（位移/模糊/擦除） | `gsap@^3.13.0`（实测） | GSAP + ScrollTrigger | 高 |
| Aurora / Particles 等背景类 | 全屏背景 | 以 WebGL/shader 为主（仓库自述；具体逐个**待复核**） | OGL/three 着色器 | 极高（体积 + 渲染开销） |

> 项目现有动画依赖：`motion`（React 19 兼容），无 GSAP、无 WebGL 库。AGENTS.md §5 要求"优先复用已有依赖"——上表据此划出红线。

## 5. 适配矩阵：建议应用到本项目的触点

优先级含义：P0 = 建议下一批动画任务落地；P1 = 可选增强；P2 = 观察；不采用 = 有明确反对理由。

### P0（零新增依赖，收益明确）

| # | 组件 → 项目触点 | 现状痛点 | 落地要点 |
|---|---|---|---|
| 1 | **SpotlightCard** → 知识库管理弹窗 KB 卡片、工作区管理卡片、信息面板「相关」文档列表 | 现在卡片 hover 只有 `bg-secondary` 平铺变色，层次感弱 | `theme="light"`；`spotlightColor` 用 `rgba(232,114,42,·)`（--primary 派生）而不是默认黑白；`--spotlight-card-surface/border/shadow` 三个 CSS 变量映射到 `--card / --border / --shadow-md`；`intensity` 调低至 ~0.10、`proximity` 60-80px 保持克制；组件自带键盘 focusin 点亮与 reduced-motion，无需额外处理 |
| 2 | **ShinyText** → 空状态主 CTA（"新建文档"按钮文字）扫光；首次启动欢迎标题单次扫光 | 空状态目前完全静态，缺一个"可扫到"的焦点 | 仅用 `trigger="hover"`（按钮）与 `trigger="view"` 单次（标题）；`speed` 2s→2.5s、`shineColor` 用 `--logo-c`（#F2B33D）暖金而非纯白，贴合暖屿主题；正文编辑区内**禁止**使用 |
| 3 | **CountUp** → 信息面板「字数」、设置-存储统计（文档 128 / 画板 342 MB 等）、KB 卡片 docCount | 数字直接跳变，统计场景缺"完成感" | 时长压到 400-500ms 并用 `--ease`；配合 `prefers-reduced-motion` 直接显示终值；千位分隔与现有文案一致 |
| 4 | **统一入场过渡**（对应 FadeContent/AnimatedContent 的**能力**，但用 motion 重写，不复制 GSAP 源码） | 目前只有 `anim-fade-in`（纯淡入）；浮窗/弹窗/标签切换缺少位移与层次 | 封装一个 `<Reveal>`（motion 实现：y 8-12px + opacity + 可选 blur 4px，300ms `--ease`，支持 stagger）；替换现有 `anim-fade-in` 调用点；这就是"动画过渡优化"的主体 |

### P1（可选增强，效果与风险都中等）

| # | 组件 → 触点 | 说明 |
|---|---|---|
| 5 | **BlurText** → 空状态标题（"从一个想法开始"）入场 | 逐词 blur+上移，motion 实现零新增依赖；仅首屏/空状态用一次，不重复触发 |
| 6 | **TiltedCard** → 信息面板「相关」卡片 hover 微倾斜 | 幅度必须调小（rotate ≤ 6°、缩放 ≤ 1.02）；仅悬浮预览类小卡，不放主编辑区 |

### P2（观察，暂不建议立项）

- **Dock**（侧栏快捷钮放大镜）：实现是手写弹簧物理，代码量不小；对 3 个快捷钮的交互增益存疑，且 macOS 红绿灯区已在侧栏顶部，再放"坞"会拥挤。观察用户反馈再定。

### 不采用（有明确反对理由）

| 类别 | 理由 |
|---|---|
| WebGL/shader 背景（Aurora、Particles、Waves、LiquidChrome 等 63 个） | 体积与渲染开销大（着色器）；与"暖色、安静、内容优先"的笔记工具气质直接冲突；GPU 占用对低配机器不友好 |
| 炫技文本（GlitchText、ScrambleText/DecryptedText、TextPressure、VariableProximity 等） | 干扰阅读、纯装饰；Scramble 类还会造成文本不可读窗口 |
| ClickSpark / 光标特效（GhostCursor、Magnet 等） | 生产力工具应克制；点击粒子在写作场景是负反馈 |
| GSAP 系组件（SplitText、ScrollReveal、FadeContent、AnimatedContent）源码直接复制 | 会引入第二个动画体系（~60-80KB min+gzip）+ 双套心智；其能力已由 P0-4 的 motion 方案覆盖 |

## 6. 统一实施约束（立项落地时作为验收标准）

1. **来源可追溯**：每个复制的组件在《项目文件改造清单》记录来源 URL、变体（TS-TW）、复制日期与当日上游状态（2.0 刚重构，API 可能继续变）。
2. **令牌化**：组件内写死的 `duration/ease/color` 全部替换为 `var(--dur-1|2|3)`、`var(--ease)`、主题色变量；新增颜色一律走 `src/styles/tokens.css`，禁止出现孤立的 hex。
3. **目录归位**：复制源码放 `src/components/common/`（跨弹窗/面板共用），带中文注释说明来源与改造点；不建 `misc/temp` 类目录（AGENTS.md §2.1）。
4. **依赖红线**：仅允许零依赖组件与已有 `motion`；引入 GSAP/OGL/其他动画库必须先走 AGENTS.md §5 依赖审批并在任务记录说明必要性。
5. **性能口径**：动画只跑 `transform / opacity / filter` 合成层属性；rAF 组件要求"静止即停帧"（SpotlightCard / ShinyText 已内置）；列表 stagger 单页 ≤ 12 项。
6. **可访问性**：全部动效必须响应 `prefers-reduced-motion`（ShinyText / SpotlightCard 实测已内置；motion 组件用 `useReducedMotion`）；键盘 focus 必须有等价视觉反馈（SpotlightCard 的 focusin 点亮已满足）。
7. **风格保持**：所有光效/扫光颜色从主题令牌派生（暖屿橙、暖金）；深浅主题各过一遍（8 主题 × 深浅，至少验证 sunset 明暗两态）。

## 7. 风险与未决问题

1. **上游变动快**：react-bits 2.0 于 2026-10 大版本重构，registry 内容可能持续变化 → 复制即锁定，后续升级视为新任务（手工 diff）。
2. **GSAP 组件的能力缺口**：SplitText 的按字符拆分、ScrollTrigger 的 scrub 联动，motion 需要自写少量等价逻辑；P0-4 的 `<Reveal>` 范围仅"入场"，不做 scrub 滚动联动（笔记工具无长滚动页，收益低）。
3. **未复核项**：StarBorder、ClickSpark、BounceCards、InfiniteScroll、Aurora/Particles 的 registry 依赖未逐一实测（本次抓取被网络环境截断）；其中前三者已列入不采用/P2，不影响结论；背景类若未来翻案，先按 §2 方法补测。
4. **Commons Clause 边界**：组件可集成进 Starris，但未来若把"复制自 react-bits 的组件"单独打包售卖/做付费组件市场，会触碰 Commons Clause——需要在分发时注意。
