## 背景

单行顶栏把窗口 chrome 与文档操作压在同一排：标签、面包屑、已保存、收藏、目录、信息、分享、打印、搜索、设置同时出现。用户要求顶栏只保留标签与搜索，文档操作下沉到文档页头，面包屑放到正文左上空白区；保存状态继续由正文 `SaveIndicator` 承担。

## 终态

1. **顶栏瘦身**：`WindowBar` 只保留标签页、全局搜索与窗口控制。删除面包屑、`已保存` 胶囊、收藏/目录/信息/分享/打印与设置；设置仍可从侧栏「更多」进入。
2. **文档页头**：新增 `DocPageBar`，顶行左侧是「知识库 › 文档」面包屑，右侧是 5 个 28px 图标钮（收藏、目录、信息、分享、打印）；下方保留「文档」徽标、输入提示、标题与 meta。
3. **保存态唯一**：删除顶栏保存胶囊，正文 meta 行的 `SaveIndicator` 继续展示本地自动保存 / 有未保存更改 / 正在保存 / 已保存 / 保存失败·重试。
4. **信息浮窗避让**：浮窗起点从 `top-4` 下移到 `top-16`，展开时从页头操作行下方开始，分享/打印不被遮挡。
5. **目录首开修复**：加载正文使用 `emitUpdate:false` 导致 TOC 不自动发布；加载完成后显式 `updateTableOfContents()`。同时 `onOutline` 透传来源编辑器，过滤 StrictMode/重建后旧实例的延迟回调，避免 3 条目录被一次空发布清空。
6. **页面留白**：`.doc-editor-page` 顶部间距 52px → 28px（窄屏 28 → 20），把原来的空白让给面包屑行，标题整体下移约 14px。

## 方法论沉淀

- **窗口 chrome 与文档 chrome 要分层**：标签/搜索属于窗口，收藏/目录/信息才属于文档；同排会让顶栏随文档数量增长而失衡。
- **把控件移进浮层覆盖区前，先量遮挡**：信息浮窗默认展开，页头操作放在其下会被整体盖住；下移浮窗起点是最小修复。
- **StrictMode 的延迟回调会回写共享单例**：大纲是进程内单 owner 存储，旧编辑器实例的空发布必须按来源过滤，不能只靠 owner 身份。
