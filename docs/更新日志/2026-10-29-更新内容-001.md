# 2026-10-29 更新内容 001

- 关联需求：`docs/需求文档/2026-10-29-需求文档-界面收口-附件与存储.md`
- 关联任务：`docs/开发任务清单/2026-10-29-任务-001/`
- 涉及模块：附件（预览/上传）、新建弹窗、知识库管理、设置-存储、本地数据清理

## 用户可见的变化

1. **附件页更干净**：页头只剩「下载」；不再有「校验完整性」这类程序内部入口，信息表也不再有「创建时间」。
2. **常用格式能直接看**：图片、纯文本（.txt）、Markdown（.md）、Word（.docx）在应用内预览；
   其它类型仍是「该类型暂不支持预览，可下载后查看」。图片会显示自然尺寸，透明区域有棋盘格衬底，
   极小图会放大显示，加载失败会明确提示而不是留一块空白。
3. **上传支持整个文件夹**：文件树工具栏的上传按钮点开后先选「选择附件 / 选择文件夹」（新建弹窗只保留四类节点，不含附件）。
   选文件夹会按目录层级创建文件夹节点并递归上传其中的文件：
   同名文件夹复用、同名文件自动改名（`笔记 (2).md`）、隐藏文件与符号链接跳过；单次上限 2000 个文件 / 2 GB，超限时一个节点都不建。
4. **知识库管理**：列表去掉「条目数」列。
5. **保留时间改完即生效**：设置-存储 的「保留时间」不再需要点保存，停止输入约 0.6 秒自动落库；
   越界（未使用/回收站 1–365 天、临时文件 1–168 小时）会提示且不落库；关闭设置时未落库的改动会补写。
6. **立即清理说明改成用户话术**：「只清理临时数据和过期数据；正在使用的文档、画板、思维导图与附件不会删除。」
   清理结果提示同步改为「已清理 N 项临时或过期数据」。
7. **本地数据清理**：删除了三个历史测试留下的工作区目录（`~/Downloads/11111`、`~/Downloads/1`、`~/Downloads/test`，共 29 MB），
   保留在用的 `2222333` 与旧版真实笔记目录。

## 实现要点

- 新增 `attachment_preview` 命令：txt 只读前 512 KB；Markdown 与 Word 复用导入用的同一套解析，以「预览模式」运行
  （不把图片/本地链接写进附件库）；Word 到暂存目录解析后立即删除临时文件。
- 新增 `attachment_tree_import_service`：单文件上传→建节点→失败回滚只有一份实现；目录导入先收集清单再动手，保证护栏不通过时零副作用。
- 前端新增 `AttachmentPreviewBlocks` 只读块渲染，不引入新的 Markdown 渲染依赖。

## 未采用与原因

- **一个面板同时选文件与文件夹**：Tauri dialog 插件的 `directory` 是二选一，底层 rfd 在 macOS 把两个开关写死互斥；
  自建 `NSOpenPanel` 同时置真后，真机上 `runModal` 阻塞主线程且面板不进 AX 树（四种修法均失败），
  最终改为同一入口下的两个明确按钮，代码与 objc2 依赖已移除。
