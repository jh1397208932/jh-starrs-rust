# 2026-10-22 图片与附件块：事实与踩坑

## 节点契约

- `attachmentImage` 是 atom 块，attrs 只存 `attachmentId/name/size/mime/alt/width/align`，**不存 src**；预览通过 `attachment_read_bytes` 读取对象字节，前端生成 Blob URL，卸载/ID 变化时 revoke。
- `attachmentBlock` 是 atom 块，attrs `items[]/variant/align`；items 每项有 `uid`（组内实例 id）、attachmentId、name、size、mime。不要为每项建 ProseMirror 子节点：NodeView 一次渲染卡片/长条更简单，拖动/删除整组也稳定。
- 旧 `image` 节点保留官方 Image 扩展；新上传不再写 data URL。两者可同时存在。

## NodeView 关键点

- 必须使用 `NodeViewWrapper`；atom 节点不渲染 `NodeViewContent`。
- 点击图片用 `editor.commands.setNodeSelection(getPos())` 选中；否则自定义工具栏永远不出现。
- 工具栏/缩放柄只在选中时挂载，避免 opacity:0 的按钮仍进入 Tab 顺序与无障碍树。
- 文字 BubbleMenu 的 `shouldShow` 要加 `state.selection.$from.parent.inlineContent`；否则选中图片/附件块时文字格式菜单会与块浮条叠在一起。
- 图片 frame 用 `<fieldset>`（`min-inline-size:0; border:0; margin:0; padding:0`）承载 onMouseDown，既满足语义又避开 `role=group` 的语义化 lint；缩放柄是 frame 内的按钮。
- 缩放：pointerdown 记录 frame 实际宽度；window pointermove 更新本地 width；pointerup 才 `updateAttributes({width})`，避免每帧写事务。最大宽度用 `editor.view.dom.clientWidth`，最小 120px。
- 没有 width attr 时，图片 onLoad 后按自然宽度 clamp 到正文宽度；不要在 load 前写死宽度。
- 附件卡片 key 用 `item.uid`，不要用 index；重复引用同一 attachmentId 时也不会撞 key。

## 文件图标

- 自绘 SVG 页面：折角 + 底部类型色条 + 扩展名文字。`FileTypeIcon` 必须把基础类 `file-glyph` 与外部 className 合并（本轮曾漏加基础类，导致图标全部无样式、`querySelector('.file-glyph')` 读不到）。
- 类型色全部用语义令牌（primary/destructive/accent-foreground/logo-c/glow-b/muted-foreground）；不要引入紫/靛蓝。
- 扩展名标签 ≤4 字符；未知类型回退 FILE，不能留空。

## 上传链路

- 文件选择器返回路径：`attachment_upload(sourcePath)`；Slash/右键都走这条。
- 粘贴/拖放的 File 没有本地路径：Tauri raw IPC `invoke(cmd, Uint8Array, {headers})` + `attachment_upload_bytes`。header 只允许 ASCII，文件名/逻辑路径用 UTF-8 hex；Rust 侧解码后再校验。
- FileHandler 配置不要只允许图片；去掉 `allowedMimeTypes` 才能接收任意附件。
- 上传插入位置在打开对话框/开始上传前捕获；上传完成后若 `docSeqRef` 变化则丢弃插入，避免把旧批次写进新文档。
- 上传中状态放在编辑器 header，不用临时文档节点占位（会被自动保存）。

## 测试/门禁

- 浏览器 harness 的 `attachment_read_bytes` mock 必须让字节 MIME 与附件 attrs 一致：PNG 名称配 SVG 字节会导致 naturalWidth/宽度异常；截图用 SVG 预览时把名称/MIME 也设为 SVG。
- headless Chrome + canvas.toBlob 预览在 virtual-time 下可能没完成；截图用静态 SVG 字节更稳定。
- 真实 WKWebView 的 raw IPC/Blob URL 未验证；不要拿 Chromium mock 当桌面端通过。
- 新增 Rust 依赖后先 `cargo fetch`，否则离线许可证门禁会因平台目标依赖未缓存失败；本轮未新增依赖。

## 真机反馈修复轮（2026-10-22 追加）

### Tauri 的拖放不是网页的拖放

- `dragDropEnabled` 默认为 **true**：Tauri 在原生层接管从访达拖入的文件，网页侧 `drop` 事件的 `dataTransfer.files` 是空的，`@tiptap/extension-file-handler` 的 `onDrop` 永不触发。表现就是"拖进来没反应"，而 Chromium 里同一条代码路径完全正常——这类差异只有真机能暴露。
- 官方配置文档原文："By default it is enabled. Disabling it is required to use HTML5 drag and drop on the frontend." 这条同时解释了早前官方 DragHandle 在 WKWebView 里拖不动的成因：**同一个开关**屏蔽了 HTML5 拖放。自绘 PointerEvent 手柄不受影响。
- 不关这个开关，改用 `getCurrentWebview().onDragDropEvent`：事件直接给**绝对路径**，能复用已测过的路径流式上传，且不受粘贴那条 64 MiB 字节上限约束。
- 事件里的 `position` 是**相对 webview 左上角的物理像素**，必须除以 `devicePixelRatio` 才是 `posAtCoords` 要的视口 CSS 像素。开着 DevTools 时该坐标可能不准（官方注明的限制），真机复测时要 detach 调试器。
- 落点判据要有一道"归属门"：事件对整个窗口都会触发，落在左侧树或顶栏时若一律退回文末，就会把文件塞进当前打开的文档。`resolveDropInsertPos` 因此先判落点是否在正文容器内，容器外返回 `null` 让调用方放弃。

### 浮条的居中参照物

- 浮条 `left: 50%` 居中的是**定位祖先**，不是"看得见的那坨内容"。图片块没事（shell 在 flex 容器里收缩到图片宽度），附件块出事（shell 是普通块元素，宽度等于整行正文）——同一份浮条样式在两种块上语义不同，只看图片块的截图会漏检。
- 改法是把对齐上移到块元素（flex + `justify-content`），让 shell 在卡片形态下 `width: fit-content` 收缩；长条形态必须保持 `width: 100%`，否则行内 `width: 100%` 的长条会在收缩容器里塌成文字宽度。
- 判据不能拿"卡片组容器"当参照物：旧布局下那个容器同样是整行宽，量出来偏差永远是 0（本轮第一次测就是这样全绿）。要量**卡片自身**的并集中心，并且做一次变异——把样式临时退回旧布局，看偏差是否真的变成非零（实测 −645px）才算判据有牙。
