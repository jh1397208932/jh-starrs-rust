# 记忆 · 2026-10-23 · 主题迁移与雾光笺

## 1. 默认主题为什么是 mist

第十一轮把默认外观从 `sunset` 改为 `mist`（雾光青）。迁移不靠“每次启动都强制”，而是：

- 前端记忆写入 `appearance.designVersion = 2`；
- 仅当「没有 designVersion」且「已存主题是旧默认 sunset」时，写一次 `appearance.theme = mist`；
- 用户主动选过的其它主题不覆盖。

Rust 侧 `THEME_NAMES` 是白名单，任何新主题必须同步，否则 `memory_save` 会拒绝但 UI 仍显示新主题（内存态与落盘态不一致）。单测 `theme_names_accept_all_presets_and_reject_unknown` 守住这一点。

## 2. 新增/修改主题的检查单

1. `src/styles/tokens.css`：补 light 主题块 + `[data-theme=x][data-mode=dark]` 强调层。
2. `src/lib/theme.tsx`：`THEME_NAMES` 与 `THEME_LABELS` 各加一项。
3. `src/features/settings/components/SettingsDialog.tsx`：主题网格自动遍历 `THEME_NAMES`，无需改布局；确认 3×3 能放下。
4. `src-tauri/src/domain/mod.rs`：`THEME_NAMES` 数组长度与内容同步，补/改单测。
5. `node scripts/check-contrast.mjs --check`：9（未来 10）主题全 PASS。
6. 真机切一次主题，重启后再看是否仍生效（验证落盘，而不是只验证内存态）。

## 3. 真机截图的两个坑

- **离屏/非前台窗口会停在动画首帧**：BlurFade 的 initial 是 `opacity:0`，WebKit 在窗口不可见或非前台时会暂停 rAF，截图上就只剩背景圆环、没有标题/CTA。这不是渲染 bug，别去删空态内容；把窗口切到前台或等动画落定后再截。必要时临时让 BlurFade 渲染终态，截完立即还原。
- **AX 枚举不到 WKWebView 窗口**：`System Events` 常报 `window 1 ... 无效的索引`，`CGWindowListCopyWindowInfo` 却能看到窗口。此时不要继续用合成点击/AXPress 折腾；用 `screencapture -l <CGWindowID>` 截窗口，坐标从 `kCGWindowBounds` 取。`NSRunningApplication.activate` 返回 true 也不等于真的抢到前台（macOS 14 已忽略 `activateIgnoringOtherApps`）。

## 4. 主题记忆存在哪

全局库：`~/.starris/rust/db/starris.db` → `settings` 表：

- `appearance.theme`：主题 id
- `appearance.mode`：light / dark
- `appearance.designVersion`：设计语言版本（当前 2）

`current_workspace_id` 是保留键，前端不能直接写。手工改库只在“应用未运行”或“改完强制整页重载”时做，否则会与内存态冲突。

## 5. 雾光笺的三条硬约束

- 侧栏行永远透明；hover 只加 `--sidebar-active` 或 24–28% card，选中才出现主题浅调底。
- 工作区入口是透明品牌行，不是卡片；不要给它边框、阴影或大白底。
- 主题色只做图标/描边/选中指示；浅调底上的文字一律用 `accent-foreground` / `sidebar-active-fg`，不用 `primary` 写正文。
