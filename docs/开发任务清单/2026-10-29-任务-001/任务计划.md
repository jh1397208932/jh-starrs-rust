## 实现方案

### 1. 清理测试遗留工作区（已完成）

删除 `~/Downloads/11111`、`~/Downloads/1`、`~/Downloads/test`；保留在用的 `2222333` 与旧版真实笔记 `~/Documents/笔记文件夹`。

### 2. 附件页去「校验完整性」

`AttachmentNodeView.tsx`：删按钮、删 notice 状态里的校验分支与其文案键使用（文案键保留在词典里，供后续复用，不新增缺失）。
`verify_attachment` 命令保留（内部诊断用），只去掉界面入口。

### 3. 附件预览

- 新增 Rust 命令 `attachment_preview(node_id)`，按扩展名/MIME 返回三类之一：
  - `{"kind":"text","text":"…","truncated":bool}`：txt（≤512 KB，超出截断）
  - `{"kind":"blocks","format":"markdown"|"docx","blocks":[…]}`：md 走 `parse_markdown`，docx 先materialize 到暂存文件再 `parse_word`，返回块 JSON
  - `{"kind":"unsupported"}`
  - 图片继续走现有 `attachment_read_bytes`（不改其契约）
- 前端新增只读块渲染组件 `AttachmentPreviewBlocks`：只渲染标题/段落/列表/代码块/引用/分割线/图片占位，未知节点降级为纯文本；不渲染 HTML、不执行脚本。
- `AttachmentNodeView` 按扩展名分派；兜底文案保持不变；错误显示明确原因。

### 4. 附件信息表去「创建时间」

`AttachmentNodeView.tsx:199` 删一行即可。

### 5. 上传附件支持选文件夹

- Rust 新增 `pick_any_paths`（macOS：`NSOpenPanel` + `canChooseFiles` + `canChooseDirectories` + 多选，`run_on_main_thread` 执行；非 macOS：退回现有插件单文件选择）。
- 前端 `api/fileDialog.ts` 新增 `pickUploadTargets()`；`useWorkspaceMainController` 的 `uploadAttachmentsToTree` 改为：
  1. 拿到路径列表后先分类（文件 / 目录）；
  2. 目录走新命令 `attachment_upload_folder(parent_id, folder_path)`：Rust 侧递归遍历（跳过 `.` 开头与符号链接、深度 ≤32），先算清单再校验护栏（≤2000 文件、≤2 GB），逐层复用同名文件夹节点，文件按层级挂载，同名文件自动 `名称 (2).ext`；
  3. 单文件仍逐个走现有 `attachment_upload_to_tree`；
  4. 前端显示「正在上传 x/y」与完成汇总，部分失败逐条提示。
- 按钮、文案、位置不变。

### 6. 知识库管理去「条目数」

`KbManageDialog.tsx`：`GRID` 由 4 列改 3 列，删表头与值单元格；`docCount` 字段保留（其它页面仍可能用）。

### 7. 保留时间改完即生效

`MaintenancePolicyEditor.tsx`：删「保存」按钮与 `saving` 状态；`update()` 里做范围校验后 600 ms 防抖调 `updateMaintenanceSettings`；
成功显示「已保存」，失败显示错误并保留输入；加载失败时禁用输入。

### 8. 立即清理文案

`SettingsDialog.tsx`：说明改为一句用户话术（临时数据/过期数据 + 不会删除正在使用的内容），移除 hash、索引、引用等词。同步改 i18n 英文条目。

## 执行时的方案变更（2026-10-29）

1. **「一个面板同时选文件与文件夹」没落地**：已按计划实现 `utils/native_picker.rs`（objc2 直接开 NSOpenPanel，两个开关都置真），
   真机上 `runModal` 阻塞主线程且面板不进 AX 树；依次尝试激活应用、抬到屏蔽层级、坐标点击、键盘选择四种修法仍不稳定。
   改为：新建弹窗里「上传附件」独立成块，两个明确按钮「上传文件 / 上传文件夹」，分别走官方文件选择器与目录选择器；
   `native_picker.rs` 与 objc2 直接依赖已删除。原因写在 `项目文件改造清单.md` 的「已放弃的方案」。
2. **图片预览看起来「一片空白」**：根因是测试素材 `pixel.png` 是全透明 1×1 PNG，不是预览坏了。
   产品侧补：透明底棋盘格、小图放大显示、自然尺寸标注、加载失败明确提示；测试素材新增 32×32 实心色块 `swatch.png`。

4. **附件入口的最终定稿**：先在新建弹窗里做成「上传附件」区域（两个按钮），再按反馈改成与四类节点同级的第 5 张卡片，
   最后按需求方口径定稿为 —— 新建弹窗只做四类节点；上传入口回到文件树工具栏的上传按钮，点开一次二选一（选择附件 / 选择文件夹）。
   三种形态都只是入口位置，递归导入与护栏逻辑不变。
