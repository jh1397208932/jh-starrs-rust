# 任务-001 计划：导出 / 导入闭环与页头细化

- 日期：2026-10-24
- 关联需求：`docs/需求文档/2026-10-24-需求文档-导出导入与页头细化.md`
- 关联设计：`docs/设计/2026-10-24-导出导入-001/`

## 1. 目标

1. 页头删除提示、保存态移到徽标行、meta 去创建时间、信息浮窗默认关闭并改「新建时间」。
2. 单文档导出 md / html / docx / pdf，md 附件落同级 `attach/`。
3. 整库按树导出，含附件、未引用附件、manifest。
4. Markdown / Word 文件与目录批量导入，可指定子文件夹并保留层级，原始文件附加保证不丢数据。

## 2. 实现方案

### 2.1 前端

- `DocEditor`：`SaveIndicator` 移入徽标行，meta 只留字数/最近编辑；切换文档滚动回顶；页头 `DocPageBar` 导出按钮改 Download。
- `InfoPanel`：字段「创建时间」→「新建时间」；`infoOpen` 默认 false。
- 新增 `api/exchange.ts`、`types/exchange.ts`、`FileDialog` 的导出路径/导入文件选择。
- 新增 `ExportKnowledgeBaseDialog`、`ImportDialog`；重写 `ShareExportDialog` 为四格式导出。
- `WorkspaceMainController` 新增 `exportActiveDocument` / `exportCurrentKnowledgeBase` / `importIntoKnowledgeBase`，统一 flush 当前文档、调用 IPC、刷新树与 toast。
- `MoreMenu` 接通全部导出/导入；文件树文件夹菜单增加「导入到此文件夹」。

### 2.2 Rust

- `models/exchange.rs`：导出/导入 DTO。
- `services/export_render.rs`：Markdown/HTML/DOCX/PDF 渲染；附件路径注入；未知块以 JSON 代码块保留。
- `services/export_service.rs`：单文档与整树导出、附件落盘、manifest、未引用附件、重名处理。
- `services/import_markdown.rs`：pulldown-cmark 全选项事件流 → Tiptap。
- `services/import_word.rs`：office_oxide IR → Tiptap（段落/标题/列表/表格/图片/脚注/页眉页脚/文本框）。
- `services/import_service.rs`：文件/目录扫描、目标父级、重名标题、节点创建、文档保存、原文件附件、失败兜底。
- `commands/export.rs`、`commands/import.rs` 注册到 `lib.rs`。

## 3. 依赖

- `office_oxide`（MIT/Apache-2.0）：DOCX/DOC IR 解析。
- `docx-rs`（MIT）：DOCX 生成，图片/表格。
- `printpdf`（MIT）：HTML → PDF，系统字体。
- `pulldown-cmark`（MIT）：Markdown 事件解析。
- `html-escape`、`base64`、`percent-encoding`、`image`。

## 4. 风险

- PDF 依赖系统字体，Linux 缺 Noto Sans SC 时中文回退可能不理想。
- DOCX 列表导出使用文本标记，不是 Word 原生编号域。
- 大批量/PDF 串行导出耗时；本轮先保证正确与闭环。
- 复杂域、宏、嵌入 OLE 只能靠原文件附件兜底。

## 5. 验收

见需求文档 §4；Rust 集成测试覆盖四格式、整树、MD/Word/目录导入；前端 check/typecheck/build 全绿。
