# 任务计划 · 对象存储与附件生命周期（2026-10-25-任务-004）

- 需求：`docs/需求文档/2026-10-25-需求文档-对象存储生命周期.md`
- 前置：任务-003（文案精简）已完成
- 后续：任务-005 附件树依赖本任务的关联表与生命周期

## 目标

建立 `node_attachment` 引用闭环，补齐孤儿/回收站/TTL/临时文件/看门狗，避免删除文档、画板、节点后留下对象碎片；所有清理有可验证的统计与测试。

## 实现步骤

1. **schema v10**：node 表重建支持 type 6；新增 `node_attachment`、`attachment.scope/expires_at/orphaned_at` 与索引；回填旧文档/画板引用。
2. **引用服务**：新增 `attachment_reference_service`，统一提取文档/画板 object_id、同步引用差量、标记孤儿、查询关联数。
3. **保存闭环**：`document_service::save`、`board_service::save` 在同一事务同步引用；节点/知识库删除后增量标记孤儿。
4. **生命周期**：`attachment_service` 支持 scope/TTL；软删除保留 blob 与恢复；新增 restore/purge；显式删除有关联附件时拒绝。
5. **维护服务**：`attachment_maintenance_service` 执行 staging 清理、孤儿转回收站、TTL、回收站 purge、孤儿 blob、pack 压缩；启动一次 + 每 6 小时线程；手动命令。
6. **统计与 UI**：实际磁盘/可回收/回收站统计；设置存储页恢复、彻底删除、立即清理、关联数。
7. **测试**：迁移、引用同步、共享对象、撤销重做、TTL、孤儿、回收站、看门狗；前端门禁与真机 E2E。

## 风险

- node 表重建涉及既有外键，必须用 foreign_keys OFF + legacy_alter_table 并做外键检查。
- 软删除保留 blob 会改变现有删除语义与测试，需要同步更新测试和统计。
- 看门狗与上传/删除并发：共用存储锁，禁止持有 UI 状态锁做 IO。
- 旧附件回填可能耗时：迁移中单事务完成，失败回滚；日志记录数量。
