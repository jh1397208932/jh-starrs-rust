# 任务计划 · 当前知识库写入全局记忆（2026-10-22-任务-001）

- 关联需求：`docs/需求文档/2026-10-21-需求文档-本地工作区与文件树.md` §US-7
- 目标：让每个工作区记住用户最后选择的知识库，切换工作区/重启后优先恢复，而不是总回到第一个库。
- 输出：全局记忆键 `kb.current.<workspaceId>` 的读写；真实 Tauri 窗口验证与截图归档。

## 方案

- **键设计**：`kb.current.<workspaceId>`（UUID 中的字母/数字/连字符符合记忆键白名单），按工作区隔离，避免多个工作区互相覆盖。
- **写入**：`useWorkspaceStore` 在知识库切换成功前调用统一 `memory_save`；内容加载发现记忆失效（库被删）时回退第一个库并回写。
- **读取**：`app_bootstrap` 已返回全部记忆；store 把快照放入 `memoryRef`，`loadContent` 依次选择“显式指定 → 记忆值 → 当前值 → 第一个库”。
- **并发**：知识库记忆写操作通过 Promise 队列串行化，避免启动加载的旧写入覆盖用户的新选择。
- **不改数据库结构**：复用全局库 `settings` 表与现有 `memory_load/memory_save`。

## 拆分步骤

1. `api/memory.ts` 增加 `currentKbKey(workspaceId)`。
2. `useWorkspaceStore` 增加记忆快照 ref、写入队列、恢复/回写逻辑。
3. Rust 记忆测试覆盖 `kb.current.*` 键。
4. 前端 check/typecheck/build；Rust fmt/test。
5. 真实 Tauri 窗口验证“启动恢复 → 切换写库 → 重启恢复”，归档截图。
6. 更新需求/架构/数据库/功能测试/任务/更新日志。

## 验收标准

| 编号 | 标准 |
|---|---|
| B1 | 切换知识库后，全局库 `settings` 出现/更新 `kb.current.<workspaceId>=<kbId>` |
| B2 | 重启应用后自动选中该工作区记忆的知识库 |
| B3 | 不同工作区的当前知识库互不覆盖 |
| B4 | 记忆指向已删除知识库时回退第一个库并回写 |
| B5 | 前端 check/typecheck/build 与 Rust test 通过 |
| B6 | 真实 Tauri 窗口完成 B1/B2（截图归档） |

## 风险

- 删除工作区后其 `kb.current.*` 键会留在全局库（小体积孤儿键）；不影响功能，后续可在删除工作区时按前缀清理。
- 写入失败时知识库切换不生效并提示错误，优先保证“选中即已记忆”。
