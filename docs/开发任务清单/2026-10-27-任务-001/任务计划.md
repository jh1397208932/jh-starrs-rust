## 1. 目标

在真机（生产前端构建档位）定位并修复全部渲染性能瓶颈；对全部交互触点检查性能并补合理动效；达成"操作视觉连贯丝滑、无可感知掉帧"（验收标准 A1-A7 见需求文档）。

## 2. 范围

- 修：B1 大面积 backdrop-filter、B2 全应用重渲染、B3 标签切换重挂载、B4 指针热路径、B5 侧栏折叠、B6 打字期成本（以基线权重取舍）。
- 建：`log_write` + `src/lib/logger.ts` 日志链路（永久）；临时帧率探针（任务结束删）；`test/perf` 真机场景采集脚本。
- 补：交互触点动效，全部走现有 Motion/CSS 令牌。
- 不改：业务语义、schema、第三方库内部；不引入新动画依赖。

## 3. 实现方案与拆分步骤

1. **测量基建**：`log_write` 命令（Rust，写 `logging::info/debug`）→ `src/lib/logger.ts`（攒批/冲刷/隐藏时送出）→ `perfProbe.ts`（rAF delta 采样，5s 汇总 + 长帧即时上报）。
2. **真机采集**：包装 .app 启动生产前端二进制（隔离 `STARRIS_HOME`、`STARRIS_LOG_LEVEL=debug`），AX 驱动 9 类场景；读日志出基线报告。
3. **修复**：按基线权重逐项实施（每项独立提交粒度，修完即跑 `check + typecheck`）。
4. **动效补全**：性能达标后按触点表补动效（弹簧/进出场/微反馈），`prefers-reduced-motion` 全覆盖。
5. **复测对比**：同构建同场景同次数对比，归档对比表。
6. **收尾**：全量门禁 + `pnpm run test` 黑盒 + 删探针（grep 自证）+ 文档归档。

## 4. 依赖

- 生产前端 debug 二进制（已构建，2026-10-27 17:23，`target/debug/starris-rust`）。
- e2e harness 的 `NativeAX`（复用，不改动原 harness 文件）。
- 无新增 npm 依赖。

## 5. 风险

| 风险 | 应对 |
|---|---|
| 去模糊改变视觉观感 | 先 A/B 确认权重；截图对比；优先降半径/单层化 |
| 工作区有未提交思维导图改动 | 编辑前重读现场，只改必要片段 |
| WKWebView 帧率上限未知 | 先测空闲 rAF，判定平台档位 |
| `tauri dev` 会覆盖性能档二进制 | 每次采集前确认二进制为生产前端档 |

## 6. 验收标准

见需求文档 A1-A7。核心：主要交互 p95 ≤ 16.7ms、无可感知长帧；门禁与全量黑盒 e2e 全绿；探针删除无残留。

- `npm run check` / `typecheck` / `build` / `check:licenses`
- `pnpm run test`（全量黑盒，真机）
- `test/perf` 基线与复测报告
- grep 自证探针已删
