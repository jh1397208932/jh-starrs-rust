## 目标

在 Tiptap 编辑器实现 `attachmentImage` 与 `attachmentBlock` 两个自定义 atom 块，图片可预览/对齐/缩放/下载，附件按类型显示自定义图标并支持卡片/长条形态、对齐、逐项下载/移除；所有上传、回显、下载统一走附件对象模块。

## 范围

### 后端

- `attachment_read_bytes`：按附件 id 读取原始字节，仅图片、上限 20 MiB，raw IPC 返回。
- `attachment_upload_bytes`：raw IPC body + hex header 元数据，上限 64 MiB。
- `attachment_store::stage_bytes` / 通用 `stage_reader`。
- `domain/document.rs`：Markdown 支持两种新节点；props 增加 attachment 计数。
- 集成测试：bytes 上传、预览读取/上限/类型拒绝、Markdown/props。

### 前端

- `api/attachment.ts`：`uploadAttachmentBytes`、`readAttachmentBytes`；`api/client.ts` 支持 raw invoke。
- `api/fileDialog.ts`：图片过滤选项。
- `features/attachments/`：类型分类、`FileTypeIcon` 自绘图标。
- `features/editor/extensions/{attachmentImage,attachmentBlock}.ts` + React NodeViews。
- `features/editor/utils/attachmentUpload.ts`：路径/字节上传并构建节点。
- `DocEditor`：Slash/右键/粘贴/拖放接入、上传中状态、标签映射。
- `editorExtensions`：注册新节点；FileHandler 改为所有文件、上传至对象模块。
- `app.css`：图片块/附件块/图标/工具栏/缩放柄/两种形态/深浅主题。

### 测试与文档

- Rust 52→新增附件节点相关测试。
- Chromium 功能测试：图片预览/对齐/缩放、附件卡片/长条/图标/下载/移除、粘贴上传、回显。
- 更新 UI-SPEC、数据库/架构（如 props 字段）、更新日志、记忆、任务记录。

## 风险

- `attachment_upload_bytes` 的 raw body 与 headers 需 Tauri 编译验证。
- NodeView 内按钮/缩放与 ProseMirror 选中事件冲突。
- Blob URL 在 WKWebView 的行为需真实 Tauri 复测。
- 20 MiB 预览上限是产品取舍；超大图片仅能下载。
- 旧 data URL 图片保留官方 Image，不做一次性迁移。
