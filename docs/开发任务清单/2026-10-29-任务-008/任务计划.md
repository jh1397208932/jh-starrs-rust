# 任务计划：全模块性能白盒审计与修复

- 任务编号：2026-10-29-任务-008
- 关联需求：用户 2026-10-29 反馈（画板右侧组件库加载慢、滚动时先空图标；要求按功能模块逐一白盒审计调用链）
- 开始日期：2026-10-29

## 目标

1. **组件库体验**：打开画板右侧组件库时缩略图立刻可见，滚动不再出现"空图标→等一会才出图"。
2. **白盒审计**：按功能模块逐条读调用链，找出多余操作、重复 IPC/解析、重复渲染、以及"局部变更放大成整片重渲染"的位置，逐条修复并留证据。
3. **验证**：静态门禁 + 真机 e2e 回归；性能类结论必须带实测读数，不接受"看起来更快"。

## 审计方法

- 每个模块沿「组件 props → hook → api 层 → Rust 命令 → SQL」读完，记录：
  - 每次交互真正发生的 IPC 次数与数据量；
  - 哪些 state 变化会重渲染哪些子树，memo 边界是否被新引用击穿；
  - 是否有重复计算/重复拉取/无缓存。
- 结论落 `完成进度.md` 的审计表，修复项附 `file:line` 与验证方式。

## 范围

画板（组件库、画布、保存、导出）、文档编辑器、文件树/侧栏、画布/导图、Rust 命令层。

## 不做

- 不引入新依赖。
- 不改业务语义（插入、保存、拖拽的行为不变）。
- 不做与实测无关的"顺手优化"。

## 验收标准

- `npm run typecheck` / `biome check`（本任务文件）/ `node test/smoke/run.mjs` 全绿。
- 真机 e2e：`20-tree`（拖拽/重命名/删除）、`40-board`（组件插入/导出）、`26c`（导图极限）通过。
- 组件库缩略图有 `perf.library` 日志读数，修复前后可对比。
