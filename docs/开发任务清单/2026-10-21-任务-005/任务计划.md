# 任务计划 · 本地工作区与文件树（2026-10-21-任务-005）

- 关联需求：`docs/需求文档/2026-10-21-需求文档-本地工作区与文件树.md`
- 目标：把工作区、知识库、文件树、记忆配置从 mock 迁移为 Rust + SQLite 持久化，并接入现有 UI。
- 技术前提：Tauri 2、React 19、rusqlite 0.40（bundled）、uuid 1.28（v7）、tauri-plugin-dialog 2.8。

## 范围

1. 全局工作区目录（`STARRIS_HOME`，默认 `~/.starris/rust`）与 `db/starris.db`、`logs/starris.log`。
2. 工作区生命周期：创建、打开、列表、改名、删除（可选删目录）、统一 `switch_workspace` 入口、启动恢复。
3. 工作区库迁移与 `knowledge_base` CRUD。
4. `node` 文件树：CRUD、任意层级、路径/层级/排序维护、递归删除、拖拽移动。
5. 统一记忆 KV API；主题与当前工作区持久化。
6. 前端 API 层、store、首次引导、管理弹窗、嵌套树与拖拽。
7. 测试与文档：Rust 集成测试、前端三件套、应用冒烟、架构/数据库/更新日志。

## 实现方案（分层）

- `src-tauri/src/errors`：`AppError` + 序列化；所有命令返回 `Result<T, AppError>`。
- `src-tauri/src/logging`：启动清空本轮日志，`log_info/log_error` 单文件追加。
- `src-tauri/src/db/paths`：解析全局目录与工作区固定相对路径；路径安全校验。
- `src-tauri/src/db/global`：全局库连接与迁移（workspaces/settings）。
- `src-tauri/src/db/workspace`：工作区库连接与迁移（knowledge_base/node）。
- `src-tauri/src/repositories`：全局工作区/设置、知识库、节点 SQL。
- `src-tauri/src/services`：工作区生命周期与统一切换、知识库用例、节点树规则/事务。
- `src-tauri/src/commands`：IPC 适配与参数校验。
- `src-tauri/src/state`：`AppState { global: Mutex<Connection>, workspace: Mutex<Option<WorkspaceSession>> }`；禁止嵌套持锁。
- 前端：`types/notebook.ts` 扩展；`api/{workspace,knowledgeBase,node,memory}.ts`；`useWorkspaceStore` 改异步；新增 `WorkspaceOnboarding`、`NodeDialog`、`FileTree` 等组件。

## 风险

- 多进程写同一工作区：SQLite WAL + busy_timeout 缓解，不承诺并发安全。
- 删除目录不可恢复：二次确认 + 路径安全校验。
- macOS 黑盒自动化受限：以应用冒烟、日志与截图记录；不能执行则明确标注未执行。
- 现有 UI 的 mock 结构是单层文件夹，改造面覆盖 Sidebar、store、类型、弹窗，需同步回归。
