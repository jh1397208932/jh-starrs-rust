## 1. 测试方式与真实性

本轮不是浏览器 mock：测试运行器启动真实 Tauri 开发窗口，使用 macOS Accessibility（AX）查找控件、用 CGEvent 发出点击/拖拽/键盘/滚动，用系统保存/打开面板选择路径，通过真实 SQLite 与磁盘文件做断言。

- 测试环境：macOS Darwin 24.6.0 / arm64，窗口 1280×800；`STARRIS_HOME=tmp/e2e/<run>/home`
- 测试工作区：`tmp/e2e/<run>/workspace`（项目内 `tmp/`，不进版本库）
- 预设输入：`test/fixtures/files/` 下的 Markdown、Excalidraw、组件库和 1×1 PNG
- 每次运行从零创建全局库/工作区（首次引导通过 UI 完成），避免遗留状态影响；Word 文件由本轮文档导出后再导入，形成闭环。
- 测试结束后自动关闭应用与 Vite；`tmp/e2e/latest` 指向最近一次运行产物。

### 前置条件

1. macOS，已安装 Xcode Command Line Tools（`swiftc`，测试启动时编译 AX 辅助程序）。
2. 终端/Qoder 已获“辅助功能”权限；未授权时运行器会明确报错退出，不会假装通过。
3. 执行前没有其他星屿实例占用窗口/`localhost:1420`；运行器检测到已有实例会拒绝启动。
4. 使用 `pnpm`（当前 pnpm 10.18.0）；不需要新增 npm 依赖。

### 工作区与扩展方式

```text
test/
├── e2e/
│   ├── run.mjs                 # 编排：启动应用、运行用例、报告、清理
│   ├── harness.mjs             # AX 封装、等待、断言、截图、DB/文件核对
│   ├── native/axhelper.swift   # AX/CGEvent 原生辅助程序
│   └── cases/                  # 每个功能域一个用例文件
├── fixtures/files/             # 预置测试输入
└── README.md                   # 框架使用与扩展说明
```

新增功能测试只需：

1. 在 `test/e2e/cases/` 新建 `NN-<area>.mjs`，导出 `{ id, title, area, steps, complexity, run }`；
2. 在 `cases/index.mjs` 登记；
3. 用 `ctx.menu / press / fill / key / click / drag / nativePath / waitForDb / waitForPath / screenshot` 编写操作；
4. 需要新输入文件时放入 `test/fixtures/files/`，用 `ctx.fixture("name")` 取绝对路径。

用例的 `steps` 会直接生成报告中的“步骤 / UI 位置 / 点击 / 弹窗 / 说明”表，`complexity.assessment` 生成合理性分析；实际动作计数由框架自动统计。

## 4. 操作复杂度与合理性结论

### 4.1 好的部分

- 自动保存贯穿文档与画板，用户无需点击保存；测试均通过，且状态胶囊反馈清楚。
- 侧栏「收藏/小记/新建」、画板页头三格式导出、设置主题切换都是一到两步可达。
- 所有不可逆删除（节点、知识库、附件）都有确认或二次确认；知识库/节点删除后 DB 与 UI 一致。
- 同一份导出（全部导出）把画板三格式、附件、manifest 放在一个目录，避免用户逐项收集。

### 4.2 主要发现（按优先级）

1. **[medium] WKWebView 保留快捷键吞掉 mock 动作**：`⌘⇧F`（全局搜索）、`⌘K`（快速跳转）、`⌘P`（放映画板）在真机上按下去没有出现源码里的“本阶段未实现”toast；点击顶栏搜索胶囊也未看到反馈。建议改用非保留组合（如 `⌘⇧K`）或在 Tauri 菜单层注册，并让点击/快捷键共用同一入口。证据：运行报告快捷键用例 `发现与建议`。
2. **[medium] mock 入口无“即将推出”标记**：更多菜单的「模板库」「备份与恢复」是正常菜单项，点击只弹 toast；表格/流程图打开是占位页。建议在列表/菜单项加“即将推出”徽标，或在未实现期间收起入口，降低预期落差。
3. **[medium] 两个“更多”造成认知/自动化歧义**：画板里同时存在侧栏「更多 ⌘J」与 Excalidraw 工具条「更多工具」；测试首次打开设置时误触了后者。可见文案虽有区别，但语义接近。建议把侧栏入口改名为「应用菜单」或让 Excalidraw 按钮明确「更多工具」，并在 aria-label 上保持唯一。
4. **[low] 高频新建节点偏重**：打开弹窗 → 选类型 → 输入 → 创建，4 个动作；文档有 ⌘N 与「新建」，画板/文件夹只能走弹窗。建议增加“新建画板/文件夹”快捷入口或记住上次类型。
5. **[low] 文档导出重复四轮**：每次导出都要重新打开导出弹窗并确认系统面板；建议记住上次格式或提供“导出全部格式”。
6. **[low] 组件库列表无搜索/分组**：8 个预设在 640px 弹窗中已接近一屏，导入库排在其后；建议按预设/导入分组或提供搜索。
7. **[low] 附件上传与使用分处两页面**：上传在设置→存储，插入在画板页头；高频插图时可把上传入口放进选择器。
8. **[low] 画布缩放比例未暴露给 AX**：可访问性用户只能看到“重置缩放”按钮，无法读当前百分比；建议为缩放显示补 aria-label/aria-valuenow。
9. **[low] 单选卡片需指针操作**：导出格式/设置标签是 Radix radio，AXPress 不改变选择，自动化必须点击其区域；对辅助技术是潜在问题，建议确认键盘/AT 路径（Space/Arrow）可用并补测试。
