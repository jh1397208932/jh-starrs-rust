### FT-BOARD-07 自动保存写入次数（性能）

- 目的：打开画板不应写库；一次场景变更只写一次，避免重复 IPC 与 SQLite 写。
- 步骤：重启应用（日志自动清空）→ 打开 `Board Test` → 读取日志；通过页头「组件库」插入「星屿标签」→ 再读日志与数据库。
- 期望：打开后 0 条保存；插入后仅 1 条保存，元素数与版本各增加一次。
- 实际：打开后 0 条；插入后 1 条 `version=23 elements=7 bytes=4276`；数据库 `element_count=7, scene_version=23`。
- 状态：通过（修复后）。
- 证据：`.../画板功能适配-001/图片/board-single-save.png`；日志见第 4 节。

### 修复前对照

修复前打开画板即产生一次保存，且每次变更连续保存两次（`version 17→18`、`19→20`，两次元素字节完全相同）。根因与修复：

1. 加载后没有把 Excalidraw 挂载触发的首次 `onChange` 当作基线，导致打开即写库；
2. 保存进行中 Excalidraw 回传相同场景时，仍与“上次已保存”比较并再次标脏，导致回声双写。

处理：新增 `baselinePendingRef`（首次 onChange 只建基线）与 `inFlightSnapshotRef`（忽略保存期间相同快照的回声），见 `src/features/board/hooks/useBoardPersistence.ts`。

## 3. 本轮发现与修复

| 问题 | 根因 | 处理 |
|---|---|---|
| JSON 导出卡片与按钮是本库默认的亮绿色 | Excalidraw 的 `Card` 把 lime 写在行内 CSS 变量；且弹窗通过 portal 挂到 `document.body`，不带 `.board-excalidraw` | `board.css` 将令牌映射扩展到 `.excalidraw.excalidraw-modal-container`，并直接覆盖卡片图标/按钮属性 |
| 弹窗边框、圆角未使用 Starris 令牌 | 同上（portal 作用域） | `.Modal` 规则同时匹配 portal 容器 |
| 开发态 HMR 后 WebView 曾整窗黑屏 | `tauri dev` 的开发态 WebView 刷新副作用；DOM 已加载但未绘制 | 完全重启 `npm run tauri dev` 后恢复；产品构建不受影响，仅记录为开发环境现象 |
| 打开画板即写库、单次变更双写 | 首次 onChange 未只建基线；保存期间回声 onChange 与旧基线比较后再次标脏 | `baselinePendingRef` + `inFlightSnapshotRef`；修复后打开 0 次写库、一次变更 1 次写库 |

## 5. 已知限制 / 未覆盖项

- 本轮真机未重新执行图片/PDF 粘贴与全局附件插入；该路径由浏览器 mock 与 Rust 对象引用测试覆盖，尚缺一次真机黑盒复测。
- 文件卡片双击打开、对象被删除后的缺失提示 UI 仍未实现（与任务记录一致）。
- 列表第 8 个预设需要滚动查看，属正常滚动列表，无缺失。
- 画板组件选择器是扁平列表，未按库名分组；导入库条目沿用文件内名称（如「组件 4」），库很多时定位成本较高。
- 未做 100/1000/5000 图元的端到端耗时基准；本轮以写库次数（打开 0 次、单次变更 1 次）、单行场景写入与不重复上传对象的机制证据验证性能路径，未给出毫秒级结论。
- 导入库名称取自文件名；当前 UI 未提供自定义名称/作者/许可的二次编辑。
- 深色主题下的属性面板（选中图元后左侧面板）未单独截图；工具条、主菜单、导出弹窗与画布已覆盖。
