- 证据：`docs/设计/2026-10-25-画板导出导入-001/图片/board-export.png`、`board-export-menu.png`。

### FT-EXP-05 全部导出携带图片附件

- 步骤：设置 → 存储 → 选择文件上传 `/tmp/board-export-test/Board Test.png`（22.3 KB）→ 关闭设置 → 打开 `Board Test (2)` →「插入附件」选择该图片 → 自动保存 → 「更多 → 全部导出」到 `/tmp/kb-export-attach`；优化后再导出到 `/tmp/kb-export-final` 复核。
- 期望：画板目录含三格式、`attach/Board Test.png` 与 `attachments.json`；PNG/SVG 中出现附件卡片。
- 实际（最终代码）：
  ```text

  Board Test (2)/Board Test (2).png        35195 B  (749 x 797 RGBA)
  Board Test (2)/Board Test (2).svg         7325 B
  Board Test (2)/attach/Board Test.png     22819 B
  Board Test (2)/attachments.json            350 B
  ```
  `attachments.json` 记录 objectId、MIME `image/png`、size 22819 与 `attach/Board Test.png`；导出 PNG 目视包含附件卡片（文件名/大小/IMG 图标）。画板元素数 12、版本 2；最终 `.excalidraw` 的 `files` 为空（文件卡片由 sidecar 恢复），`sidecar=1` 且 `attach` 存在。
- 状态：通过。
- 说明：文件卡片由 sidecar 恢复；`.excalidraw` 的 `files` 映射只内嵌原生 `image` 图元（本轮后段优化），文件卡片不重复内嵌。

## 5. 已知限制

- 画板单文件 `.excalidraw` 无法携带文件卡片附件；导出时提示改用「全部导出」。
- 全部导出的 `manifest.json` 在 `boards` 中给出 PNG/SVG 路径与格式，但 `files` 数组不含前端后写入的 PNG/SVG；桌面端 toast 显示实际写入文件数。
- 仍未做「带原生 image 图元」的真机 UI 再导入回环；原生图片 files 映射由集成测试覆盖。
- 文件卡片在本轮后段改为不重复内嵌到 `.excalidraw` 的 `files`；真机导出截图产生于优化前，优化后由最终重跑的全库导出（files=0、sidecar=1、attach 存在）覆盖。
- 画板 PNG/SVG 统一白底、浅色导出，不生成深色版本。
- 导入只接受 base64 dataURL 内嵌图片；外链或非 base64 dataURL 会保留原引用并警告。
- 导入的 `.excalidraw` 标题取文件名；重名自动加序号。

## 6. 结论

7 个真机用例全部通过；三格式单板导出、全部导出画板多格式目录（含图片附件）、`.excalidraw` 导入并打开、带 sidecar 画板包导入并恢复附件均可用。原生图片 files 映射另有服务层测试覆盖；无阻塞缺陷。
