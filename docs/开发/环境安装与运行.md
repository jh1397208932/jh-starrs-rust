# 环境安装与运行（Windows / macOS）

> 更新日期：2026-10-31。本文记录从零准备开发环境、运行、打包与常见阻塞的实际步骤；命令均在仓库根目录执行。

## 1. 版本要求

| 组件 | Windows | macOS | 说明 |
|---|---|---|---|
| Node.js | 22 LTS 及以上 | 22 LTS 及以上 | 开发机以 v24.14.0 验证 |
| npm | 随 Node 安装 | 随 Node 安装 | 本仓库当前使用 npm（见 §6 的 pnpm 说明） |
| Rust | stable，edition 2024（建议 1.85+） | 同左 | `rustc --version` 确认 |
| 原生工具链 | Visual Studio Build Tools 或 VS（C++ 桌面开发）+ Windows SDK | Xcode Command Line Tools | Windows 需 MSVC 链接器 |
| WebView2 | Windows 10/11 通常内置 | 系统 WebKit | 缺失时安装 Evergreen Runtime |
| 构建产物 | NSIS（自动下载） | Xcode 工具链 | 首次打包会联网下载 NSIS |

## 2. Windows 环境准备

### 2.1 检查工具链

```powershell
node --version
npm --version
rustc --version
cargo --version
```

Rust 需要 `x86_64-pc-windows-msvc` 工具链：

```powershell
rustup show
# 如默认不是 MSVC：
rustup default stable-x86_64-pc-windows-msvc
```

### 2.2 安装 C++ 生成工具与 Windows SDK

在 Visual Studio Installer 中勾选：

- 「使用 C++ 的桌面开发」（Desktop development with C++）
- MSVC v143 / v14.x x64 生成工具
- Windows 10 SDK 或 Windows 11 SDK

验证链接器存在（路径随安装位置变化）：

```powershell
where.exe cl.exe
where.exe link.exe
```

也可以在「x64 Native Tools Command Prompt for VS」里执行 `cargo check`，确保 `link.exe` 来自 MSVC，而不是 Git 自带的 `/usr/bin/link.exe`。

### 2.3 检查 WebView2

Windows 10/11 一般已内置。若启动白屏或提示缺少 WebView2：

- 从微软官网安装 Evergreen WebView2 Runtime；
- 或在 `src-tauri/tauri.windows.conf.json` 使用 `downloadBootstrapper`（默认已配置，安装包运行时会自动补齐）。

## 3. macOS 环境准备

```bash
xcode-select --install
rustup default stable
rustup target add aarch64-apple-darwin x86_64-apple-darwin   # 通用包需要
```

## 4. 安装依赖与开发运行

```bash
npm install
npm run tauri dev
```

- `npm run tauri dev` 会同时启动 Vite 与 Tauri 窗口，使用真实 IPC 与 SQLite。
- 只跑 `npm run dev` 时没有 Tauri runtime，窗口控制与 IPC 会降级，仅适合调样式。
- 首次编译会在 `src-tauri/target/` 生成缓存；Windows 约 2–4 GB，后续增量编译很快。

### 4.1 使用独立数据目录

避免开发过程触碰真实工作区：

```powershell
# PowerShell
$env:STARRIS_HOME = "$env:TEMP\starris-dev"
npm run tauri dev
```

```bash
# macOS / Git Bash
STARRIS_HOME=/tmp/starris-dev npm run tauri dev
```

`STARRIS_HOME` 同时决定全局库与日志目录。

## 5. 构建安装包

```bash
# Windows：NSIS .exe
npm run package:win

# macOS：当前架构 DMG
npm run package:dmg

# macOS：通用 DMG
npm run package:dmg:universal
```

产物：

- Windows：`src-tauri/target/release/bundle/nsis/Starris_<version>_x64-setup.exe`
- macOS：`src-tauri/target/release/bundle/dmg/*.dmg`

首次 Windows 打包会下载 NSIS 工具到 Tauri 缓存目录；若公司网络拦截，需配置代理或预置 NSIS。

## 6. 依赖管理器说明

仓库历史与 CI 以 `pnpm` 为目标，但当前开发环境（2026-10-20 起）的文件代理会拦截 pnpm 安装所需的 symlink 与临时目录操作，因此暂时使用 npm：

- `package-lock.json` 与 `node_modules` 由 npm 维护；
- `tauri.conf.json` 的 `beforeDevCommand` / `beforeBuildCommand` 使用 `npm run`；
- 在不受限制的开发机上迁移回 pnpm 时，执行 `pnpm install` 生成 `pnpm-lock.yaml`，并同步修改 `tauri.conf.json`、`AGENTS.md` 与本文。

## 7. 质量门禁

```bash
npm run check           # Biome：格式 + lint（lineEnding: auto）
npm run typecheck       # tsc --noEmit
npm run build           # typecheck + vite build + 许可证门禁
npm run test:backend    # cargo test（需要先 cargo fetch）
npm run check:licenses  # 单独跑许可证扫描
```

Windows 注意事项：

- Biome 已配置 `lineEnding: "auto"`：Windows 使用 CRLF、macOS/Linux 使用 LF，避免 Git 自动换行造成全仓格式失败。
- `check:licenses` 内部执行 `cargo metadata --offline`。首次克隆后先跑一次 `cargo fetch --manifest-path src-tauri/Cargo.toml`，否则会因缺少其他平台依赖的 crate 源码而失败。
- 路径包含空格时，命令中的路径一律加引号。
- 长路径：程序内部会还原 Windows `\\?\` 前缀后再展示/持久化；用户选择的工作区路径建议不超过 240 字符。

## 8. 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| `link.exe not found` 或链接失败 | 未安装 MSVC 生成工具，或 PATH 命中了 Git 的 `link.exe` | 安装「使用 C++ 的桌面开发」，用 VS 开发者命令行执行 |
| `cargo metadata --offline` 失败 | 未缓存全部平台的 crate | 执行 `cargo fetch --manifest-path src-tauri/Cargo.toml` |
| 启动白屏 / 无 WebView2 | 系统缺少 WebView2 Runtime | 安装 Evergreen Runtime，或使用带 bootstrapper 的安装包 |
| 窗口没有边框、无法拖动 | 使用了浏览器 dev 而非 Tauri | 用 `npm run tauri dev`；确认 `data-tauri-drag-region` 区域可拖动 |
| Windows 上关闭按钮无响应 | 前端未加载完成 / 浏览器 dev | 查看控制台与 `logs/starris.log`；Tauri 窗口下重试 |
| 中文显示为宋体/锯齿 | 系统缺少设计字体 | 字体栈已回退到 Segoe UI / Microsoft YaHei；可在系统安装设计字体 |
| 打包时 NSIS 下载失败 | 网络/代理拦截 | 配置代理，或手动放置 NSIS 到 Tauri 缓存目录 |
| 删除工作区失败 | 目录被占用或无权限 | 关闭占用程序；查看返回的 `warning` 并手动清理 |
| 工作区路径显示 `\\?\C:\...` | 旧版本持久化了 verbatim 前缀 | 新版本已在 `db/paths.rs` 还原；旧记录重新选择一次即可 |
