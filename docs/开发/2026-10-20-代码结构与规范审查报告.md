## 三、问题清单

### 🔴 Blocker（接入真实数据前必须解决）

**B1. 实际目录结构与 AGENTS.md 目标结构完全脱节**

AGENTS.md §2 规划了 `features/<功能>/{components,hooks,api,types}` + `api/` + `types/` + `hooks/`，实际代码全部按**文件类型**平铺在 `components/` 下：

```
现状                              AGENTS.md 目标
components/layout/   (4 文件)      features/workspace/  工作空间/知识库域
components/dialogs/  (9 文件)      features/editor/     文档编辑域
components/editor/   (2 文件)      features/board/      画板域
components/board/    (1 文件)      components/ui/       shadcn 原子
components/ui/       (14 文件)     components/common/   跨功能复用组件
components/common/   (6 文件)      api/  types/  hooks/ 公共基础设施
```

没有 api 层、没有 features、没有 hooks 目录。当前 `App.tsx` 直接 `import { MOCK_KBS } from "./mocks/workspace"`，未来替换为 IPC 时需要逐文件改 import——这正是 api 层要隔离的变化点。

**B2. 业务类型寄生在 mocks 里**

`Workspace`、`KnowledgeBase`、`NodeItem`、`TabItem`、`TreeEntry` 全部定义在 `src/mocks/workspace.ts`，`App.tsx`、`Sidebar` 等从 mocks 导入类型。类型是**领域契约**（未来 Rust 命令的返回结构），mock 只是临时数据源，二者生命周期不同。接 IPC 时若类型跟着 mock 走，会出现"为了拿类型被迫 import mock 数据"的倒挂依赖。

**B3. `App.tsx` 565 行上帝组件**

单文件承担 7 类职责：工作空间/知识库/文档树三份领域状态、标签页状态、Dialog 状态机、Toast 系统、全局快捷键、收藏业务逻辑、整页布局渲染。违反 AGENTS.md §4"避免过大的组件"。每次新增功能都在加重它，且快捷键/toast/领域状态无法被其他组件复用。

### 🟡 Suggestion（应修复）

**S1. `dialogs/` 目录名不符实**

`MoreMenu.tsx` 是 DropdownMenu（radix dropdown），`WorkspaceSwitchPopover.tsx` 是 Popover，均非 Dialog。目录名承诺与内容不符会误导检索（9 个文件中仅 6 个真 dialog）。

**S2. 无路径别名，跨目录导入全靠相对路径**

`tsconfig.json` 无 `paths`，`vite.config.ts` 无 `resolve.alias`，45 个文件中 20+ 处 `from "../.."` 式导入。目录一重组（B1 的迁移必然发生），所有相对路径全部断裂。别名（`@/`）是迁移的前置保险。

**S3. 逻辑未抽 Hook**

快捷键分发（App.tsx L252-296，`keyHandler.current` ref 持闭包模式）、Toast 定时清理（L96-109）都是可复用的通用逻辑，内联在组件里导致 App.tsx 膨胀且不可测试。

**S4. 仓库根目录垃圾堆积**

存在 6 个构建/安装残留目录，且 `.gitignore` 只写了精确名 `dist`、`node_modules`，变体目录**未被忽略**：

```
dist-old-20261020/  dist-old-2/  dist-tmp/  dist-cur-tmp/
node_modules-broken/  node_modules-pnpm-broken/
```

**S5. package.json scripts 不完整**

缺独立 `typecheck` 脚本（现在靠 `build` 里的 `tsc &&` 顺带执行），缺 `lint:fix`，CI/编辑器难以单独跑类型检查。

### 💭 Nit（酌情处理）

**N1.** `components/ui/logo.tsx` 是品牌业务组件，不是 shadcn 通用原子，放 `ui/` 层级不符（建议迁 `common/`）。
**N2.** `InfoPanel` 的 `related` 直接传 `MOCK_RELATED` 常量，接 IPC 时该 prop 应改为由数据层注入（记入迁移清单即可）。
**N3.** `App.tsx` L298 有一段空注释段"窗口宽度响应"下无对应实现，属残留注释。

## 四、迁移路线图（mock 阶段内完成，避免接入 IPC 后返工）

> 遵循 AGENTS.md §2"不得一次性大规模搬动稳定代码"，按以下顺序分四步走，每步独立可验证（`tsc` + `biome` + 手工冒烟）。

**第 1 步 · 地基（半小时级，无行为变化）**
1. 配置 `@/` 路径别名（`tsconfig.json` paths + `vite.config.ts` alias），**全量替换**现有相对导入。
2. `.gitignore` 追加 `dist-*/`、`node_modules-*/`、`*-tmp/`；删除 6 个残留目录（删除前向老板确认）。
3. `package.json` 补 `typecheck`、`lint:fix` 脚本。

**第 2 步 · 类型与数据解耦**
1. 新建 `src/types/notebook.ts`，迁入 `Workspace/KnowledgeBase/NodeItem/FolderEntry/TreeEntry/TabItem/NodeKind`。
2. `mocks/workspace.ts` 只留常量数据并从 types 导入类型；全仓库 import 改指向 `@/types`。

**第 3 步 · 抽取 Hook 与基础设施**
1. `useKeyboardShortcuts(handlers)` → `src/hooks/`；`useToast()` → `src/hooks/`（Toast UI 同步抽为 `common/AppToast.tsx`）。
2. 建 `src/api/client.ts`（invoke 包装 + 统一错误转换，mock 阶段先留 TODO 空壳）与 `src/api/index.ts` barrel——**给未来 IPC 预留唯一出入口**。

**第 4 步 · features 化与 App.tsx 瘦身**
1. 按域拆 `features/workspace/`（Sidebar、WorkspaceSwitchPopover、WsManageDialog、CreateWorkspaceWizard + workspace 状态）、`features/editor/`（DocEditor、SlashMenu + 文档状态）、`features/board/`。
2. Dialog 归位：真 dialog 留 `dialogs/` 或并入所属 feature；`MoreMenu` → `common/`，`WorkspaceSwitchPopover` → `features/workspace/`。
3. `App.tsx` 目标 ≤200 行：只做 Provider 组装 + 页面骨架 + dialog 挂载。

## 五、结论

目录的**横向分类意识**是好的（ui/common/layout 分层、动效令牌收敛），缺的是**纵向领域分层**（api/types/hooks/features）和几处名实相符的纪律。按上述四步迁移后，项目结构与 AGENTS.md 对齐，接 Rust IPC 时只改 `src/api/` 一层。
