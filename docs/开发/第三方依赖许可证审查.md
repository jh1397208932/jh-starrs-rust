# 第三方依赖许可证审查（2026-10-22）

> 结论：**Tiptap 3.32.0 引入的全部包均为 MIT**；全仓扫描未发现 GPL/AGPL/SSPL/BUSL、非商业、UNLICENSED、专有或商业授权依赖。存在 9 项 MPL-2.0 弱 copyleft（开源、无需开源本项目）与字体分发注意事项，已加构建门禁与产物字体白名单。新增 `xxhash-rust` 为 **BSL-1.0（Boost Software License，宽松可商用）**，与 Business Source License（BUSL）无关。审查日期 2026-10-22。

## 1. 审查范围与方法

- 前端：遍历 `node_modules` 全部已安装包（含嵌套/scope 包）读取 `package.json` 的 `license`/`licenses`；缺失字段时读取包内 `LICENSE*` 文件推断 SPDX。
- Rust：`cargo metadata --format-version 1 --offline` 读取全部第三方 crate 的 `license`/`license_file`。
- 字体：解析 `@excalidraw/excalidraw` 随包 WOFF2 的 `name` 表（nameID 0/13/14）读取嵌入版权与许可；同时核对上游官方许可证。
- 构建产物：检查 `dist/` 中实际会随安装包分发的字体文件。
- 可复跑命令：`npm run check:licenses`（`npm run build` 会在构建后自动执行）。

判定口径：
- 任一 OR 分支为宽松许可（MIT / Apache-2.0 / BSD / ISC / Zlib / 0BSD / BSL-1.0 / Unlicense / CC0 / OFL-1.1 等）→ 通过；
- 仅弱 copyleft（MPL-2.0 / EPL / LGPL / CDDL）→ 警告：开源，且仅在修改对应文件时需要回馈该文件源码，不要求本项目开源；
- 强 copyleft（GPL/AGPL/SSPL/BUSL）、非商业、UNLICENSED、专有、许可不明 → 失败。

## 5. 字体审查（随包分发）

生产构建实际产出的字体只有：`Assistant-Bold/Medium/Regular/SemiBold.woff2`（OFL-1.1，嵌入 name 表许可明确）。

`node_modules/@excalidraw/excalidraw/dist/prod/fonts` 还包含其他字体，但不会被打进 `dist`；为防未来升级自动打包，已加两道防线：

1. `vite.config.ts` 的 `fontLicenseGuard`：构建阶段删除未列入白名单的字体资产。
2. `scripts/check-licenses.mjs` 的 `dist` 检查：产物中出现白名单外字体直接失败。

| 字体 | 随包元数据/上游许可 | 处理 |
|---|---|---|
| Assistant | OFL-1.1（嵌入 name 表明确） | 允许；当前唯一随包字体 |
| Virgil | OFL-1.1（官方仓库） | 允许 |
| Nunito / Lilita One | OFL-1.1（嵌入 licenseURL） | 允许 |
| Cascadia Code | OFL-1.1（微软官方 LICENSE） | 允许 |
| Comic Shanns | MIT（嵌入版权行） | 允许 |
| Xiaolai（小赖字体） | OFL-1.1（上游发布说明） | 允许 |
| Liberation Sans 1.05 | 嵌入元数据指向 Ascender 旧许可；上游已改为 OFL | **禁止发布**（白名单外，构建剔除） |
| Excalifont | npm 包内无独立许可文件/嵌入许可声明 | **暂禁止发布**（白名单外；待上游明确许可后再评估） |

说明：OFL-1.1 是 OSI 认可的开源字体许可，允许商用、嵌入与随软件分发；要求保留版权与许可声明、不得单独售卖字体、修改版不得使用保留名称。当前项目不修改字体文件。

## 6. 门禁与后续

- `npm run check:licenses`：全量许可证扫描（node_modules + Cargo + dist 字体）。
- `npm run build`：`tsc --noEmit && vite build && node scripts/check-licenses.mjs`，许可证失败会让构建失败。
- 门禁修正：`PERMISSIVE` 显式加入 `/^BSL-1\.0$/i`，并加注释区分 Boost 与 BUSL；这不是放宽强 copyleft 规则，而是修正对宽松许可的漏判。`STRONG` 中仍保留 `/BUSL/i`。
- 发布前额外确认：若未来需要在画板中使用 Excalifont/Liberation 的手写或 Helvetica 外观，必须先把对应字体替换为许可明确的开源字体（OFL）再放开白名单。
- 自有包 `starris-rust` 未声明 `license` 字段（工作区成员，非第三方依赖）；若要对外发布，建议单独确定并声明项目许可证。
