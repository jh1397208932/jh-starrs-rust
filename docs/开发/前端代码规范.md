# 前端代码规范（starris-rust）

> 生效日期：2026-10-20 ｜ 适用范围：`src/` 全部 TypeScript/React 代码
> 本文件是 AGENTS.md §3（前端工程规范）的展开细则：提供正反例、命名表、迁移索引；AGENTS.md §3 为强制条款速查，两者冲突时以 AGENTS.md 为准。
> 强制级别标记：【必须】违反即打回；【应当】例外需在 PR 说明理由；【可以】团队惯例参考。

## 1. 目录结构规范

### 1.1 目录结构（2026-10-21 已按本规范落地，与 AGENTS.md §2 对齐）

```text
src/
├── main.tsx                    # 入口：挂载 App，保持精简
├── App.tsx                     # 【必须】≤250 行：Provider 组装 + 页面骨架 + 全局弹窗挂载，禁止业务逻辑
├── features/                   # 【必须】按业务域分包，一个域一个文件夹
│   ├── workspace/              # 工作空间/知识库域（侧栏/窗口栏/工具栏/信息面板 + ws·kb 管理 + 收藏）
│   │   ├── components/         # 仅本域使用的组件
│   │   ├── hooks/              # useWorkspaceStore / useTabSession / useWorkspaceShortcuts
│   │   ├── api/                # 本域的 IPC 调用封装（命令落地时建）
│   │   └── utils/              # 本域专用工具（tree.ts：flattenTree/findNode）
│   ├── editor/                 # 文档编辑域（DocEditor、SlashMenu、ShareExportDialog）
│   ├── board/                  # 画板域（BoardView）
│   └── settings/               # 设置域（SettingsDialog：外观/快捷键/存储/云/关于）
├── components/
│   ├── ui/                     # 【必须】仅 shadcn/ui 生成物，保留生成约定，不做业务改造
│   └── common/                 # 跨域通用展示组件（BrandLogo、NodeKindIcon、TrafficLightSlot、AppToast）
│       └── motion/             # 动效组件子目录
├── hooks/                      # 【必须】全局通用 hooks（useKeyboardShortcuts、useToast）
├── api/                        # IPC 唯一出入口：client.ts（invokeCommand + ApiError，详见 §3）
├── types/                      # 【必须】跨 feature 共享的领域类型（notebook.ts）
├── lib/                        # 第三方库封装与基础设施（theme、motion 令牌、cn、window）
├── mocks/                      # 仅 mock 数据常量，【禁止】定义业务类型
└── styles/                     # tokens.css / app.css，样式令牌唯一来源
```

### 1.2 归位规则（判断一个文件放哪）

1. 只被一个 feature 用 → `features/<域>/`；被 ≥2 个 feature 用 → `components/common/`；shadcn 生成 → `components/ui/`。
2. 调 Rust 命令（现在或将来）→ 一律经 `api/` 层，组件禁止直接 `import { invoke }`。
3. 描述领域概念的 interface/type → `types/`（跨域）或 `features/<域>/types.ts`（域内）；【禁止】放在 mocks、组件文件或 App.tsx 里。
4. 【禁止】建立 `misc/`、`utils2/`、`temp/`、`helper/` 等堆放目录；`common/` 只收确实跨域复用的能力。

### 1.3 仓库卫生

- `.gitignore` 必须用通配：`dist-*/`、`node_modules-*/`、`*-tmp/`；构建/安装残留目录（dist-old-*、node_modules-broken 等）不入库、不留在工作区。
- 【禁止】在根目录堆放 tmp 备份目录；需要备份交给 git。

## 2. 命名规范

| 对象 | 规则 | 示例 |
|---|---|---|
| 组件文件/目录 | PascalCase，一文件一组件 | `InfoPanel.tsx` |
| 非组件 ts 文件 | camelCase | `useToast.ts`、`notebook.ts` |
| Hooks | `use` 前缀 + PascalCase | `useWorkspaceStore` |
| 组件 Props 接口 | `XxxProps`，与组件同名 | `InfoPanelProps` |
| 类型/接口 | PascalCase，领域名词 | `TreeEntry`、`NodeKind` |
| 类型联合字面量 | 小写字符串字面量 | `"doc" \| "board" \| "table"` |
| 常量 | SCREAMING_SNAKE_CASE | `MOCK_KBS`、`EASE_STANDARD` |
| 变量/函数 | 语义化 camelCase，见名知意 | `activeKbName`；【禁止】`a`/`tmp`/`data1`/`flag2` |
| 布尔值 | `is/has/can/should` 前缀 | `sidebarOpen`、`infoVisible` |
| 回调 Props | `on` + 动词（或 `onXxxChange`） | `onOpenNode`、`onOpenChange` |
| 事件处理器 | `handle` + 动词（组件内部） | `handleSubmit` |
| 目录名 | 功能名词，小写或 PascalCase 与现状一致 | `features/editor/` |

## 3. API 层规范（IPC 唯一出入口）

### 3.1 分层

```text
组件/hooks →  api/<域>.ts  →  api/client.ts  →  Tauri invoke  →  Rust commands/
```

- `api/client.ts`【必须】：统一封装 `invoke`，集中处理错误转换（Rust 错误 → 可展示消息）、超时与日志；组件【禁止】直接 import `@tauri-apps/api`。
- `api/<域>.ts`【必须】按业务域细分：`workspace.ts`、`kb.ts`、`document.ts`、`board.ts`…一个 Rust 命令域一个文件，禁止全堆在 `index.ts`。
- `api/index.ts` 仅做 barrel 再导出，【禁止】写实现。
- mock 阶段：api 函数返回 mock 数据并在函数头注明 `// TODO(IPC): 替换为 invoke("<命令名>")`；切换数据源时【必须】只改 `api/` 层，组件零改动。

### 3.2 函数约定

```ts
/**
 * 获取知识库列表
 * @param workspaceId 工作空间 id，非空
 * @returns 知识库数组，按创建时间升序
 * @example const list = await listKnowledgeBases("ws-1");
 */
export async function listKnowledgeBases(workspaceId: string): Promise<KnowledgeBase[]> {
  // TODO(IPC): 替换为 invoke("list_kbs", { workspaceId })
  return MOCK_KBS.filter((kb) => kb.workspaceId === workspaceId);
}
```

- 【必须】每个导出函数有中文 JSDoc：用途、参数约束、返回含义；命令名与 Rust `commands/` 一一对应。
- 命名动词表：`list/get` 查询、`create` 新建、`update` 修改、`delete` 删除、`switch` 切换；一个函数只调一个 Rust 命令。
- 【必须】返回领域类型（来自 `types/`），【禁止】返回裸 `any` 或未定义结构的 JSON。

## 4. 组件规范

### 4.1 分类与边界

| 层 | 允许内容 | 禁止内容 |
|---|---|---|
| `components/ui/` | shadcn 原子组件原样保留 | 业务文案、领域类型、mock 依赖 |
| `components/common/` | 跨域复用展示组件、动效组件 | 领域状态、api 调用 |
| `features/<域>/components/` | 本域业务组件 | 被其他域 import（需要时先提升 common） |
| `App.tsx` | Provider、骨架、弹窗挂载、顶层状态组装 | 具体业务规则、快捷键实现、长 JSX 段落 |

### 4.2 写法约定

- 【必须】函数组件用 `function` 声明 + 具名导出；Props 用 `interface XxxProps` 并逐字段中文注释。
- 【必须】单一文件 ≤300 行、单组件 ≤200 行；超过即按业务步骤拆子组件或抽 hook。
- 【必须】`App.tsx` ≤250 行（2026-10-21 实测：两列外壳布局 + 17-prop 侧栏 + 4 弹窗挂载的组装层为 238 行，继续硬拆需制造无语义 props 巨物，违反 AGENTS.md §4；核心约束是业务逻辑清零，行数是防膨胀辅助指标）。
- 【应当】状态提升到最小必要范围：领域状态放 feature 顶层（或将来 store），`App.tsx` 只组装不持有细节状态。
- 【必须】mock 未实现交互统一走 `onMockAction(label)` 模式，禁止各组件自造 toast 文案拼法。
- 【应当】组件头注释写职责与关键交互约定（现状已良好，保持）。

### 4.3 弹窗与浮层命名

- 真模态（radix Dialog）→ `XxxDialog`；下拉菜单 → `XxxMenu`；气泡 → `XxxPopover`；向导 → `XxxWizard`。【禁止】文件名与实际浮层类型不符（修复项：MoreMenu、WorkspaceSwitchPopover 归位）。

## 5. 类型规范

- 【必须】领域类型集中在 `types/`（跨域）或 `features/<域>/types.ts`（域内）；`mocks/` 只 import 类型、只导出常量。
- 【必须】TS strict 全开（现状），【禁止】无理由 `any`、`@ts-ignore`、非空断言 `!`；确需例外时行内注释中文原因并缩小范围。
- 【应当】联合类型优于布尔枚举（`kind: "doc" | "board"` 优于 `isDoc + isBoard`）；可空字段显式 `| null` 并注释何时为空。
- id 字段【必须】带域前缀（`ws-`、`kb-`、`node-`、`tab-`），与现状一致，方便排查数据混用。

## 6. Hooks 规范

- 可复用逻辑（快捷键、toast、窗口操作、防抖等）【必须】抽为 hook 放 `hooks/`（全局）或 `features/<域>/hooks/`（域内）；组件内不重复实现同类逻辑。
- 【必须】hook 文件名 = hook 名（`useToast.ts`）；hook 返回值用对象并保持字段稳定，避免调用方解构断裂。
- ref 持闭包（如快捷键 `keyHandler.current` 模式）【必须】在注释里写明"为什么不用 useEffect 依赖"。

## 7. 样式与主题规范

- 【必须】颜色一律用语义令牌（`bg-background`、`text-muted-foreground`、`var(--primary)`），禁止硬编码色值——切肤机制依赖此约束（见 架构说明.md §2.1）。
- 【必须】动效从 `lib/motion.ts` 取预设、CSS 从 `tokens.css` 取变量，两侧同步改动；禁止组件内私定弹簧/缓动字面量。
- 【应当】字号用令牌阶梯（display 30 / h1 24 / h2 18 / body 15 / caption 12.5），排版组合优先用 `CAPTION_CLS`。
- 【应当】圆角 16/12/8、过渡时长 150/300/500ms 与 `--ease` 组合，新增断点先查 UI-SPEC。

## 8. 注释与文档

- 【必须】简体中文注释；类/组件/导出函数/重要变量必须有，写"为什么"而非语法翻译；注释与实现不一致视为 bug。
- 【必须】TODO 格式：`// TODO(阶段标识): 说明 + 完成条件`，如 `// TODO(IPC): 接入 list_kbs 命令，mock 阶段返回常量`。
- 【禁止】残留空注释段、注释掉的死代码、调试 console（`console.debug` 在 mock 阶段允许，接 IPC 前清理）。

## 9. 工具链与质量门禁

- 脚本约定：`pnpm check`（biome 检查）、`pnpm lint:fix`（biome 修复）、`pnpm typecheck`（tsc --noEmit）、`pnpm build`（typecheck + vite build）。
- 提交前【必须】`check` + `typecheck` 双绿；格式交给 biome（2 空格、双引号、分号、110 列），不为格式争论。
- 导入顺序由 biome organizeImports 维护；路径导入统一用 `@/` 别名，禁止 `../..` 跨两层以上（同目录 `./` 允许）。
- 新增依赖【必须】先查官方文档确认版本与用法（AGENTS.md §16），优先复用已有依赖。
