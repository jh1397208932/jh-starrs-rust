# 需求文档 · 全局界面文案精简（2026-10-25）

- 关联任务：`docs/开发任务清单/2026-10-25-任务-003/`
- 范围：桌面应用内所有用户可见文字，以及会通过 toast/表单错误直接展示给用户的后端消息
- 不改：功能行为、页面结构、数据库、IPC 协议、历史测试报告

## 背景

界面中混入了较多实现说明、操作教学和内部术语：例如空态解释存储位置、新建弹窗解释“根级”、更多菜单展示设置分区列表、外观页复述“看到外观就知道”的内容。它们不帮助用户完成当前动作，反而增加阅读负担，也让界面显得像开发原型。

## 目标

1. 所有按钮只表达动作；弹窗标题与少量必要限制表达后果，不解释实现方案。
2. 去掉内部术语和实现细节：根级、节点、图元、对象库、逻辑大小、物理占用、BLAKE3、db/、storage/、object_id、JSON 结构、mock、本阶段等。
3. 空状态只保留“当前状态 + 一个动作”，不写命令用法或存储说明。
4. 未实现能力统一用“即将推出”标注并提示，不再使用“本阶段未实现 / mock”。
5. 错误提示改为用户能理解、能行动的一句话，不暴露 Rust 命令名和内部校验细节。
6. 统一术语：工作区、内容、组件库、位置、名称。

## 文案原则

| 类型 | 写法 |
|---|---|
| 按钮 | 只写动词：新建、创建、导入、导出、上传、移除、重试 |
| 弹窗标题 | 名词或动作：新建、导入、导出、创建工作区、重命名 |
| 弹窗说明 | 只在必要时写限制或后果：目录需为空、将永久删除、等 |
| 空状态 | 只写状态：还没有内容、还没有附件、暂无推荐 |
| 成功提示 | 结果 + 对象：已导入 3 项、已删除「文件名」 |
| 失败提示 | 普通话 + 下一步：文档未保存，请重试、请选择文件夹 |
| 占位能力 | “即将推出”，并在入口或快捷键列表标注 |

## 用户给出的明确示例

| 位置 | 原文案 | 处理 |
|---|---|---|
| 主内容空态 | 输入 / 唤起命令，或把 Markdown 文件拖进这片纸面。所有内容只保存在本地。 | 删除整段；标题改为「开始记录」 |
| 新建弹窗 | 新建到根级 | 改为「新建」 |
| 新建弹窗 | 根级可以创建任意类型的节点 | 删除 |
| 更多菜单 | 通用 · 外观 · 快捷键 · 存储 · 云同步 · 关于 | 删除设置分区串 |
| 设置 · 外观 | 选择明暗模式与主题预设，即时生效。 | 删除 |

## 验收标准

1. 首启引导、空内容页、新建弹窗、更多菜单、外观页不再出现上述示例文案。
2. `src/` 与用户可见 Rust 错误中不再出现“根级 / 新建节点 / 对象库 / 图元 / BLAKE3 / 本阶段未实现 / mock”等内部表达；技术文档与代码注释不受此限。
3. mock 入口（模板库、备份与恢复、搜索/跳转/放映）在入口或快捷键列表有“即将推出”，点击有对应提示。
4. 附件管理不再展示 BLAKE3、pack、死字节、逻辑/物理大小等存储实现统计。
5. 导入、导出、删除、保存等关键流程文案仍能说明对象和结果，不因精简产生歧义。
6. 自动化验证：
   - `pnpm run check`、`pnpm run typecheck`、`pnpm run build` 通过；
   - `cargo test`、`cargo clippy`、`cargo fmt --check` 通过；
   - `pnpm run test` 12/12 通过，报告与截图归档。
7. `UI-SPEC.md` 中涉及本轮文案的条目同步更新。

## 非目标

- 不重写历史任务记录、历史测试报告与设计原型中的旧文案。
- 不改菜单层级、快捷键绑定、数据库或导出文件结构。
- 不为了减少文字而删除必要的结果、限制和风险提示。
