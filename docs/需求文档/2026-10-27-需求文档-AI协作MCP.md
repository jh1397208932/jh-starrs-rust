# 需求文档 · AI 协作 MCP 与写权限系统（任务 2）

- 日期：2026-10-27
- 目标：把星屿暴露成 agent 的记忆后端（文档/画板段落级读写），并提供可配置权限与「待审区」人工复核机制。

## 1. 范围

### 1.1 MCP Server（客户端托管）

- MCP 是客户端能力：桌面端进程内托管本机 HTTP 服务（`POST /mcp`，JSON-RPC 2.0：initialize / tools/list / tools/call），随窗口启停；不存在可单独运行的服务程序。
- 鉴权：设备本地生成的 Bearer 令牌；仅监听 `127.0.0.1`，默认端口 `47821`（`STARRIS_MCP_PORT` 可覆盖）。
- 工具执行复用客户端当前 `AppState`（当前工作区连接、权限与待审区一致）。
- 工具（21 个）：

| 工具 | 风险 | 说明 |
|---|---|---|
| `kb_list` | 无 | 列出知识库与根级节点 |
| `kb_search` | 无 | 标题+正文检索（复用 search_service） |
| `node_tree` | 无 | 指定父节点的子树 |
| `doc_read` | 无 | 段落级读取：`{blockId, type, text, depth, order}` 扁平列表 + 原始版本号 |
| `board_read` | 无 | 画板元素列表（id/type/text/坐标） |
| `mindmap_read` | 无 | 思维导图树 JSON |
| `doc_create` | 低 | 建文档并写初始 Markdown |
| `doc_append_blocks` | 低 | 追加段落（段落级） |
| `doc_update_block` | 中 | 按 blockId 替换段落文本；不存在则拒绝 |
| `doc_insert_after_block` | 中 | 在指定块后插入段落（含子块） |
| `doc_replace_range` | 高 | 按段落区间替换（可能删除内容） |
| `doc_delete_block` | 高 | 删除段落及其子块 |
| `board_add_elements` | 低 | 追加画板元素（rect/text/arrow 等最小集） |
| `board_update_element` | 中 | 按元素 id 更新文本/颜色/位置 |
| `board_delete_elements` | 高 | 批量删除画板元素 |
| `node_rename` | 中 | 重命名节点（走文档作用域权限） |
| `node_move` | 中 | 移动节点到父级指定序号（走文档作用域权限） |
| `node_create_folder` | 低 | 新建文件夹（走文档作用域权限） |
| `node_trash` | 高 | 移入回收站（可恢复，不做永久删除） |
| `inbox_list` / `inbox_get` | 无 | 查询待审项与状态（供 agent 轮询结果） |

- 所有写工具接受 `expectedVersion`（可选，乐观并发）与 `summary`（写入审计与待审列表的动机说明）。
- 每个工具都声明完整的 `inputSchema`（properties + required），供 MCP 客户端直接生成参数。
- `node_*` 工具按**目标节点实际类型**选择作用域：画板→board、思维导图→mindmap、其余→doc；目标不存在时退回工具声明作用域。
- 待审审批是单次的：先原子认领再从 `pending` 变为 `approved`，重复/并发审批返回冲突，不重复写入。

### 1.2 权限模型（设置 → AI 协作）

- 作用域：`doc`、`board`、`mindmap`（只读读取不设限）。
- 模式（每作用域独立）：`read-only` / `review`（默认）/ `editable`。
  - `read-only`：一切写工具直接拒绝，返回结构化错误 `PERMISSION_DENIED`。
  - `review`：低/中风险写入进入待审区；高风险（`doc_replace_range`、`doc_delete_block`、`board_delete_elements`、`node_trash`）始终进入待审区，即使在 `editable` 模式。
  - `editable`：低/中风险直接执行并记审计；高风险仍进待审区。
- 设置存储：工作区库 `workspace_meta` 键 `ai.permissions`（JSON），默认 `{doc:"review", board:"review", mindmap:"review"}`。

### 1.3 待审区 / Inbox

- 新表 `ai_inbox`：`id, tool, node_id, payload_json, summary, risk, status(pending|approved|rejected|failed), error, created_at, decided_at`。
- 新表 `ai_audit`：`id, tool, node_id, summary, risk, outcome(direct|inbox|approved|rejected|failed), created_at`。
- 审批：桌面端「设置 → AI 协作 → 待审区」列表，逐条查看差异摘要 → 通过（执行真实写入，复用服务层，成功后 status=approved）或拒绝。
- 冲突：审批执行时若 `expectedVersion` 不匹配，标记 `failed` 并记录原因，agent 在 `inbox_get` 里可读到。

### 1.4 Skill

- 仓库内置 `skills/starris-memory/SKILL.md`：工具用法、权限语义、推荐工作流（检索 → 读段落 → 提出修改 → 等待审批 → 复核）、错误码。
- 安装说明写入需求文档与 README 片段。

## 2. 数据与实现

- Rust：`mcp.rs`（JSON-RPC dispatch）、`services/mcp_host.rs`（客户端托管 HTTP 服务与令牌）、`services/ai_service.rs`（工具执行 + 权限判定 + inbox 入队/审批）、`repositories/ai_repository.rs`（SQL）、`commands/ai.rs` + `commands/mcp.rs`（权限、待审、MCP 开关）；`ai_inbox`/`ai_audit` 纳入 schema v15 基线与启动自愈，不新增独立版本号。
- 段落级编辑基于文档 BlockNote JSON：`doc_read` 展平块树；`doc_update_block` 仅改目标块内联文本；`doc_append_blocks` 追加 paragraph；`doc_replace_range` 按扁平常量区段替换。所有写入走 `document_service` 的保存路径（版本+历史一致）。
- 权限判定集中在 `ai_service::decide(&settings, tool) -> Decision::{Deny, Direct, Enqueue}`。

## 3. 验收

1. 客户端启动后 MCP 端点在 `/health` 可访问，`initialize` 握手并列出工具；无令牌返回 401；只读工具在真实工作区返回内容。
2. `review` 模式下 `doc_update_block` 不落库，出现在 `inbox_list` 与桌面端待审区；通过后落库、审计日志完整；拒绝后保持原样。
3. `read-only` 下写工具返回 `PERMISSION_DENIED`；`editable` 下低/中风险直接落库并审计；高风险始终进待审。
4. 并发冲突：携带旧 `expectedVersion` 的审批失败并记录原因。
5. Rust 集成测试覆盖上述矩阵；MCP HTTP 烟雾脚本（需运行中的客户端）；真机 UI（设置页 MCP 状态与待审区）操作通过。
6. Skill 文档可被 agent 直接使用（包含端点配置、令牌与工具签名）。

## 4. 非目标（v1）

- HTTP/SSE 传输、多客户端并发会话管理。
- 删除类工具（永久删除/清空回收站）。
- 画板自由手绘/图片上传工具。
- 块级「移动/重排」以外的高级排版命令（表格合并等）。
