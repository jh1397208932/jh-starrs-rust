# 需求文档 · 界面收口与 MCP 人工确认（2026-10-28）

> 来源：用户 2026-10-28 提出的 10 条界面/功能收口要求（含 9 张真机截图证据）。
> 口径：本文只记「要什么 + 判定标准」；实现细节在 `docs/开发任务清单/2026-10-28-任务-003/`。

## 1. 导入入口合并

更多菜单里「导入…」与「导入思维导图…」两条并存 → 只保留「导入…」。
判定：菜单项数减一；`.mm/.xmind/.opml/.starris-mindmap.json` 经「导入…」仍能生成思维导图节点，
且比原专用入口多保留「导入到」目标目录（原入口固定写到知识库根）。
依据：后端 `import_service.rs:800` 早已按扩展名把这三类转给导图导入器，两条入口本属重复。

## 2. 新建弹窗类型行的空白

「新建」弹窗四个类型图标挤在左侧、右侧大片空白。
判定：图标行按类型数量等分整行宽度，类型增减时不留空洞。

## 3. 关于页收口

现状只有一句「第三方开源组件」加三行文本，不足以说明项目用了什么。
判定：一句话简介 + 构建信息 + 上游开源项目（默认可见）+ 完整第三方清单（默认收起、可展开），
清单含许可证、仓库地址与用途；许可证与地址必须来自实测数据（`node_modules` 与 `cargo metadata`），
不得凭印象写。

## 4. 设置-存储 只做统计

设置里的上传、搜索附件、附件列表、保留时间下拉与「回收站」切换按钮全部下线：
附件是文件树里的一等节点，管理动作跟着树走。
判定：设置-存储 只剩「位置 + 工作区总大小 + 分类占用（数据库/附件/回收站/临时文件/隔离区）
+ 保留时间 + 立即清理」；左侧树「新建」弹窗内有「上传附件」。

## 5. 界面语言显示为空

设置-通用 的「界面语言」下拉在真机上显示空白（新建工作区后同样）。
判定：触发器始终显示当前语言（简体中文 / English），切换后仍显示新值。

## 6. 快捷键不再报跨作用域重复

设置-快捷键 对「保存当前文档 ⌘S」等提示「与画板「保存画板」重复，当前作用域优先」。
判定：这类跨作用域提示全部撤下——同一时刻光标只在一个标签页，tab 内键位不构成冲突；
同作用域内的真实冲突仍然报错。

## 7. MCP 健壮性与人工确认

- 代码审查发现的传输层与权限层缺陷需修复（详见任务目录的缺陷清单）。
- 判定：需要人工确认的写入（高风险，或作用域设为「需人工确认」）在主界面弹出**前后对比**确认窗，
  标注工具名、风险、目标与新增/移除行；批准才落库，拒绝一条都不写。
- 真机 e2e 必须实际调用一次 MCP 写入并走完确认。

## 8. 立即清理的边界

判定：清理只碰过期临时文件、超过保留期的回收站条目、失去引用的对象与失效哈希索引；
有效数据（正在使用的文档/画板/导图/附件）不受任何影响；点击需二次确认，并回报清理数量与释放字节。

## 9. 清空回收站按钮错位

「清空回收站」与对话框右上角关闭按钮重叠。
判定：按钮移到页脚；清空功能真机可用（二次确认后回收站条目真正移除）。
