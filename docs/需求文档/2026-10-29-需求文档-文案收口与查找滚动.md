# 需求文档 · 文案收口与查找滚动

- 日期：2026-10-29
- 状态：已实施并完成真机验证
- 关联任务：`docs/开发任务清单/2026-10-29-任务-005/`

## 1. 文档查找：命中必须滚到视口

现状：查找条能算出 `1 / 1` 与高亮，但命中在屏幕外时编辑器不滚动；原因是查找框持有焦点，ProseMirror 的 `scrollIntoView` 只对获得焦点的编辑器视图生效。

方案：

1. `DocFindBar` 在每次落到命中后，读取 `view.coordsAtPos(from)`，找到 `.doc-editor-scroll`，按命中相对容器顶部的位置显式 `scrollTo`，把命中放到视口约 32% 高度。
2. 只在命中超出视口（上下各留 72px）时滚动，避免已可见时来回跳。
3. 输入与上/下一处共用同一跳转函数；不抢查找框焦点。
4. e2e `97b` 增加「命中文字在视口内」的 AX 断言并保留截图。

## 2. 导入弹窗：去技术解释，改回「选择文件夹」

- 去掉「支持 Markdown、Word、PDF、Excalidraw、XMind、FreeMind、OPML…」格式清单与「扫描件未启用 OCR」等技术解释，改为一句「选择文件或文件夹，导入为文档、画板或思维导图。」
- 卡片只保留「选择文件」「选择文件夹」，去掉「可多选」「选文件夹 · 自动分流」副标题与「混合导入：本地附件进对象库…」提示。
- 空「来源」块不再渲染；选中后只显示一行「已选择：文件夹名」或文件名摘要，「保留文件夹结构」保留。
- 扫描结果改为「找到 N 个文件，将导入 X 个」「其中 N 个附件会一并保存」「跳过 N 个无法识别的文件」；确认弹窗改为「有 N 个文件无法识别，将被跳过。」
- 主按钮统一为「导入」；扫描中显示「正在准备…」。
- 用户可见的 PDF 提示同步去术语：图片版 PDF、无法提取文字、文件太大等，不再出现 OCR/编码等词。

## 3. 开发规范：用户文案只说明功能

在 `AGENTS.md` 新增 §3.8：

- 先回答“这是什么功能/会发生什么”，一句话说清；不解释实现原理、协议、存储机制、算法或数据格式。
- 不用开发者术语（OCR、hash、对象库、CID、token）；状态用用户结果表述。
- 弹窗说明、按钮副标题、空态、警告、错误同一标准；技术细节只进日志/开发文档。
- 文案改动同步检查 e2e 断言与英文词典。

## 4. 关于页：鸣谢 + 开源项目清单弹窗

- 删除常驻的「上游开源项目」长列表与「展开完整第三方清单（41 项）」折叠区。
- 改为一句鸣谢「星屿建立在这些开源项目之上，感谢每一位作者与贡献者。」+「查看开源项目清单」按钮。
- 按钮打开弹窗，只列**直接引用**的开源项目（前端/桌面后端/字体三组，来自 `CREDIT_GROUPS`），每项显示名称、许可证与可点击仓库地址；地址过长截断，点击用系统浏览器打开。
- 弹窗末尾加一句「以及这些项目的上游项目。」
- 关于页的信息行改为用户语言：「运行方式 · 本地桌面应用」「数据位置 · 保存在本地工作区」。
