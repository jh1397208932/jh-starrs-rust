## 1. 背景与目标

把 PDF 纳入现有「导入」入口，转成可编辑文档：标题、段落、列表、表格尽量保留为原生块；原始 PDF 作为附件挂在文档末尾，便于回溯。扫描件不做假转换，保留原件并明确提示未启用 OCR。

## 3. 行为

1. **入口**：沿用「更多 → 导入…」；文件面板过滤加入 `.pdf`，可与 Markdown/Word 等一起多选。
2. **文本型 / 混合型 PDF**：`process_pdf` 输出 Markdown → 复用 `import_markdown::parse_markdown` 转 Tiptap 块（同一套块规则，不引入第二套 Markdown 解析）；有表格/标题时保留为原生表格与标题。
3. **原始文件**：与 Markdown/Word 导入一致，把 PDF 作为附件块追加到文档末尾（逻辑目录 `attach`，重名自动改名）。
4. **扫描件 / 图片型**：不生成假正文；文档首段写明「此 PDF 是扫描件，当前未启用 OCR，未提取到文字。」，原始 PDF 仍作为附件保留；导入结果展示警告（含需 OCR 的页码）。
5. **失败**：加密/损坏/超限（>128 MB）时，沿用现有导入兜底：创建文档、写明正文转换失败、保留原始附件，并在结果里给出原因。
6. **质量提示**：字体编码不完整、部分页需 OCR 时写入 warnings，导入弹窗展示前 3 条（文件名：原因）。

## 4. 非目标

- 不启用 OCR（`ocr`/`ocr-oar`/`render-pdfium` 特性全部关闭），不引入 PDFium/ONNX。
- 不保留 PDF 的精确分页、页眉页脚版式与批注/表单。
- 不改变 PDF 导出链路。

## 5. 验收

- 导入文本型 PDF：生成同名文档，正文含 PDF 文字（标题/段落），末尾有原始 PDF 附件。
- 扫描件：生成文档 + 提示段 + 原始附件，导入结果有警告；不出现空白正文。
- 多选 Markdown + PDF：两者都成功，失败项不影响其它项。
- 单份 >128 MB：给出明确提示，不崩溃。
- 门禁：`cargo test`（新增 PDF 导入用例）、`cargo clippy`、`tsc`、`biome`、i18n、许可证门禁。
