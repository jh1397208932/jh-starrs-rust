# 需求文档：编辑器数据闭环与交互重构

- 日期：2026-10-22
- 关联任务：`docs/开发任务清单/2026-10-22-任务-004/`
- 前置需求：`2026-10-22-需求文档-编辑器块存储与交互增强.md`

## 1. 背景与目标

上一轮已经落地 Tiptap 块级增量存储、拖拽手柄和三类浮动菜单，但真实使用中暴露出数据与交互问题：

1. 正文里出现大量 `:null::null:`；已落库内容存在 `{"type":"emoji","attrs":{"name":null}}`。
2. 在带颜色/代码等样式的段落回车后，新块继续沿用上一块的 marks。
3. 拖动手柄观感突兀、显示时机不稳定、拖动后不生效，缺少清晰的落点分隔线。
4. 各类块的样式和菜单布局缺少统一、精致的设计语言。
5. 需要确认 `editor.getJSON()` 的真实结构，并修正保存/回显链路。
6. 需要为文档保存一份可检索的 Markdown 文本和扩展属性，异步写入 `doc_block_meta`。

**目标**：在不引入任何非开源/收费依赖的前提下，把编辑器做到数据正确、交互稳定、块类型完整、视觉达到 Notion-like 高级感，并保持 Rust 为业务权威。

## 2. 范围

### 2.1 本期做

- 确认 Tiptap JSON：根对象 `{"type":"doc","content":[...]}`，后端按 `content` 数组切顶层块。
- 保存与加载统一做 JSON 规范化：
  - 删除 `emoji` 中缺失/空 `name` 的非法节点；
  - 删除值为 `null` 的节点属性（`attrs`）与空 marks；
  - 规范化结果参与块哈希与正文缓存，保证 hash 与内容一致。
- 新增 `doc_block_meta` 表（每篇文档一行，主键与 `node.id` 完全相同）：
  - `markdown`：由 Tiptap JSON 生成的 Markdown 文本；
  - `prop`：JSON 对象，存字数、块数、schema 版本等扩展属性；
  - `update_time`：最近一次元数据生成时间；
  - 保存成功后**异步**更新，不阻塞正文保存返回。
- 关闭 Emoji 的 emoticon 输入规则（当前表情集没有 emoticons，空规则会把空格变成非法 emoji 节点），并对渲染增加守卫。
- 回车新建块时清除行内样式（storedMarks），列表/引用/代码块/表格保留各自应有的块语义。
- 重做拖拽手柄：手柄定位、显隐、插入与拖拽全部自绘（不使用官方 DragHandle），保证 WKWebView 下真实可用；显示/隐藏、滚动、拖动落点稳定。
- 使用官方 Dropcursor 提供行级高亮落点指示。
- 全量检查并对齐以下块的样式：段落、H1–H3、无序/有序/任务列表、引用、代码块、分隔线、表格、图片、折叠块、表情、链接、行内代码、颜色/高亮、上下标。
- 三类浮层统一视觉：气泡菜单、右键菜单、Slash 菜单。

### 2.2 本期不做

- 图片附件后端上传（仍为 ≤2MB data URL）。
- 协同编辑、评论、AI 能力。
- 全文检索 UI（本期只落 Markdown 与 prop 数据）。

## 3. 功能规则

### 3.1 编辑器数据契约

- 前端提交：`SaveDocumentInput.document = editor.getJSON()`，必须是根 doc 对象。
- Rust 权威校验：根 `type=doc`；`content` 缺失/null 视为空数组；其余类型报错。
- 顶层块规范化后计算 xxh3-128；规范化正文整体写入 `node.content`。
- 加载返回完整根 doc；前端 `setContent` 不触发 update，避免“加载即脏”。

### 3.2 文档元数据

- 表结构：

```sql
CREATE TABLE doc_block_meta (
  id          TEXT PRIMARY KEY NOT NULL,
  markdown    TEXT NOT NULL DEFAULT '',
  prop        TEXT NOT NULL DEFAULT '{}',
  update_time INTEGER NOT NULL,
  FOREIGN KEY (id) REFERENCES node(id) ON DELETE CASCADE
);
```

- `id` 与 `node.id` 完全一致；删除节点级联删除元数据。
- 保存正文成功后，将 `markdown/prop` 投入后台写线程；失败只记录日志，不影响正文保存结果，下一次保存自动重试。
- `markdown` 至少支持：标题、段落、粗/斜/删除线/行内代码/链接、引用、有序/无序/任务列表、代码块、分隔线、图片、表格、折叠块、表情。
- `prop` 至少包含 `wordCount`、`blockCount`、`version`，并预留其他属性。

### 3.3 回车与行内样式

- 普通段落/标题/引用/列表项中按 Enter：
  - 新块不继承上一块的颜色、高亮、粗斜体等行内 marks；
  - 空列表项、空引用等结构退出行为沿用 Tiptap 默认；
  - 代码块、表格、折叠块内部不拦截。
- Shift+Enter 软换行保持原样式。

### 3.4 拖拽

- 手柄位于块左侧，颜色/背景使用语义令牌，默认低对比，hover 才明显。
- 鼠标进入正文块时显示，离开正文/滚动/按键盘时隐藏；鼠标移向左侧手柄时保持当前块不跳动。
- 拖动必须真正改变 ProseMirror 文档顺序，松开后内容与块树顺序一致。
- 拖动过程中在目标位置显示整行水平高亮条；源块淡化；光标旁显示块类型标签。

#### 3.4.1 技术决策：手柄与拖拽自绘

- 官方 `@tiptap/extension-drag-handle` 把手柄定位与 HTML5 拖放绑在一起。在 Tauri 的 WKWebView 中，`dragstart` 协议字段与 `effectAllowed/dropEffect` 的行为和 Chromium 不一致，实际表现为“手柄能拖走、松手正文不动”；同时官方 `mouseleave` 会立刻隐藏手柄，移到按钮的过程不可控。
- 因此移除 `@tiptap/extension-drag-handle` 与 `-react` 依赖，改由 `useBlockHandle` + `useBlockPointerDrag` 自绘：
  - 定位：按鼠标 Y 找到顶层块，读取 `view.nodeDOM` 的 `getBoundingClientRect`，绝对定位到 `.doc-editor-body` 左走廊；
  - 拖拽：`pointerdown/pointermove/pointerup` 计算落点，直接派发 ProseMirror `delete + insert` 事务，不依赖 `dataTransfer`；
  - 源块淡化：用 ProseMirror Decoration 表达，不直接改 DOM class；
  - 块级落点线自绘，官方 Dropcursor 仅保留给图片/文件原生拖放。
- 边界：仅支持顶层块拖拽（与官方默认一致）；键盘拖拽与触屏长按未纳入本轮范围。

### 3.5 视觉

- 沿用 `tokens.css` 的暖色语义令牌，不硬编码颜色。
- 浮层：12px 圆角、1px 边框、分层阴影、紧凑分组标题、图标 + 文本 + 快捷键提示。
- 菜单按钮位置稳定，不遮挡选区；长菜单在视口内滚动。
- 所有块具备 hover/active/selected/focus 状态。

## 4. 验收标准

1. 在任意段落连续输入空格，不出现 `:null:` 文本；重新加载后也不出现。
2. 设置颜色/粗体后回车，新段落的输入文本无上一段 marks；列表、代码块、表格行为正常。
3. `doc_save` 入参的 `document.type === "doc"` 且 `Array.isArray(document.content)`；保存后重新加载内容一致。
4. 旧库启动迁移到 v4，`doc_block_meta` 存在；保存后该表出现/更新对应 node.id 的行，`json_valid(prop)` 为 1。
5. 鼠标悬停块左侧出现手柄；滚动后手柄不残留在错误位置；拖动块到另一块之前/之后，顺序真实变化并出现落点指示线。
6. 所有块类型在浅色/深色主题下样式完整，无不可见文字、无零尺寸控件。
7. Rust 单元/集成测试、Biome、tsc、构建、许可证门禁全部通过；浏览器黑盒复验记录真实结果。

## 5. 风险与边界

- 规范化会改变旧正文的字节内容与块哈希；属于修复性迁移，首篇旧文档加载后会自动触发一次保存，块树重建为新哈希。
- 异步元数据允许短暂滞后；正文保存成功优先。应用在写入前退出时，下一次保存会补齐。
- 拖拽依赖鼠标事件；自动化环境需使用真实 pointer 序列，不能用直接改 DOM 代替。
- Markdown 为派生数据，不反向驱动编辑器内容。
