## 1. 背景与目标

本轮收口 7 个问题：文档内查找的形态与跳转、草稿恢复的误触发、文档内嵌画板/思维导图预览、多标签下「新建」弹窗的响应延迟，以及画板（Excalidraw 集成）的 chrome 收口。

画板部分是体验走查后的改版：

| 维度 | 现状 | 结论 |
| --- | --- | --- |
| 一致性 | 原生汉堡菜单含 Excalidraw links（GitHub / Follow us / Discord）、原生帮助弹窗带博客/反馈/YouTube 外链 | 与星屿的信息架构和视觉体系不一致 |
| 可发现性 | 页头有「组件库」按钮，画布右上还有原生素材库入口；右侧打开后是原生空白库 | 入口重复，且右侧内容不是我们的组件库 |
| 用户控制 | 帮助/重置藏在左侧汉堡菜单；画布背景也在菜单里 | 高频外观操作埋得过深 |
| 帮助文档 | 原生帮助弹窗中英混排、含无关条目、无明确关闭按钮 | 改为跟随本应用快捷键配置的自家帮助弹窗 |
| 性能 | 多标签时点「新建」弹窗出现慢 | 需实测定位，见 §7 |

目标：画布区域只留画布与工具条，其余全部收进页头；右侧组件库用星屿组件重做；文档内可直接嵌入画板图/思维导图，并随源更新。

## 2. 需求逐条

### 2.1 文档内查找：右上角浮动 + 高亮 + 跳转视口

现状：`DocFindBar` 渲染在文档页头流内（标题上方），展开时把标题往下推；输入关键字只算匹配，不主动滚动到第一处。

方案：

1. 查找条移出文档流，绝对定位到编辑区右上角（`right: 16px; top: 12px`，宽约 320px、单行、带阴影），不改变正文布局；窄窗口（< 1120px）下移到页头操作行下方，避免覆盖页头图标。
2. 输入即跳转：查询变化并算出匹配后，把选区落到第一处并 `scrollIntoView`；`Enter` / `Shift+Enter` 与上/下按钮跳转并同步滚动。
3. 高亮保持两档：全部匹配淡色底，当前匹配主色实底；关闭查找时清除装饰，不改正文、不触发保存。

验收：

- 打开查找条后正文不位移；
- 输入一个文末才出现的词，视口自动滚到命中处且该处为主色高亮；
- `1 / N` 计数与命中数一致；`Esc` 关闭后无残留高亮。

### 2.2 草稿恢复：先查触发条件，再修误报

现状与根因（已读代码确认）：

- 草稿写入：`DocEditor` 在每次 `onUpdate` 后 2s 防抖写 `localStorage`（`src/features/editor/components/DocEditor.tsx:661-675`）。
- 草稿清除：仅在保存成功回调、点「忽略」、切换文档时清（`DocEditor.tsx:225-236`、`957`）。
- 提示条件：`draft.savedAt > loaded.updatedAt`（`DocEditor.tsx:797-803`）。

误报链路：正常编辑时自动保存约 1s 完成并清掉草稿，但 2s 的草稿定时器随后仍会再写一份；此后没有新的保存，这份草稿就一直留着，且 `savedAt` 比服务端 `updatedAt` 晚 1s 左右 → 下次打开必然弹「检测到未保存的草稿」。这与协作无关，是崩溃恢复的实现缺陷。

方案：

1. 只在「有未保存修改」时写草稿：`onUpdate` 置 dirty 标记；保存成功清标记并取消挂起的草稿定时器 + 清草稿；定时器到点时若已无未保存修改则跳过。
2. 草稿继续保留为崩溃/强退恢复手段，不做成协作或版本功能；冲突、保存失败时草稿不清，符合预期。
3. 历史遗留的误报草稿：下一次成功保存会清掉；不额外做迁移。

验收：

- 编辑后等自动保存完成，再停留 > 2s，关闭重开文档：不出现草稿提示；
- 编辑后 2s 内强杀应用、重开：出现提示，恢复后内容一致；
- 保存失败（模拟冲突）时草稿仍在，提示可恢复。

### 2.3 文档内嵌画板 / 思维导图（异步预览图，存对象库，可回收）

需求拆解：

- 文档新增两个自定义块：`boardEmbed`（画板图）、`mindmapEmbed`（思维导图），只存源节点 id 与标题，不复制源数据。
- 源内容异步生成 PNG，存对象库；文档块通过命令按 id 取图渲染。
- 源更新后，文档再次打开（或同屏收到更新事件）时刷新图片。
- 源节点删除、预览被替换时，旧对象要被回收。

关键约束（2026-10-29 用户补充）：文档编辑器**不得实时渲染**画板/思维导图，只能显示已经导出的最终 PNG；导出必须发生在源视图一侧（提前生成）。因此职责划分为：

- **画板/思维导图视图**：保存静止 1.2s 后，用现有官方导出器渲染（画板 `renderBoardPng`、导图 `renderMindmapSvg` + `svgToPngBlob`），缩放到最长边 ≤ 1600px 后提交；已有且未过期的预览直接复用，不重复渲染。
- **文档内嵌块**：只调用两个查询命令读已存图片；缺图时提示「打开源内容后会自动导出」，不在编辑器里加载源场景、不做光栅化。
- **Rust**：存对象、去重、记录「源节点 → 预览对象」、提供两个只读查询命令，并接入现有引用回收链路。

数据模型（工作区库新增迁移）：

```sql
CREATE TABLE IF NOT EXISTS node_preview (
    node_id          TEXT PRIMARY KEY NOT NULL REFERENCES node(id) ON DELETE CASCADE,
    object_id        TEXT NOT NULL,
    width            INTEGER NOT NULL CHECK (width > 0),
    height           INTEGER NOT NULL CHECK (height > 0),
    source_updated_at INTEGER NOT NULL,   -- 生成时源节点 update_time
    updated_at       INTEGER NOT NULL
);
```

对象归属：预览图作为内部附件落现有 `attachment`/`attachment_blob`（scope=node，逻辑目录 `__preview`），并在 `node_attachment` 里登记「源节点 → 预览对象」引用。这样：

- 源节点删除 → `node_attachment` 级联 → 旧对象进入孤儿流程 → 维护任务按用户设置的宽限期回收；
- 预览替换 → 先写新对象、更新 `node_preview`，再删旧引用，旧对象走同一回收链路；
- 内容未变（版本相同或字节哈希相同）时不新建逻辑行，避免自动保存造成对象膨胀。

命令（`commands/preview.rs` + `services/node_preview_service.rs`）：

| 命令 | 入参 | 返回 | 说明 |
| --- | --- | --- | --- |
| `board_image` | nodeId | `NodePreviewDto \| null` | 按画板 id 查文档图片 |
| `mindmap_image` | nodeId | `NodePreviewDto \| null` | 按思维导图 id 查文档图片 |
| `node_preview_save` | nodeId, dataBase64, width, height, sourceUpdatedAt | `NodePreviewDto` | 前端渲染完成后写入（去重 + 换引用） |

`NodePreviewDto`：`{ nodeId, dataUrl, width, height, sourceUpdatedAt, stale }`；`stale = source_updated_at < node.update_time`，用于前端决定是否后台重生成（先显示旧图，再无缝替换）。

前端：

- `src/features/editor/extensions/embedBlock.ts`：两个 atom 节点，attrs `{ nodeId, title }`，HTML 用 `data-board-embed` / `data-mindmap-embed` 承载，便于导出与重载。
- `NodeView`：只查询已存 PNG → 骨架占位 → 图片（`figure` 卡片：图标 + 标题 + 图 + 更新时间）；点击标题/图片打开源节点。缺图时显示「预览尚未生成，打开源内容后会自动导出」，**不触发渲染**。收到 `starris:node-preview-updated` 时重读。
- 导出队列 `src/features/editor/utils/nodePreview.ts`：只由画板/导图视图在保存静止后调用（1.2s 防抖 + 同节点单飞）；先查已有预览，未过期直接复用；渲染失败保留旧图并记日志。
- 插入入口：Slash 菜单「画板图」「思维导图」→ 选择弹窗（列出当前知识库内对应类型节点，带搜索；空态引导先新建）。弹窗由 `DocEditor` 持有，节点列表由 `TabContentView` 从 store 透传。
- 打开源节点：沿用 `activeDocument` 式的事件通道，由工作区注册「按 id 打开标签」。

导出兜底：Markdown/HTML/整库导出遇到两个新块时输出一行可读占位（如 `画板：标题（内嵌预览，请在 Starris 中查看）`），不静默丢内容。

验收：

- 插入画板图后显示源画板缩略图，尺寸标注正确；
- 改动画板并保存，回到文档：先看到旧图，短暂后替换为新图（或重新打开即为新图）；
- 删除内嵌块不影响源节点；删除源节点后文档块显示「源已删除」，对象在宽限期后由维护任务回收；
- 连续自动保存 10 次只产生不超过 1 个新对象；
- 导出的 Markdown/HTML 不丢块（有占位文本）。

### 2.4 多标签下「新建」弹窗延迟：先量后修

现象：窗口里打开多个标签后点「新建」，弹窗出现明显延迟。

现状可疑点（待实测确认，不先下结论）：

1. `WorkspaceLayout` 给 `TabContentView` 传了内联 `onBoardExported={(message) => showToast(...)}`，每次控制器渲染都是新引用，`memo` 被击穿 → 打开任意弹窗都会连带重渲染当前文档编辑器（`src/features/workspace/components/WorkspaceLayout.tsx:167`）。
2. 弹窗自身挂载成本：Radix Portal + 焦点陷阱 + `backdrop-blur-md` 容器（在 WKWebView 上可能与窗口内既有模糊层叠加）。
3. 标签栏每个 tab 带 Motion `layout` / `layoutId`，需确认重渲染时的测量成本。

排查方法：

1. 在 `requestNodeCreate` → `DialogContent` 首次绘制之间打 `performance.mark`，经现有 `log_write` 输出；分别测 1 个标签 / 8 个标签 / 长文档三种场景。
2. 先修可静态确认的 memo 击穿，再复测；若仍高，按测量占比处理弹窗挂载（例如降低入场的模糊/动画成本或延迟挂载正文），不盲改。
3. 探针只在排查期存在，结论落文档后删除。

验收：给出改前/改后的同场景数字；8 标签场景点击到弹窗可见不再有可感知延迟。

### 2.5 画板：去掉原生链接，帮助/重置收进页头最后一个按钮

现状：原生汉堡菜单含 `Excalidraw links`（GitHub / Follow us / Discord chat）；帮助与重置画布也在这个菜单里。

方案：

1. 隐藏原生汉堡菜单（`.main-menu-trigger`），画布左上不再有操作按钮。
2. 页头操作区改为：`附件` `放映` `导出▾` `⋯` `已保存`；`⋯` 是页头最后一个按钮，承载：
   - 帮助与快捷键
   - 画布背景（5 个官方色 + 默认白，行内色块）
   - 打开画板文件…
   - 重置画布（危险项，二次确认）
3. 原生菜单的能力不丢：导出已在页头；打开文件迁到 `⋯`；画布内查找如有原生入口，迁到 `⋯`（实现时验证，不以「删除」收场）。
4. 不再出现任何 Excalidraw 外链。

说明：原生工具条最右侧的「更多工具」下拉（画框/嵌入网页/激光笔/Mermaid）是 Excalidraw 内部组件，没有注入 API；因此「最后一个按钮」落在页头操作区的 `⋯`，而不是原生工具条内。此为本条的唯一偏差，需确认。

### 2.6 画板帮助：去无关内容、快捷键联动、补关闭按钮

方案：不用原生帮助弹窗，改为 `BoardHelpDialog`（星屿弹窗规范）：

- 分组：工具（选择/矩形/椭圆/箭头/文本）、画板（插入附件/组件库/导出 PNG/保存画板）、编辑（撤销/重做/复制/粘贴/删除/全选/缩放，标注「固定键位」）。
- 工具与画板两组直接读 `ShortcutProvider` 的当前绑定；用户改键/清空后，帮助弹窗同步变化（清空的条目不显示）。
- 顶部右上角 `×`，底部「关闭」按钮；`Esc` 可关。
- 删除文档/博客/反馈/YouTube 外链与中英混排条目。

### 2.7 画板右侧组件库与整体布局

方案：

- 删除页头的「组件库」按钮；组件库改为画布右侧的停靠面板（宽 296px），与画布并排，展开时画布收窄、Excalidraw 自行适配，不遮挡内容。
- 面板内容全部用星屿组件与令牌，不用 Excalidraw 原生 library 样式：
  - 头部：标题「组件库」+ 数量 + 关闭；
  - 搜索框；
  - 列表：组件名、形状数、插入按钮（插入后不关面板，可连续插入）；
  - 空态：提示在「左侧更多 → 组件库」导入 `.excalidrawlib`；
  - 加载/错误态。
- 入口：画布右缘中部一个竖向把手（Layers 图标 + 「组件」），与文档大纲把手同一语言；`Mod+Shift+L` 亦可开合（沿用现有 `board.openLibrary`）。
- 隐藏原生 library 入口（`.default-sidebar-trigger`）与底部原生帮助入口，避免双入口。
- 画布背景从菜单迁到页头 `⋯`（见 2.5）。

布局示意：

```
┌ 页头 ───────────────────────────────────────────────────────────┐
│ 知识库 › 标题                    附件  放映  导出▾  ⋯   已保存   │
├───────────────────────────────────────────────┬─────────────────┤
│                                               │ 组件库      ×   │
│              Excalidraw 画布                  │ [搜索组件…]      │
│      （无原生汉堡 / 无原生素材库入口）         │ ▢ 组件 A   插入  │
│                                               │ ▢ 组件 B   插入  │
│                                        [组件] │                 │
└───────────────────────────────────────────────┴─────────────────┘
```

验收：

- 页头不再有「组件库」；画布左上无汉堡、右上无原生 library 入口；
- 右侧面板开合正常，画布不遮不压，窗口变窄时面板可关闭且画布可正常缩放；
- 面板列表来自已启用组件库，插入行为与原弹窗一致；
- 画布背景修改立即生效并在重开后保持；
- 帮助弹窗只含本应用相关内容，键位与设置中的自定义一致。

## 3. 数据与迁移

- 新增 `node_preview` 表；随现有工作区库启动任务按版本迁移，不在业务路径写 DDL。
- 预览对象复用 `attachment`（scope=node，`logical_path = "__preview"`）与现有 blob/pack 存储、去重、维护任务。

- Rust：`db/workspace.rs`（迁移）、`models/node_preview.rs`、`repositories/node_preview_repository.rs`、`services/node_preview_service.rs`、`commands/preview.rs`、`lib.rs` 注册；`domain/document.rs`、`services/export_render.rs`、`services/export_service.rs` 增加占位渲染；维护服务无需改判据。
- 测试：Rust 单测（去重、替换、级联、懒迁移）；前端单测（草稿 dirty 语义、查找跳转、预览队列单飞）；真机 e2e 扩展。

## 5. 非目标

- 不做协作、不引入版本合并；草稿仍只服务崩溃恢复。
- 不改画板文件格式与 Excalidraw 版本。
- 不重做思维导图编辑器本身。
- 不在本轮做整库导出内嵌图片的像素级还原（只保证不丢块）。

## 6. 风险与取舍

- 原生汉堡菜单移除后，Excalidraw 自身「打开场景/查找」入口需要迁到 `⋯`；若原生查找无法从外部触发，就在 `⋯` 里保留「画布内查找」并用可控方式实现，不能静默消失。
- 预览生成依赖打开文档时读取源场景；大画板首次生成会多一次加载，采用「先旧图后替换」避免白屏。
- 右侧面板停靠会改变画布可视宽度，需验证 Excalidraw 尺寸适配与缩放中心。

## 7. 验收方式

1. 门禁：`biome`、`tsc --noEmit`、`cargo fmt --check`、`cargo clippy`、`cargo test`、`check-i18n-keys.mjs`、`check:licenses`。
2. 真机：全部功能完成后统一跑 `test/e2e` 全量，逐张审查截图；新增用例覆盖查找跳转、草稿不误报、内嵌预览更新与回收、画板新布局、帮助键位联动。
3. 性能：§2.4 的三种场景给出改前/改后数字。

## 8. 已定方案

1. 「最后一个按钮」落在页头 `⋯`（原生工具条无法注入）；原生汉堡菜单整体隐藏。
2. 草稿保留为崩溃恢复，只修「保存后又写一份」的误报。
3. 组件库面板默认收起，画布右缘把手进入，展开时画布收窄 296px。
4. 预览生成时机（已定）：画板/导图保存静止后导出；文档端只读最终 PNG，打开文档不触发渲染。
