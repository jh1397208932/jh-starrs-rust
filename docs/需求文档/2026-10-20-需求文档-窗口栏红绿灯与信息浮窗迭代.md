# 需求文档 · 窗口栏红绿灯与信息浮窗迭代

- 日期：2026-10-20 · 状态：已实现 · 来源：用户桌面端实测反馈

## 1. 背景与目标

用户在 macOS 实机运行 `tauri dev` 后反馈三点：红绿灯位置过于贴顶；窗口失焦后红绿灯变灰、左上角区域空旷；同时要求按 `AGENTS.md` 规范审查代码结构。目标是在不破坏现有二分布局（通高侧栏 + 窗口栏）的前提下修正红绿灯视觉并完成规范对齐。

## 2. 需求范围

1. 红绿灯垂直位置调整至 44px 拖拽带内视觉居中。
2. 红绿灯槽位增加淡色胶囊底座（焦点/失焦均有视觉承托），颜色随主题令牌。
3. 按 AGENTS.md 检查规范文件本身错误并修正；对代码结构与规范不一致处做最小对齐（组件映射去重、文档体系补齐）。

不做：不迁移 pnpm（环境阻塞，见 AGENTS.md §1 例外记录）；不大规模搬动稳定代码（规范 §2 禁止）。

## 3. 业务规则与验收标准

| # | 规则 | 验收标准 |
|---|---|---|
| R1 | 红绿灯中心与 44px 槽位居中对齐 | `trafficLightPosition.y = 16`（16 + 12/2 = 22 = 44/2） |
| R2 | 底座胶囊覆盖三枚红绿灯（x≈12~64） | `TrafficLightSlot` 渲染 58×16 胶囊 `bg-accent/70`，left 6px 垂直居中 |
| R3 | 底座在侧栏常态与折叠回补两处视觉一致 | 侧栏顶带与 WindowBar `trafficInset` 共用同一 `TrafficLightSlot` 组件 |
| R4 | 节点类型图标/文案单一权威实现 | Sidebar 树与 WindowBar 标签页均引用 `components/common/NodeKindIcon` |
| R5 | AGENTS.md 无 Markdown 语法错误与笔误 | §14 孤立围栏清除、§19 文件名修正为 UI-SPEC.md |

## 4. 交互流程

纯视觉与结构对齐，无新增交互流程；信息浮窗把手交互沿用上一版本（`›`/`‹` 开合）。

## 5. 边界与异常

- `TrafficLightSlot` 在非 macOS 平台返回 null，Windows 由 WindowBar 自绘按钮承担窗口控制，互不干扰。
- 浏览器 dev（无 Tauri runtime）下红绿灯不存在，胶囊底座作为静态装饰仍渲染，不影响布局。
