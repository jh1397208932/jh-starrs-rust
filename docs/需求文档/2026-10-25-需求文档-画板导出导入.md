# 画板导出与导入需求（PNG / SVG / Excalidraw）

- 日期：2026-10-25
- 关联设计：`docs/设计/2026-10-25-画板导出导入-001/说明.md`
- 关联任务：`docs/开发任务清单/2026-10-25-任务-001/`
- 前序能力：`docs/需求文档/2026-10-24-需求文档-画板功能.md`、`docs/需求文档/2026-10-24-需求文档-导出导入与页头细化.md`

## 1. 背景与目标

画板目前只有 Excalidraw 自带的「保存到…」与整库导出中的元数据占位，不能在应用内选择 PNG/SVG/Excalidraw 格式，也不能把画板作为可再导入的内容带入知识库。

目标：

1. 画板页头提供「导出」菜单，可选 PNG、SVG、Excalidraw 源文件，并落到用户选择的路径。
2. 左下角「更多 → 全部导出」纳入画板：每个画板导出到同名文件夹，默认同时生成 `.excalidraw`、`.png`、`.svg`，并包含图片与文件附件；文档仍按用户选择的 Markdown/HTML/Word/PDF 格式导出。
3. 「导入文档」支持 `.excalidraw`，创建画板节点并恢复可编辑场景；内嵌图片与 Starris 导出的附件映射可用。

## 2. 范围

### 2.1 包含

- 画板页头导出菜单：PNG / SVG / Excalidraw 三选一。
- 画板级 PNG/SVG 使用 Excalidraw 官方导出工具，保留图片与文件卡片外观。
- 画板级 `.excalidraw` 内嵌图片 `files`；文件卡片仅保留图元元数据。
- 全部导出：画板使用同名文件夹承载多格式与附件；manifest 与导出说明列出画板目录。
- 全部导出中的 PNG/SVG 由桌面端渲染后写入后端规划的路径。
- 导入 `.excalidraw`：单文件与目录批量导入均可，遵循目标文件夹与目录层级设置。
- 导入图片：`files` 中的 dataURL 上传为全局对象，图元 `fileId` 改写为 object_id。
- 导入 Starris 画板包内的 `attachments.json`：恢复文件卡片附件。

### 2.2 不包含

- 画板历史版本、多人协作、Excalidraw+ 链接。
- 将文件卡片附件嵌入单文件 `.excalidraw`（单文件导出只保留图元；需保留附件时使用全部导出）。
- 在 Rust 端重写 Excalidraw 渲染器；PNG/SVG 一律由前端官方导出工具生成。
- 表格/流程图的导出与导入。

## 3. 输出结构

```text
<知识库>/
├── 设计/
│   └── 首页.md                     # 文档按所选格式
├── 架构画板/                       # 画板同名文件夹
│   ├── 架构画板.excalidraw
│   ├── 架构画板.png
│   ├── 架构画板.svg
│   ├── attach/
│   │   ├── 架构图.png
│   │   └── 需求.pdf
│   └── attachments.json            # objectId → attach/<文件> 映射
├── _attachments/                   # 未被文档/画板引用的附件
├── manifest.json
└── 导出说明.md
```

- 同名画板自动加序号目录，避免覆盖。
- 图片在 `.excalidraw` 的 `files` 中以 dataURL 内嵌，同时复制原始文件到 `attach/`。
- 文件卡片不进入 `files`，其 object_id 由 `attachments.json` 映射到 `attach/` 文件。
- PNG/SVG 默认白色导出背景，不套用深色 UI 反色，保证文档/分享场景可读。

## 4. 交互与状态

- 画板页头「导出」：下拉选择 PNG / SVG / Excalidraw；选择后弹系统保存对话框；导出中禁用菜单并显示忙碌态；成功/失败使用全局 toast。
- 全部导出弹窗：文档格式仍为 Markdown/HTML/Word/PDF 单选；新增文案说明画板固定导出三种格式并带附件。导出中显示忙碌；完成后关闭并 toast 文件数/附件数。
- 导入弹窗：文件过滤器包含 `.excalidraw`；说明文案覆盖画板；结果计数使用「项」。目录导入保留层级。
- 空白画板：全部导出写 `.excalidraw`；PNG/SVG 跳过并记录警告，不阻断其他内容。
- 单板 `.excalidraw` 含文件卡片：导出成功但提示「文件卡片附件请使用全部导出保留」。

## 5. 规则与边界

1. 单板 PNG/SVG 导出使用当前画布实时内容；`.excalidraw` 使用当前场景与图片。
2. 全部导出先 flush 当前画板，再从数据库读取各画板场景，保证与文件树一致。
3. `.excalidraw` 解析失败、缺少 `elements` 数组或非法 JSON 时，导入失败并给出可读错误；不创建空画板。
4. 图片 dataURL 非 base64、MIME 非图片或超过 64 MiB 时跳过该图片并记录警告；其余图元继续导入。
5. `attachments.json` 中的路径必须是相对路径且不得包含 `..`；越界条目跳过并警告。
6. 导入画板失败时删除已创建的节点，避免留下空壳。
7. 全部导出的画板引用附件不进入 `_attachments/`，避免重复。
8. 写入导出文件仅接受绝对路径；覆盖必须显式允许。

## 6. 验收标准

1. 画板导出 PNG：生成可打开的 PNG，包含矩形与便签；SVG：生成可打开的 SVG；Excalidraw：生成可被本应用重新导入的 JSON。
2. 全部导出（Markdown）：画板目录同时含 `.excalidraw`、`.png`、`.svg`、`attach/` 与 `attachments.json`；manifest 列出画板；未引用附件仍导出。
3. 导入标准 `.excalidraw`（含内嵌图片）：文件树出现画板节点，打开后图元与图片可见，图片文件成为全局对象。
4. 导入带 `attachments.json` 的 Starris 画板包：文件卡片保留并在附件库中有对应对象。
5. 目录批量导入含 `.excalidraw`：层级与目标文件夹正确。
6. 门禁与测试：Rust 集成测试、`cargo fmt/clippy/test`、`npm check/typecheck/build` 全绿；真机截图/日志证据齐全。
