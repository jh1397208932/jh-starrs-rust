# 需求文档 · 界面国际化（R14）

| 项 | 内容 |
|---|---|
| 日期 | 2026-10-25 |
| 关联调研 | `docs/产品功能调研/2026-10-25-缺失功能与需求调研-001/调研报告.md`（R14） |
| 目标 | 提供简体中文 / English 两种界面语言，切换即时生效并持久化 |
| 状态 | 已实现，待真机语言用例回归 |

## 1. 范围

- 设置 → 通用 → 界面语言：简体中文 / English。
- 应用界面文案（侧栏、顶栏、文件树、编辑器、画板、附件、搜索、设置、所有弹窗、空态、toast）。
- 后端错误消息与原生菜单标签。
- Excalidraw 内置 UI 语言。
- 语言持久化到全局记忆 `appearance.locale`。

## 2. 非目标

- 第三种语言、RTL、语言包市场。
- 翻译用户正文、文件名、模板内容。
- 日期/数字的本地化格式（继续使用 `YYYY-MM-DD HH:mm`，避免布局回归）。

## 3. 规则

- 默认 `zh-CN`；英文缺失时回退中文，不允许出现空白文案。
- 文案键为中文源文案；变量用 `{name}` 插值。
- `t("...")` 在事件/服务中直接调用；React 组件通过 `useI18n()` 订阅语言变化，切换后整棵界面即时刷新。
- 组件内禁止自建第二套文案映射；共享文案集中在 `src/lib/messages/en-US.ts`。
- 原生菜单在启动时按持久化语言构建；`memory_save` 写入 `appearance.locale` 时重建菜单。
- Excalidraw `langCode` 随语言切换为 `en` / `zh-CN`。
- 覆盖探针：`scripts/check-i18n.mjs`（未包裹中文）、`scripts/check-i18n-keys.mjs`（缺失英文键）。

## 4. 验收

- 设置中切到 English：设置导航、侧栏、更多菜单、页面标题、对话框立即变英文；切回中文恢复。
- 重启后保持上次语言。
- 未包裹中文清单仅剩数据键/逻辑匹配字符串/资源路径；`t()` 键缺失英文为 0。
- 中文默认布局与既有 E2E 文案不变。
- Rust 99 项、前端 typecheck/build/biome、许可证门禁通过。
- 真机 `12-language` 用例通过（需独占窗口，待执行）。

## 5. 风险

- 英文文案长度不同可能导致部分窄按钮换行；布局沿用自动换行与 truncate，需真机截图复核。
- 后端错误消息通过中文源键映射；未收录的新错误会回退中文，需随新增错误同步词典。
- 系统预定义菜单项在不同 macOS 版本上的默认本地化不一致，已改为显式中英文标签。
