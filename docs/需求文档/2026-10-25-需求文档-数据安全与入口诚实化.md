## 1. 背景与目标

### 1.1 背景

当前版本的功能骨架已经完整，但调研发现四类问题会在正常使用路径上造成错误预期或数据损失：

1. **关闭窗口不落盘**：文档自动保存是 1 秒防抖，切换文档/标签/工作区前会 flush；但窗口关闭直接调用 `window.close()`，没有拦截与保存，最后一次输入可能丢失。
2. **升级无恢复点**：打开旧工作区时直接执行 schema 迁移（当前 v10），迁移前没有数据库副本；迁移失败或磁盘异常时缺少可回滚文件。
3. **文档无冲突检测**：画板保存有 `base_version`，文档保存只有 `node_id + document`；两个应用实例打开同一工作区时，后保存者静默覆盖先保存者。
4. **入口承诺与实际能力不一致**：搜索、快速跳转、打印、放映、表格/流程图、语言切换、相关推荐等入口没有真实闭环；其中相关推荐是假数据、语言选择只改本地 state，用户会误以为已经生效。

本轮目标不是一次性实现所有缺失功能，而是先把"数据不能丢、入口不说谎"这条底线补齐。检索、存储闭环、备份/恢复、模板/历史等能力按调研报告分批实施。

### 1.2 目标

- 用户通过红绿灯、`⌘Q` 或菜单退出时，应用先落盘当前文档；保存失败则取消退出并提示重试。
- 打开旧 schema 的工作区前，自动复制一份数据库到 `db/backups/`；复制失败则拒绝迁移；保留最近 3 份。
- 文档保存携带版本号；版本不一致时返回冲突，前端提示重新加载，不静默覆盖。
- 所有已出现但未实现的入口，要么真实可用，要么明确禁用/标注"即将推出"；移除假数据与无效本地 state。
- 维护任务删除 big 对象时与同哈希上传互斥，避免"DB 有行、磁盘无文件"。

### 1.3 术语

| 术语 | 含义 |
|---|---|
| flush | 立即把当前编辑器/画板的 dirty 内容写入 Rust/SQLite，不等防抖计时器 |
| 退出请求 | Tauri `RunEvent::ExitRequested`，包括 `⌘Q`、菜单退出、系统退出等 |
| 窗口关闭请求 | Tauri `WindowEvent::CloseRequested` / 前端 `onCloseRequested`，包括红绿灯、`⌘W` 关闭窗口 |
| baseVersion | 前端加载/上次保存后拿到的文档版本号；保存时回传，用于乐观并发控制 |
| 旧库 | `PRAGMA user_version` 小于当前 `SCHEMA_VERSION` 且大于 0 的工作区数据库 |
| 入口诚实化 | 界面上的入口必须对应真实能力；未实现时禁用或明示"即将推出"，禁止假数据 |

### 1.4 用户角色与场景

- **本地单用户**：在自己的 Mac 上写文档、画板，关闭应用后下次继续。
- **多实例用户**：误开两个星屿窗口，指向同一个工作区；两个窗口编辑同一文档。
- **升级用户**：从旧版本升级后第一次打开已有工作区。
- **首次/低频用户**：看到顶栏搜索、打印、语言、相关推荐等入口，期望它们能工作。

## 2. 范围

### 2.1 本轮范围

| 编号 | 能力 | 说明 |
|---|---|---|
| R01 | 关闭/退出前保存 | 窗口关闭、`⌘Q`、应用退出统一走保存守卫 |
| R02 | 维护与上传互斥 | 把 big 对象 unlink 放进存储锁内，补并发测试 |
| R03 | 迁移前备份 | 旧库升级前复制 DB，保留 3 份，失败中止 |
| R22 | 文档冲突检测 | 新增 `doc_version`，保存时校验；前端冲突提示 |
| 批次 0 | 入口诚实化 | 假数据、无效 state、未实现入口统一处理 |

### 2.2 明确不做

- 不做系统级全局热键；不做云同步/协作；不做表格/流程图编辑器本体；不做反向链接/相关推荐算法；不做国际化。
- 不改变附件生命周期、引用表、回收站与 pack 压缩规则。
- 不改变画板 `base_version` 语义，不把画板与文档版本合并。
- 不删除用户已有节点或附件来"清理"假数据；只改展示与入口。
- 不引入新的前端 UI 框架；不修改 Excalidraw 源码。
- 不承诺 `⌘Q` 在所有系统级强制退出（如 `kill -9`、系统关机）下都能保存；只覆盖应用可拦截的退出路径。

### 2.3 前置条件与假设

- Tauri 版本 2.12.x；前端 `@tauri-apps/api` 2.12.x（以锁文件为准）。
- 工作区数据库为 SQLite WAL 模式，单连接由 `AppState` 持有；同一时刻的写操作由连接串行化。
- 窗口关闭与应用退出都发生在主窗口；当前没有多窗口业务。
- 迁移备份只针对"已有数据库且 `0 < user_version < SCHEMA_VERSION`"；新建库不备份。
- 文档版本号只保护文档正文；重命名、收藏、移动不增加文档版本。

## 3. 用户故事与业务规则

### 3.1 R01 关闭/退出前保存

**用户故事**：作为用户，我在文档末尾输入一句话后立刻按红绿灯或 `⌘Q`，重新打开应用时这句话仍在。

**规则**：

1. 前端在主界面挂载 `onCloseRequested` 监听；收到事件后先 `event.preventDefault()`，再调用 `flushActivePersistence()`。
2. `flush` 成功：调用 Rust `app_confirm_exit`，由 Rust 设置"允许退出"标志并退出应用；不再重复询问。
3. `flush` 失败：不退出，窗口保持打开，toast 提示"文档未保存，已取消关闭"；用户可以重试保存或再次关闭。
4. `⌘Q` 与菜单退出：Rust 在 `RunEvent::ExitRequested` 中拦截，向前端发送 `starris://exit-requested`；前端执行同一套 flush + `app_confirm_exit`。
5. 没有活动文档、没有 Tauri 运行时（浏览器 dev）或 flush 本身抛错：按"无可保存内容"处理，允许退出/关闭；错误写日志，不阻塞用户。
6. 画板复用同一 `flushActivePersistence`，同时 flush 文档与画板（当前模块已按活动标签分派）。
7. 防重入：保存/退出过程中再次触发关闭，忽略重复请求；失败后允许再次尝试。
8. 超时：前端 flush 超过 8 秒仍未完成，提示"保存超时，已取消关闭"，不退出；避免无限等待。

### 3.2 R03 迁移前备份

**用户故事**：作为升级用户，我打开旧工作区时，应用先自动备份数据库；即使迁移失败，我也能找回原文件。

**规则**：

1. `db::workspace::open` 在打开已有文件后读取 `PRAGMA user_version`；仅当 `version > 0 && version < SCHEMA_VERSION` 时执行备份。
2. 备份前执行 `PRAGMA wal_checkpoint(TRUNCATE)`，确保 WAL 内容落主库；随后 `fs::copy` 到 `db/backups/workspace-v{oldVersion}-{timestamp}.sqlite3`。
3. 备份目录不存在时创建；保留最近 3 份（按文件名时间戳排序），删除更旧的备份；删除失败只记日志，不阻塞迁移。
4. 备份复制失败：返回错误，不执行迁移；用户看到"数据库备份失败，未升级工作区"。
5. 备份成功：继续原迁移事务；迁移失败时数据库保持不变（事务回滚），备份仍保留。
6. 新建数据库（version=0 且文件不存在）与已是最新版本不备份。
7. 日志只写备份文件名、版本与字节数，不写完整用户路径。
8. 备份文件不参与 `is_valid_workspace` 判定，不会被误认为工作区数据库。

### 3.3 R22 文档冲突检测

**用户故事**：作为多实例用户，我在两个窗口编辑同一文档时，后保存的窗口收到冲突提示，而不是静默覆盖。

**规则**：

1. 工作区 schema 升到 v11：`node` 增加 `doc_version INTEGER NOT NULL DEFAULT 0`；迁移只 `ALTER TABLE`，不改既有数据。
2. `doc_load` 返回 `version`；前端保存时回传 `baseVersion`。
3. `doc_save` 在写事务内比较 `node.doc_version` 与 `baseVersion`；不一致返回 `AppError::conflict("文档已在别处更新，请重新加载")`。
4. 保存成功后 `doc_version = doc_version + 1`，返回新 `version`；前端更新基线。
5. 文档首次保存时 `doc_version=0`，`baseVersion=0`；旧前端不传 `baseVersion` 时按 0 处理（仅在过渡期，任务完成后前端必须传）。
6. 冲突不自动合并、不覆盖；前端保留用户当前编辑内容，提供"重新加载"按钮；重新加载前如需保留本地内容，由用户自行复制（本轮不做自动合并）。
7. 重命名、收藏、移动、附件引用同步不增加 `doc_version`；只有正文保存增加。
8. 画板继续使用 `board_scene.scene_version`，不迁移到 `node.doc_version`。

### 3.4 批次 0 入口诚实化

**规则**：

| 入口 | 处理 |
|---|---|
| 顶栏搜索 | 在 R04 搜索实现前，按钮禁用并显示"搜索即将推出"；不再弹 mock toast；快捷键设置中保持"即将推出" |
| 快速跳转 | 保持不可用；主界面不再绑定 mock 处理器，避免按了没反应 |
| 打印 | 在 R12 实现前，页头打印按钮禁用并显示"打印即将推出"；不再弹 mock toast |
| 画板放映 | 保持不可用；快捷键设置显示"即将推出"；主界面不弹 mock |
| 表格/流程图 | 创建弹窗不再提供这两个类型；已存在的节点仍可打开占位页并删除；不删除用户数据 |
| 模板库/备份与恢复 | 保持菜单项 + "即将推出"标记；不新增假页面 |
| 云同步 | 保持"即将推出"文案 |
| 界面语言 | 未接 i18n 前禁用选择器，文案"其他语言即将推出"；不再保留可切换的本地 state |
| 相关推荐 | 移除 `MOCK_RELATED` 假数据；"相关"tab 显示空态"暂无推荐"；不展示不存在的文档 |
| 收藏空页 CTA | 不再走 mock；改为提示"打开文档后按 ⌘D 收藏"，不显示可点击的假按钮 |
| 未使用的 mock 常量 | 删除 `MOCK_OUTLINE`、`MOCK_RELATED`；若文件为空则删除文件 |

**通用规则**：

- 未实现入口必须有明确的禁用态或"即将推出"文案，不能点击后无反馈。
- 删除假数据时不能删除真实节点/附件；只改展示。
- 已存在的表格/流程图节点不自动删除；只停止新建。
- 所有新增/修改文案必须简短，不解释实现原理。

### 3.5 R02 维护与上传互斥

**用户故事**：作为用户，我在清理孤儿对象的同时再次上传同一文件，不会得到"附件内容不存在"的坏对象。

**规则**：

1. 维护任务在持有存储锁期间完成 big 对象 `unlink`；pack compaction 仍在锁外执行（它会自行获取锁）。
2. 删除前再次确认 `attachment_blob` 中该 hash 仍不存在；若已被并发上传写入，跳过 unlink。
3. 若 unlink 失败且错误不是 `NotFound`，记录日志并把 blob 留待下一轮维护；不把失败当成成功。
4. 增加并发测试：在同一 hash 上反复上传 + 维护，所有上传完成的附件都能通过 `attachment_verify` 读取。
5. 不改变小对象 pack 的追加/压缩语义；不改变孤儿宽限期与回收站保留期。

## 4. 交互流程与页面状态

### 4.1 关闭/退出

| 状态 | 界面表现 |
|---|---|
| 正常关闭 | 无额外弹窗；保存胶囊最后显示"已保存"，随后窗口关闭 |
| 保存中 | 窗口保持打开，标题栏/保存胶囊显示"保存中…"；禁止重复关闭 |
| 保存失败 | 窗口保持打开；toast"文档未保存，已取消关闭"；保存胶囊显示失败，可重试 |
| 超时 | 窗口保持打开；toast"保存超时，已取消关闭" |
| 无活动文档 | 直接退出，无提示 |
| 浏览器 dev | 无法注册 Tauri 监听时静默降级；不阻塞页面 |

### 4.2 迁移备份

| 状态 | 界面表现 |
|---|---|
| 旧库升级成功 | 无额外弹窗；日志记录备份文件名；工作区正常打开 |
| 备份失败 | 打开工作区失败，toast"数据库备份失败，未升级工作区"；原库不迁移 |
| 迁移失败 | 打开工作区失败；原库事务回滚；备份保留 |
| 备份清理失败 | 不阻塞；日志记录；下次再清理 |

### 4.3 文档冲突

| 状态 | 界面表现 |
|---|---|
| 正常保存 | 保存胶囊"已保存"；版本号递增；无提示 |
| 冲突 | 保存胶囊"冲突，点击重试"；toast"文档已在别处更新，请重新加载"；编辑器保留当前内容 |
| 重新加载 | 重新拉取文档与版本；未保存内容丢失前需用户确认（本轮先提示"重新加载会丢失当前修改"） |
| 网络/IPC 失败 | 沿用现有保存失败状态，可重试 |

### 4.4 入口诚实化

- 禁用按钮使用 `disabled` + `aria-disabled`，tooltip 写明"即将推出"。
- 不显示可点击但无行为的按钮。
- 假数据移除后，"相关"tab 仍可打开，显示空态；不隐藏 tab 以免布局跳动。

### 4.5 流程图

见 `docs/设计/2026-10-25-数据安全与入口诚实化-001/原型/data-safety.html`：上排为关闭保存（用户 → 前端拦截 → flush → Rust 确认 → 退出），下排为旧库迁移（打开旧工作区 → 备份 → 迁移）；失败路径以边标签"成功才继续；失败留在窗口"和"成功才迁移；失败中止"表达。

## 5. 数据定义与迁移

### 5.1 schema v11

```sql
ALTER TABLE node ADD COLUMN doc_version INTEGER NOT NULL DEFAULT 0;
```

- 仅文档节点使用；文件夹/画板/附件节点保持 0。
- 不新增索引：保存按主键 `id` 更新，无需额外索引。
- 迁移版本：`SCHEMA_VERSION = 11`；迁移在事务中执行，失败回滚。
- v1-v10 数据无需回填；默认 0 即合法基线。

### 5.2 文档 IPC 变更

```text
DocLoadResult += version: number
DocSaveInput  += baseVersion: number
DocSaveResult += version: number
```

- Rust `SaveDocumentInput`：`base_version: i64`（camelCase 序列化为 `baseVersion`）。
- Rust `DocLoadResult` / `DocSaveResult`：`version: i64`。
- 前端 `src/types/document.ts`、`src/api/document.ts`、`useDocumentPersistence` 同步。
- 旧数据/旧测试调用必须显式传 0；不允许省略后静默跳过校验（除 API 反序列化的过渡默认 0 外）。

### 5.3 备份文件

```text
<workspace>/db/backups/workspace-v9-20261025T140000Z.sqlite3
```

- 文件名时间戳使用 UTC 毫秒或秒；只含 ASCII。
- 备份内容为 checkpoint 后的主库文件；不复制 WAL/SHM。
- 保留 3 份；按文件名排序删除最旧。

### 5.4 性能与安全

- 关闭 flush 最多 8 秒；不阻塞 Rust 主线程（前端 await IPC）。
- 迁移备份是单次文件复制，在打开工作区时执行；大库可能耗时，日志记录耗时；不做后台迁移（避免用户误操作）。
- 备份文件可能包含用户全部数据，权限沿用工作区目录；不写入日志路径。
- 冲突检测只比较整数，无额外查询；保存事务内读取 `node` 一次。
- 不引入新依赖。

## 7. 未决问题与风险

1. **`⌘Q` 的拦截范围**：Tauri `ExitRequested` 能拦截菜单/系统退出，但 `kill -9`、系统强制关机不可拦截。本轮只承诺可拦截路径，UI 不承诺"任何情况下不丢字"。
2. **窗口关闭语义**：当前为单窗口应用；关闭窗口后是否退出由 Tauri 默认行为决定。本轮统一走 `app_confirm_exit` 退出应用；若后续改为"关窗不退出"，需要重新设计 Dock/菜单行为。
3. **迁移备份空间**：备份是完整 DB 副本，工作区很大时占空间。保留 3 份是保守默认；后续可加"备份大小/剩余空间"提示。
4. **冲突后的自动合并**：本轮不做；冲突时保留用户内容并提供重新加载。若要自动合并，需引入块级三路合并，成本高。
5. **多实例**：本轮先做文档版本冲突；单实例插件是否引入需按 AGENTS §16 复核许可与体积。若用户强需求"第二次启动聚焦已有窗口"，再单独加插件。
6. **入口诚实化可能让用户觉得能力变少**：这是有意的；比展示假数据更可信。表格/流程图已存在的节点不删除。
7. **R02 竞态**：先按锁内删除修复；若并发测试仍能复现，再考虑 tombstone/临时文件名方案。
8. **版本号与历史版本**：`doc_version` 只用于并发控制，不是历史版本；文档历史是 R10，另行实现。
