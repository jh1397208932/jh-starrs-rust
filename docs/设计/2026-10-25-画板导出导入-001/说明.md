## 1. 分工

| 能力 | 执行侧 | 原因 |
|---|---|---|
| 读取画板场景/附件、写 `.excalidraw`、复制附件、manifest | Rust | 数据权威、文件系统与对象库都在后端 |
| PNG / SVG 渲染 | 前端（Excalidraw `exportToBlob` / `exportToSvg`） | 渲染器是 JS 实现；Rust 重写会丢失字体、绑定、嵌入等保真度 |
| 写前端渲染结果 | Rust 新命令 `export_write_file` | 统一文件系统入口，限制绝对路径与显式覆盖 |
| 单板导出编排 | 前端 BoardView | 使用实时场景与 `getFiles()` |
| 全部导出编排 | 前端控制层 + 后端 | 后端先建目录/源文件/附件，前端补 PNG/SVG |
| 导入 `.excalidraw` | Rust | 创建节点、上传对象、改写 fileId、写 board_scene 属持久化权威 |

## 2. 数据流

```text
单板导出
点击页头导出 → 保存对话框选路径
  ├─ png:  api.getSceneElements/getAppState/getFiles → exportToBlob → base64 → export_write_file
  ├─ svg:  同上 → exportToSvg → XMLSerializer → base64 → export_write_file
  └─ excalidraw: serializeAsJSON(elements, appState, files, "local") → UTF-8 → base64 → export_write_file

全部导出
Dialog 选文档格式 + 目录 → flush 当前画板 → export_knowledge_base
  Rust: 遍历树
    ├─ 文档：按所选格式写文件 + attach/
    ├─ 画板：建同名目录；写 <name>.excalidraw、复制引用附件、attachments.json；
    │        返回 BoardExportTarget { dirPath, pngPath, svgPath, ... }
    └─ 未引用附件：_attachments/
  前端: 对每个 BoardExportTarget
    ├─ board_load → elements/appState/files
    ├─ exportToSvg / exportToBlob（白底、非深色反色、padding 16）
    └─ export_write_file 写入后端规划的 pngPath / svgPath
  合并文件清单与警告 → toast

导入 .excalidraw
ImportDialog 选择文件/目录 → import_documents
  Rust:
    ├─ 创建 type=3 画板节点
    ├─ files[fileId] 的 dataURL → attachment_service::upload_bytes
    ├─ image.fileId := object_id
    ├─ 若同目录有 attachments.json：上传文件卡片附件并改写 customData.objectId
    └─ board_service::save(baseVersion=0)
```

## 3. 关键契约

### 3.1 全部导出新增返回

```rust
BoardExportTarget {
  node_id, title, dir_path, base_name,
  excalidraw_path, png_path, svg_path,
}
ExportResult { .., boards: Vec<BoardExportTarget> }
```

### 3.2 写文件命令

```rust
ExportWriteFileInput { path: String, data_base64: String, overwrite: bool }
ExportFileDto { path, kind = "board-image" | "board" }
```

- `path` 必须为绝对路径；父目录自动创建。
- 先写同目录临时文件再 `rename`，避免半成品。
- 解码后上限 128 MiB；超过报校验错误。

### 3.3 `.excalidraw` 源文件

```json
{
  "type": "excalidraw",
  "version": 2,
  "source": "starris",
  "elements": [ ... ],
  "appState": { "viewBackgroundColor": "#ffffff", "gridModeEnabled": false },
  "files": { "<object_id>": { "mimeType": "image/png", "dataURL": "data:image/png;base64,...", "created": 0 } }
}
```

- 仅 embed `mimeType` 为 `image/*` 且可按 20 MiB 读取的对象；失败或超限只复制文件并警告。
- `attachments.json`：

```json
{
  "type": "starris-board-attachments",
  "version": 1,
  "attachments": [
    { "objectId": "...", "name": "需求.pdf", "mime": "application/pdf", "size": 123, "file": "attach/需求.pdf" }
  ]
}
```

### 3.4 导入解析

- 接受 `{type:"excalidraw", elements, appState, files}`；也接受仅含 `elements` 的 JSON。
- `elements` 必须是数组；`appState` 非法时退回 `{}`。
- `files[fileId].dataURL` 必须匹配 `data:<mime>;base64,<payload>`。
- `attachments.json` 的 `file` 禁止绝对路径与 `..`；无法读取时该条只警告。
- 导入后 `board_scene` 版本 1；删除节点即级联删除场景，不删除全局对象。

## 4. 失败与边界

| 场景 | 行为 |
|---|---|
| 单板 PNG 渲染失败 | 不写文件，destructive toast；不影响画板 |
| 单板 `.excalidraw` 存在文件卡片 | 导出成功，提示附件需用全部导出 |
| 全部导出某画板 PNG/SVG 失败 | 保留 `.excalidraw` 与附件，warning 汇总到结果与 toast |
| 空白画板 | `.excalidraw` 成功；PNG/SVG 跳过并警告 |
| 画板图片对象缺失 | `.excalidraw` 不写该 files 条目，复制缺失记录 warning |
| 导入 JSON 损坏/无 elements | 失败，不创建节点 |
| 导入图片上传失败 | 保留原 fileId 并警告；其余图元继续保存 |
| 写文件路径非绝对/过大 | 校验失败，不落盘 |

## 5. 测试

- Rust：
  - 全库导出：画板目录、`.excalidraw` 内嵌图片、附件复制、`attachments.json`、manifest、未引用附件不重复。
  - 写文件：绝对路径、覆盖开关、base64 解码。
  - 导入：标准 `.excalidraw`（含图片）创建画板/上传对象/重写 fileId；目录层级；损坏文件失败且不建节点。
- 前端：
  - 单板三格式导出（PNG 可打开、SVG 可打开、`.excalidraw` 可再导入）。
  - 全部导出画板三格式 + 附件。
  - 导入 `.excalidraw` 后文件树/画板打开。
