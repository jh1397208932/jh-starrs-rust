# 画板 UI 风格与主题适配设计（审阅稿）

- 日期：2026-10-24
- 状态：已实现并完成真机验证（2026-10-24）
- 关联目标：画板功能第 1 项「功能、弹窗、按钮、交互、UI 风格适配，不能有功能缺失或按钮遗漏」
- 依赖版本：`@excalidraw/excalidraw@0.18.1`（仓库当前安装版本）
- 视觉权威：`UI-SPEC.md`、`src/styles/tokens.css`
- 现状文件：`src/features/board/components/BoardView.tsx`（54 行，默认 Excalidraw UI + mock 图元）

---

## 1. 结论先行

**不改 Excalidraw 的功能组件树，只换外观与壳层。**

Excalidraw 自带完整的工具栏、属性面板、菜单、弹窗、右键菜单、命令面板、搜索、帮助、导出、统计等能力。逐个重写这些组件是“按钮遗漏”的最大来源。因此本方案：

1. 保留 Excalidraw 内置 UI 与交互逻辑。
2. 用作用域限定的 CSS 变量层把它的表面色、文字色、边框、圆角、阴影、字号、控件尺寸映射到 Starris 令牌。
3. 只在两个位置新增/替换：
   - 画板页壳层：面包屑 + 保存状态 + 画布容器；
   - 与本地桌面应用冲突的“外部服务动作”：改为本地等价动作或明确隐藏。
4. 主题切换通过 CSS 变量即时生效；`theme={mode}` 继续负责 Excalidraw 的明暗渲染（含画布反色 filter）。
5. 用“功能清单 × 真实截图 × 逐项点击”做不遗漏验收，而不是只看代码。

本方案不涉及保存表结构、组件库存储；这两块分别按已提交的 v8 存储设计和后续 v9 设计推进。

| 主菜单/画布动作含 Open、Save、Export JSON、Export image、Canvas background、Reset、Clear、Live collaboration、Toggle theme、Language、Zen、Grid、Snap、Stats、Command palette、Find on canvas 等 | `buttons`、`labels`、`commandPalette`、`search` 分组 |

| Excalidraw 的 `AppState` 默认 `viewBackgroundColor` 是白色；深色主题靠 canvas CSS filter（`invert(93%) hue-rotate(180deg)`）反色，而不是改背景色值 | `dist/dev/chunk-*.js` 中 `getDefaultAppState()` 与 `THEME_FILTER` |
| 官方 `cleanAppStateForExport()` 只保留背景/网格四项；视口需宿主自行保存 | 本仓库类型与官方 utils 文档（存储设计已引用） |
| Excalidraw 的 UI 颜色几乎都走 CSS 变量 | `dist/prod/index.css` 中 `--island-bg-color`、`--color-primary`、`--button-*`、`--sidebar-*` 等 |

因此主题适配的技术路径是 **CSS 变量覆盖 + 少量壳层**，而不是替换 Excalidraw 组件。深色画布不能直接把 `viewBackgroundColor` 改成 `var(--background)`（canvas 不解析 CSS 变量，且会破坏 Excalidraw 的 filter 反色逻辑）。

### 4.4 文件与附件（2026-10-24 追加）

画板必须支持把任意文件粘贴/拖入画布，并能插入全局附件库中的既有附件：

| 输入 | 画布表示 | 数据 |
|---|---|---|
| 图片文件（PNG/JPEG/GIF/WebP/SVG/BMP） | Excalidraw 原生 image 元素 | `fileId = 全局 object_id`；加载时按对象 id 回填 dataURL |
| 非图片文件（PDF/DOCX/XLSX/ZIP/MD…） | 文件卡片图元组 | `customData.objectId` + `name` + `mime` + `size`；`link = attachment://<object_id>` |
| 已有附件（从附件库插入） | 图片走 image；其它走文件卡片 | 只引用已有 `object_id`，不复制对象 |

**文件卡片造型**（在画布内用矢量图元绘制，不额外创建对象）：

```text
┌──────────────────────────┐
│  ╭────╮   需求文档.pdf   │
│  │PDF │   1.2 MB · PDF   │
│  ╰────╯                  │
└──────────────────────────┘
```

- 左侧为折角文件页图标 + 扩展名徽标，右侧为文件名（最多两行）与大小/类型。
- 类型色沿用文档附件图标的语义：PDF 危险色、文档/表格/演示主色系、图片金色、压缩金色、音视频主色、代码/文本 accent、其它 muted。
- 画布颜色必须用具体色值（Excalidraw 不接受 CSS 变量）；取插入时主题的令牌计算值，保存为用户内容，不随主题二次变化。
- 双击卡片或点击 `attachment://` 链接时，通过全局附件下载/打开；对象已删除时提示“附件已删除”，卡片保留。
- 卡片是普通图元组，可被选择、移动、复制、删除；不引入第二套画布交互。

**粘贴/拖放**：

- 图片：Excalidraw `generateIdForFile` → 全局对象上传 → 用返回的 `object_id` 作为 `fileId`。
- 非图片：在捕获阶段拦截粘贴/拖放 → 全局对象上传 → 在指针位置插入文件卡片。
- 多个文件按粘贴顺序排列，避免完全重叠。
- 上传失败：不插入半成品，toast 提示；不阻塞后续文件。

**插入入口**：板页头右侧增加「插入附件」按钮（或工具菜单中的同名项），打开全局附件选择器；避免与 Excalidraw 自带 Library/图片按钮混淆。

**验收**：

1. 粘贴图片、PDF、ZIP，分别出现图片/带图标卡片；
2. 保存并重启后仍存在；图片 dataURL 正常，卡片打开正常；
3. 从附件管理删除对象后，画板显示缺图/提示附件已删除，不崩溃；
4. 插入已有附件不产生新对象；自动保存不重复上传；
5. 文件卡片的类型图标、文件名、大小不溢出，缩放到 50% 仍可辨识扩展名。

## 5. 主题适配

### 5.1 主题模型

- 9 套主题 × 明/暗两种模式，唯一来源是 `<html data-theme data-mode>` 与 `tokens.css`。
- 画板容器只引用 `var(--...)`，不写死色值。
- `theme={mode}` 传给 Excalidraw，负责它自己的明暗资源（图标、遮罩、深色 filter）。
- 九套主题的差异由 `--primary`、`--accent`、`--accent-foreground`、`--card`、`--background` 等变量自动带出，无需为每个主题写一份画板 CSS。

### 5.2 深色画布的事实与处理

Excalidraw 默认 `viewBackgroundColor` 为白色；深色模式通过 canvas 的 `filter: invert(93%) hue-rotate(180deg)` 反色（见 `THEME_FILTER`）。这意味着：

- **不要**把 `viewBackgroundColor` 改成 `var(--background)`：canvas fillStyle 只接受具体颜色，CSS 变量无效。
- **不要**给画布容器再叠一层深色背景来“配合主题”，会与 filter 冲突并改变用户图元颜色。
- 保持 Excalidraw 的 filter 机制；画布周边 chrome 用 Starris 令牌。
- 用户主动选择画布背景色时，照常保存；主题切换不覆盖用户自定义背景。

### 5.5 字体与许可证

- Excalifont 在 npm 包内许可不明确，现有 `vite.config.ts` 字体守卫会在构建时剔除；**不得为了外观重新引入**。
- UI 字体走 `--font-ui`；画布手写字体继续使用 Excalidraw 允许随包的字体集合。
- 构建后检查 `dist` 字体白名单与 `npm run check:licenses`，确保视觉调整没有绕过字体门禁。

## 6. 画板页壳层

建议在内容区内部增加一条 **36–40px 的板页头**，然后让 Excalidraw 填满剩余高度：

```text
┌ 内容区 ───────────────────────────────────────────────┐
│ 知识库 › 画板标题        [已保存]  [组件库] [导出]     │ ← 板页头（36–40px）
├───────────────────────────────────────────────────────┤
│ Excalidraw（自带左侧工具条、右侧栏、底部缩放、主菜单） │
└───────────────────────────────────────────────────────┘
```

- 左侧：面包屑，与文档页头同构。
- 右侧：保存状态胶囊；组件库入口是否放这里待定（需求要求左下角「更多」也有入口，可两处都有但只保留一个权威入口）。
- 画板页头不重复 Excalidraw 的导出/菜单按钮；避免两个导出入口。
- Zen/全屏模式时板页头隐藏，把画布交给 Excalidraw；保存状态用短暂 toast 或右上浮层提示。
- 若最终选择“浮层页头”，需保证不遮挡 Excalidraw 左上主菜单与右上按钮；本方案默认“窄页头”更稳。

## 7. 交互与动效

- 沿用 Excalidraw 的快捷键、右键菜单、拖拽、吸附、元素编辑逻辑；不重写。
- 我们只给壳层与浮层加 `--dur-2`/`--ease` 的淡入与位移；不改变 Excalidraw 内部动画时序。
- 主题切换继续使用全局圆形揭示；Excalidraw 的 `theme` prop 随 `mode` 更新，避免画板内二次动画。
- `prefers-reduced-motion` 下不新增画板动效；Excalidraw 自身动画保持其默认行为。
- 控件命中区不小于 28px；工具栏 32px、弹窗按钮 36px；焦点环使用 `--ring`，不覆盖 Excalidraw 的 `:focus-visible` 为 none。

## 8. “不遗漏按钮”验收协议

1. **基线**：在真实应用里打开空画板与有图元画板，分别截取工具条、主菜单、属性面板、右侧栏、底部、右键菜单、每个弹窗。
2. **清单对照**：用 §3 的功能清单逐项点击；记录“保留 / 替换入口 / 明确隐藏 / 缺失”。
3. **DOM 对照**：记录 Excalidraw 的 `data-testid` 与按钮 aria-label 集合，改版前后做集合差；差集只允许出现在 §4.3 清单中。
4. **主题矩阵**：9 主题 × 明暗，至少覆盖画板主界面；重点弹窗（导出图片、帮助、命令面板、颜色/字体选择、组件库）至少在 2 套主题 × 明暗下截图。
5. **可访问性**：焦点可见、aria-label 保留、键盘可到达；我们的 CSS 不得把按钮文字裁掉或把命中区缩小。
6. **许可证与字体**：`npm run check:licenses` 通过；构建产物无 Excalifont。
7. **性能**：主题切换只触发 CSS 变量重算，不重建画布；切换 9 主题时无可感知卡顿（记录实际读数，不空口宣称）。

在真实应用中完成上述矩阵前，不能把“UI 适配完成”标为已验证。
