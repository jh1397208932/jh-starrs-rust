## 1. 设计范围

本设计解决：

1. Excalidraw 场景（图元、画布设置、视口）如何落盘。
2. 图片与任意附件如何直接引用全局 `object_id`，不建画板级映射表。
3. 画板上的图片元素、非图片文件卡片如何表示，如何在加载时重建。
4. 粘贴/拖放文件与插入既有附件时的对象上传路径。
5. 自动保存触发、去抖、单飞、失败重试、版本冲突与退出前落盘。
6. 迁移、性能、测试与验收。

不包含：

- 画板工具条/弹窗/主题适配的完整 UI 方案（见 `docs/设计/2026-10-24-画板功能适配-001/说明.md`，本文件只补文件/附件交互）。
- 组件库导入与预设（第 3、4 项，另出 v9 设计）。
- 跨工作区的对象共享；当前对象库仍是“当前工作区全局”。

## 2. 核心结论

**画板场景只存一份 `elements_json` 与 `app_state_json`；图片和附件的对象 id 直接写在图元里，不再建 `board_file` 之类的映射表。**

- 图片元素：`element.fileId = object_id`。
  - Excalidraw 的 `files` 映射以 `fileId` 为键；把 `fileId` 设为全局对象 id 后，画板不再需要 `fileId → attachment_id` 的二次映射。
- 非图片附件：一个“文件卡片”图元组，`customData.objectId` 存全局对象 id，另存 `name/mime/size` 供展示。
- 画板保存 **不上传文件**；粘贴/拖放/插入附件时先走全局对象上传，拿到 `object_id` 后再插入图元。
- 画板删除不删除全局对象；全局附件管理器是对象的唯一生命周期权威。
- 对象被全局删除后，画板加载时对应图片/附件显示缺失状态；不因为画板引用而阻止全局删除（这是“无映射表”的直接代价，见 §7 决策）。

## 3. Excalidraw 数据格式事实

| 数据 | 实际结构 | 持久化要点 |
|---|---|---|
| 图元 | `elements: readonly ExcalidrawElement[]` | 整数组快照；不拆逐图元行 |
| 图片 | `files: BinaryFiles`，`fileId -> { mimeType, dataURL, created }` | `fileId` 直接用 `object_id`；加载时按 object_id 回填 dataURL |
| 非图片附件 | Excalidraw 原生没有“文件卡片”元素 | 用一组普通图元组成卡片，`customData.objectId` 指向全局对象 |

| 视口 | `scrollX/scrollY/zoom` 不在导出白名单 | 宿主用独立小表保存 |
| 变更回调 | `onChange(elements, appState, files)` 高频触发 | 回调内只标脏，不做序列化/IPC |

## 4. 表设计（工作区库 v8）

### 4.1 DDL

```sql
-- 画板场景：每个画板节点最多一行，首次保存时惰性创建。
CREATE TABLE IF NOT EXISTS board_scene (
    node_id        TEXT PRIMARY KEY NOT NULL,
    elements_json  TEXT NOT NULL DEFAULT '[]',
    app_state_json TEXT NOT NULL DEFAULT '{}',
    scene_version  INTEGER NOT NULL DEFAULT 1,
    element_count  INTEGER NOT NULL DEFAULT 0,
    updated_at     INTEGER NOT NULL,
    FOREIGN KEY (node_id) REFERENCES node(id) ON DELETE CASCADE
);

-- 视口：平移/缩放只写这一行，不重写大段图元。
CREATE TABLE IF NOT EXISTS board_viewport (
    node_id    TEXT PRIMARY KEY NOT NULL,
    scroll_x   REAL NOT NULL DEFAULT 0,
    scroll_y   REAL NOT NULL DEFAULT 0,
    zoom       REAL NOT NULL DEFAULT 1 CHECK (zoom > 0),
    updated_at INTEGER NOT NULL,
    FOREIGN KEY (node_id) REFERENCES node(id) ON DELETE CASCADE
);
```

**没有 `board_file` 表，也没有 `board_object` 表。**

### 4.2 字段说明

**board_scene**

| 字段 | 类型 | 含义与约束 |
|---|---|---|
| `node_id` | TEXT PK | 画板节点 id；外键级联 |
| `elements_json` | TEXT | 非删除图元数组 JSON；图片/附件的 object_id 内嵌在图元中 |
| `app_state_json` | TEXT | 官方白名单：`viewBackgroundColor`、`gridModeEnabled`、`gridSize`、`gridStep` |
| `scene_version` | INTEGER | 乐观并发版本；首次插入为 1，每次成功保存 +1 |
| `element_count` | INTEGER | 后端从数组长度计算；不接受前端传入 |
| `updated_at` | INTEGER | 场景保存时间；同时写 `node.update_time` |

**board_viewport**

| 字段 | 类型 | 含义与约束 |
|---|---|---|
| `node_id` | TEXT PK | 画板节点；外键级联 |
| `scroll_x` / `scroll_y` | REAL | Excalidraw 场景坐标视口偏移 |
| `zoom` | REAL | 仅存 `AppState.zoom.value`，加载还原为 `{ value }` |
| `updated_at` | INTEGER | 视口保存时间；不更新 `node.update_time` |

### 4.3 图元里的对象引用

图片元素（Excalidraw 原生 `image` 类型）：

```json
{
  "type": "image",
  "fileId": "<global object_id>",
  "customData": { "boardObject": true }
}
```

- `fileId` 就是全局对象 id，不再需要 `board_file` 映射。
- `customData.boardObject` 用于区分“用户图片对象”和“应用内置图标文件”；加载时只对前者读全局对象。

非图片附件卡片（普通图元组）：

```json
{
  "type": "rectangle",
  "id": "card-bg-...",
  "customData": {
    "boardFileCard": true,
    "objectId": "<global object_id>",
    "name": "需求文档.pdf",
    "mime": "application/pdf",
    "size": 123456
  }
}
```

- 卡片由背景矩形 + 文件页图标 + 文件名/大小文本组成；**文件类型图标用矢量图元绘制**，不额外创建对象。
- `customData` 是唯一引用处；不建映射表。
- 可同时设置 `link: "attachment://<object_id>"`，由 `onLinkOpen` 拦截为打开/下载。

### 4.4 不变量

1. `board_scene`、`board_viewport` 与 `node` 是 1:1；节点删除级联删除两表。
2. 节点类型必须是画板（`type = 3`）。
3. 图片元素的 `fileId` 必须是全局对象 id；非图片卡片的 `customData.objectId` 必须是全局对象 id。
4. 画板不拥有对象生命周期；对象由全局附件管理器删除/回收。
5. 保存时不要求所有引用对象都存在；缺失对象在加载时报告，不阻断打开。

## 5. 粘贴、上传与插入

### 5.1 图片（原生 image 元素）

Excalidraw 支持 `generateIdForFile(file) => Promise<string>`。画板实现为：

1. 调 `uploadAttachmentBytes(file, "画板")`，走现有全局对象上传；
2. 返回 `attachment.id`（即 `object_id`）；
3. Excalidraw 用该 id 作为 `fileId`，生成原生 image 元素；
4. `files` 映射里只有该 object_id 对应的 dataURL，会话内使用；
5. 自动保存只保存 elements，不再上传。

### 5.2 非图片文件（文件卡片）

Excalidraw 原生不处理 PDF/DOCX/ZIP 等文件。画板在 `onPaste` / 拖放捕获阶段拦截非图片文件：

1. `uploadAttachmentBytes(file, "画板")`；
2. 在指针位置插入一个文件卡片图元组：
   - 背景矩形（纸面底、类型色描边）；
   - 文件页图标（折角矩形 + 扩展名文字/类型徽标）；
   - 文件名（截断）与大小文本；
   - `customData.objectId`、`name`、`mime`、`size`；
   - `link: "attachment://<object_id>"`。
3. 文件类型图标按扩展名/MIME 分类着色；不读取对象字节，不生成缩略图。
4. 双击/点击链接时调用全局附件下载/打开；对象缺失时提示“附件已删除”。

图片文件仍走 §5.1 的原生 image 元素，不生成文件卡片。

### 5.3 插入已有附件

画板需要一个“插入附件”入口（板页头或工具条）：

- 列出当前工作区全局附件；
- 图片 → 插入原生 image 元素（fileId = object_id）；
- 非图片 → 插入文件卡片；
- 不复制对象，不新建对象，只引用已有 `object_id`。

### 5.4 文件类型图标

文件卡片使用矢量图标，分类至少覆盖：

| 类别 | 扩展名示例 | 图标/色 |
|---|---|---|
| PDF | pdf | 折角页 + PDF 徽标，`--destructive` 系 |
| Word | doc/docx | 折角页 + DOC，主色系 |
| Sheet | xls/xlsx/csv | 折角页 + XLS，绿色系 |
| Slide | ppt/pptx | 折角页 + PPT，橙色系 |
| Image（非画布图片） | png/jpg/webp/svg | 折角页 + IMG，金色系 |
| Archive | zip/rar/7z | 折角页 + ZIP，金色系 |
| Audio/Video | mp3/mp4/mov | 折角页 + 播放符号，主色系 |
| Code/Text | json/md/txt/code | 折角页 + `{ }`/TXT，accent 系 |
| Generic | 其他 | 折角页 + FILE，muted 系 |

画布内颜色必须用具体色值（Excalidraw 图元不接受 CSS 变量）；取插入时的主题令牌计算值，作为用户内容保存，不随主题二次变化。图标是图元而不是对象，符合“不建更多映射”。

## 6. 加载与保存

### 6.1 加载

1. 查询 `board_scene`、`board_viewport`；无场景返回空数组、版本 0。
2. 扫描 `elements_json`：
   - 图片元素的 `fileId`（且 `customData.boardObject`）→ 收集 object_id；
   - 文件卡片的 `customData.objectId` → 收集 object_id（仅用于提示缺失，不需要读字节）。
3. 对图片 object_id 批量查全局附件元数据；读取图片字节（单文件上限与全局上传上限一致，建议 64 MiB），拼成 `BinaryFileData`。
4. 文件卡片不需要 dataURL；它们的图标/文字已经在图元里。
5. 缺失对象：
   - 图片：不放入 `files`，`missingObjectIds` 返回；
   - 文件卡片：保留图元，`missingObjectIds` 返回；打开时提示；
   - 不阻断画板打开。

### 6.2 保存

`board_save` 只接收：

```ts
{
  nodeId, baseVersion,
  elements,       // 含 object_id
  appState        // 白名单
}
```

流程：

1. 校验节点是画板、`baseVersion` 与 `scene_version` 一致；
2. `elements` 必须是 JSON 数组；过滤 `isDeleted`；统计 `element_count`；
3. `Immediate` 事务：upsert `board_scene`、更新 `node.update_time`；
4. 提交后返回新版本/时间。

**保存不做对象上传、不做对象删除、不做映射表写入。** 这是本方案相对上一版最大的性能收益：自动保存只写一行场景。

### 6.3 视口

`board_save_viewport` 只更新 `board_viewport`，不递增场景版本、不更新 `node.update_time`；平移缩放不重写 `elements_json`。

### 6.4 IPC 类型

```ts
/** 加载返回的图片 dataURL；键即 object_id */
export interface BoardFile {
  id: string;          // 与 object_id 相同
  mimeType: string;
  dataURL: string;
  created: number;
}

export interface BoardLoadResult {
  nodeId: string;
  elements: unknown[];
  appState: BoardAppState;
  viewport: BoardViewport;
  files: BoardFile[];
  version: number;
  updatedAt: number;
  missingObjectIds: string[];
}

export interface BoardSaveInput {
  nodeId: string;
  baseVersion: number;
  elements: unknown[];
  appState: BoardAppState;
}
```

不再有 `filesAdded` / `fileIdsRemoved`。

## 7. 自动保存策略

### 7.1 状态机

`idle → dirty → saving → saved`；失败 `error`，版本冲突 `conflict`。

- 场景去抖：最后一次有效变更后 800ms。
- 最大等待：5s 强制保存一次。
- 视口去抖：1200ms，只调 `board_save_viewport`。
- 单飞：保存中不并发；期间变更排队。
- 失败：保留脏数据，指数退避（1s → 2s → 4s，上限 10s）；切换页面前必须 flush 成功。
- 冲突：409 语义冲突，提示重新加载，不覆盖。

### 7.2 有效变更判定

- 图元：`getSceneVersion(elements)` 变化。
- 视口：`onScrollChange` 与已保存值不同。
- 仅选择框、当前工具、面板开关不触发保存。
- 因为对象上传发生在粘贴/插入时，自动保存无需关心 files。

### 7.3 切换与退出

- 切换标签/知识库/工作区前 flush 场景与视口；失败阻止切换。
- 关闭标签/窗口前 flush；窗口关闭拦截，超时 2s 放行。
- 页面隐藏时 flush。
- 初始化后的首次 `onChange` 只建立基线。

## 8. 生命周期与全局对象

### 8.1 画板删除

- 删除节点/文件夹：外键级联删除 `board_scene`、`board_viewport`；
- **不删除全局对象**；
- 对象仍可在附件管理器中查看/删除/复用；
- 若用户希望“删除画板时清理专属对象”，需要额外映射/引用统计，与“不要建立更多映射”冲突，本版不做。

### 8.2 全局对象删除

- 附件管理器删除对象后，画板不阻止、不回收；
- 下次加载对应图片缺失，文件卡片打开失败；
- 这是全局对象库为唯一权威的直接结果。

### 8.3 崩溃

- 粘贴上传成功但图元未插入：全局库多一个对象，可见、可删；
- 自动保存失败/崩溃：最多丢失去抖窗口内的图元变更；
- 不会出现画板表指向本地不存在文件：画板不存文件路径。

## 9. 迁移、兼容与影响面

- `SCHEMA_VERSION` 7 → 8；只新增 `board_scene`、`board_viewport` 两表。
- 旧画板节点无持久化内容，打开为空画板。
- `node.content` 对画板保持空串。
- `attachment` / `attachment_blob` 结构不变。
- 附件管理器可继续删除任何对象；画板不再参与对象回收。
- 导出：扫描画板图元收集 object_id，从全局对象库读取图片/附件；不得只导出节点元信息。
- 备份：工作区 SQLite + `storage/objects`，与现有附件口径一致。

## 10. 测试与验证

### 10.1 Rust 自动化

- v7 → v8 迁移：旧数据不丢；两张新表存在。
- 空画板加载：空数组、版本 0。
- 保存/加载往返：图元与 appState 一致；object_id 原样保留。
- 版本冲突：旧 baseVersion 返回冲突且不写库。
- 视口：独立保存，不递增场景版本。
- 无 `board_file` / 无映射表：schema 断言（表不存在）。
- 删除画板：只清画板表，全局对象仍存在。
- 删除对象后加载：`missingObjectIds` 正确返回。
- 文件卡片：customData 字段原样保存；不产生额外对象。

### 10.2 真实应用黑盒

1. 粘贴图片 → 画布出现图片 → 自动保存 → 重启仍可见；附件管理器有同一 object_id。
2. 粘贴 PDF/ZIP → 出现带格式图标的文件卡片 → 保存/重启仍在；双击能打开/下载。
3. 从附件管理器插入已有图片/PDF → 不产生新对象，画板正常显示。
4. 删除画板 → 全局对象仍在附件管理器。
5. 删除附件管理器中的对象 → 重开画板对应图片缺失/卡片提示删除，不崩溃。
6. 连续绘制 10s + 粘贴若干图片 → 自动保存不重复上传对象，无长任务。
7. 切换标签/窗口关闭前 flush，不丢最后变更。

### 10.3 性能

- 自动保存只写一行场景；对象上传只在粘贴/插入时发生。
- 100/1000/5000 图元实测 `JSON.stringify`、IPC、事务耗时并记录。
- 加载大量图片时分批构建 dataURL，避免首帧卡顿。

## 11. 需要你审阅确认的决策

| # | 决策 | 推荐 |
|---|---|---|
| 1 | 不建 `board_file` / 任何画板-对象映射表；`object_id` 直接写进图元 | 是（按本轮约束） |
| 2 | 图片 `fileId = object_id`；非图片卡片 `customData.objectId` | 是 |
| 3 | `object_id` 是当前工作区全局附件 id（`attachment.id`），与文档附件块一致 | 是；若你要跨工作区全局对象库，需要另改附件作用域 |
| 4 | 画板删除不删对象；全局删除后画板显示缺失 | 是（无映射表的直接结果） |
| 5 | 文件卡片用矢量图元画格式图标，不额外建对象 | 是 |
| 6 | 插入已有附件通过画板“插入附件”入口；粘贴图片走原生 image | 是 |
